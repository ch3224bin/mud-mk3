# mud-mk3

범인수선전 풍 수선(修仙) 텍스트 MUD. 지금은 6차 이터레이션까지 했다.

- 1차: 관리자가 맵을 만들고, 플레이어가 캐릭터를 만들어 돌아다니며 말한다.
- 2차: 관리자가 성·종문을 정의하고 지역 소유를 정하고, NPC를 만들어 방에 배치한다. 플레이어는 방 머리에서 소유(`[청석성]`)를, 방에서 NPC를 보고 `대화` 로 NPC에게 말을 건다.
- 3차: 아이템 종류(영석·저물대·단약·재료·법기)를 만들고 방 바닥에 물건을 두고 시작 소지품을 정하고 NPC를 상점으로 만든다. 플레이어는 소지품을 보고, 줍고 버리고, 상점에서 사고 팔고(영석으로 값을 치른다), 저물대에 담고, 다른 사람에게 주고, 버린 물건은 5분 뒤 사라진다.
- 4차: 캐릭터가 경지(범인, 연기 1~13층, 축기 초기~대원만)와 영근을 가진다. 관리자가 공법·신통을 정의하고 옥간·서책에 담고 캐릭터의 경지를 바로 지정한다. 플레이어는 영근을 고르고 `상태`·`공법`·`신통` 을 보고, 옥간을 `읽기` 로 읽어 공법을 익힌다(범인이 입문 공법을 읽으면 연기 1층). 저물탁을 더한다(축기 초기부터 칸이 열린다).
- 5차: 관리자가 몹(요수 등)과 드롭 표를 정의하고 방에 배치한다. 플레이어는 방에서 몹을 보고 `공격` 으로 교전을 시작해(서버 틱 1초, 3초마다 자동으로 친다) 몹을 쓰러뜨리고 시체를 `수습` 해 드롭을 얻는다. 쓰러진 몹은 재등장 시간 뒤 다시 나타난다. 지면 시작 방에서 기혈 1로 깨어나고, 교전이 끝나고 10초가 지나면 기혈이 다 찬다.
- 6차: 공격 신통을 쓴다. 관리자가 신통마다 이펙트 문장(1~5개)과 공격 신통의 단계별 값(기본 위력·계수)을 정한다. 플레이어는 `<신통> <몹>` 으로 신통을 쓰고(이펙트 문장 하나가 무작위로 보인다, 공통·재사용 대기시간, 법력 소모, 시전 시간이 있으면 `중지` 가능), 쓸 때마다 깨달음이 쌓여 `상태`·`공법` 에 보이며, 깎인 법력은 서버 틱마다 천천히 찬다.

| 모듈 | 하는 일 | 주소 |
|---|---|---|
| `world-server/` | 게임 서버. Java 25 · Spring Boot 4. Google 로그인, 관리 REST API, 게임 WebSocket(`/ws/game`), PostgreSQL | http://localhost:8080 |
| `play-client/` | 플레이 화면(터미널형). Next.js 정적 export | http://localhost:3000 |
| `admin-console/` | 관리 툴(지역·방·출구·시작 방, 성·종문·지역 소유, NPC 편집, 아이템 종류·시작 소지품·방 바닥 물건·NPC 상점, 공법·신통(이펙트 문장·단계별 값), 캐릭터 경지 지정·깨달음 보기, 몹·드롭 표·방의 몹 배치). Next.js 정적 export | http://localhost:3001 |

## 필요한 것

- Docker (Docker Desktop 또는 OrbStack, `docker compose` v2)
- 개별 개발 실행을 할 때만:
  - Java 25 (Gradle은 wrapper `./gradlew` 를 쓴다)
  - Node.js 26.13.1 — 프론트 모듈마다 `.nvmrc` 가 있다. nvm이면 모듈 폴더에서 `nvm install && nvm use`

## 주의할 점

- **브라우저 주소는 항상 `localhost` 로 쓴다.** `127.0.0.1` 을 섞으면 다른 사이트가 되어 world-server의 세션 쿠키가 가지 않는다(로그인이 안 된 것처럼 보인다).
- 로그인 세션은 world-server 메모리에 있다. **world-server를 다시 띄우면 다시 로그인해야 한다.**
- Google 값은 world-server만 쓴다. 두 클라이언트는 로그인 버튼으로 브라우저를 world-server에 보낼 뿐이다.

## Google OAuth 클라이언트

로그인은 world-server가 서버 측에서 한다(Spring Security OAuth2 Login). 리디렉션 URI는 하나다.

```
http://localhost:8080/login/oauth2/code/google
```

### 기존 클라이언트를 쓸 때 (권장)

이미 쓰던 OAuth 클라이언트(예: mud-mk2에서 쓰던 것)를 그대로 쓴다. [Google Cloud Console](https://console.cloud.google.com/) > API 및 서비스 > 사용자 인증 정보에서 그 클라이언트를 열고 확인한다.

- 애플리케이션 유형이 **웹 애플리케이션** 인가.
- **승인된 리디렉션 URI** 에 `http://localhost:8080/login/oauth2/code/google` 이 있는가. 이미 있으면 더 할 것이 없다(없으면 추가한다. 끝에 `/` 없이 정확히 같아야 한다).
- **승인된 JavaScript 원본** 은 필요 없다(브라우저 JS가 Google을 부르지 않는다).
- OAuth 동의 화면이 **테스트** 상태라면, 로그인할 Google 계정이 **테스트 사용자** 목록에 있어야 한다. 없으면 Google 화면에서 `액세스 차단됨` 이 뜬다.
- 범위(scope)는 `openid`, `profile`, `email` 만 쓴다(민감하지 않은 범위라 추가 검토가 필요 없다).

### 새로 만들 때

1. Google Cloud Console에서 프로젝트를 고르거나 만든다.
2. API 및 서비스 > OAuth 동의 화면: 사용자 유형 **외부**, 앱 이름·지원 이메일을 넣는다. 게시 상태는 **테스트** 로 두고 **테스트 사용자** 에 로그인할 Google 계정(관리자 계정 포함)을 넣는다.
3. API 및 서비스 > 사용자 인증 정보 > 사용자 인증 정보 만들기 > **OAuth 클라이언트 ID**.
4. 애플리케이션 유형 **웹 애플리케이션**, 승인된 리디렉션 URI에 `http://localhost:8080/login/oauth2/code/google` 를 넣고 만든다.
5. 나온 클라이언트 ID와 클라이언트 보안 비밀번호를 `.env` 의 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` 에 넣는다.

값이 없으면 world-server는 `not-configured` 로 떠서 시작 로그에 경고(`Google 로그인이 설정되지 않았습니다`)를 남긴다. 앱은 뜨지만 Google 로그인은 실패한다(아래 개발용 로그인은 된다).

## 한 번에 띄우기 (docker compose)

```sh
cp .env.example .env     # 값을 채운다 (아래 표). .env 는 커밋하지 않는다
docker compose up --build
```

| `.env` 값 | 뜻 |
|---|---|
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | 위 OAuth 클라이언트 값 |
| `MUD_ADMIN_EMAILS` | 관리자로 볼 Google 이메일. 쉼표로 나눈다(대소문자 무시). 예: `a@example.com,b@example.com` |
| `POSTGRES_PASSWORD` | compose 안 PostgreSQL 비밀번호. 꼭 채운다 |
| `SPRING_PROFILES_ACTIVE` | 비우면 운영. 개발용 로그인을 쓰려면 `local` |
| `MUD_DEV_LOGIN_ENABLED` | 개발용 로그인. 기본 `false` (아래 절) |

뜨는 것:

- play-client: http://localhost:3000
- admin-console: http://localhost:3001
- world-server: http://localhost:8080 (`/api/...`, `ws://localhost:8080/ws/game`)
- postgres: compose 안에서만 열린다(밖으로 포트를 열지 않는다). 데이터는 볼륨 `pgdata` 에 남는다.

멈추기: `docker compose down` (데이터를 지우려면 `docker compose down -v` — 맵이 모두 사라진다).

`MUD_DEV_LOGIN_ENABLED` 를 바꾸면 두 클라이언트를 다시 빌드해야 한다(`NEXT_PUBLIC_*` 는 빌드 때 박힌다): `docker compose up --build`.

### 관리자 지정

`MUD_ADMIN_EMAILS` 에 있는 이메일로 로그인한 계정이 관리자다. 로그인할 때 정해지므로, 목록을 바꾼 뒤에는 world-server를 다시 띄우고(`docker compose up -d world-server`) 다시 로그인한다.

## 처음 할 일 — 1차 시나리오

시작 방이 없으면 아무도 게임에 들어갈 수 없다(`아직 세계가 열리지 않았습니다. 관리자가 시작 방을 정해야 합니다.`).

1. http://localhost:3001 에서 관리자 이메일로 로그인한다(`Google로 로그인`, 또는 개발용 로그인).
2. 지역 목록(`/zones/`)에서 지역을 만든다. 예: `청석숲`.
3. 지역을 열어 방을 둘 이상 만든다. 예: `청석숲 오솔길`, `늙은 소나무 아래`.
4. 방을 열어 출구를 더한다(방위 → 대상 지역 → 대상 방, `반대 방향도` 를 켜 두면 돌아오는 출구도 생긴다).
5. 한 방에서 **시작 방으로 지정** 을 누른다.
6. http://localhost:3000 에서 로그인한다(다른 Google 계정이어도 된다).
7. 이름을 정한다(한글 2~6자) → 영근을 고른다(4차부터. 오행 `금 목 수 화 토` 가운데 1~5개, 예: `목 화`) → `확인` 으로 캐릭터를 만든다. 시작 방이 보인다.
8. `보기`, 출구 방위(`북`, `n` …)로 움직이고 `'안녕하시오` 로 말해 본다. 다른 브라우저(또는 시크릿 창)로 두 번째 계정을 들이면 서로의 움직임과 말이 보인다.

## 2차 시나리오 — 성·종문, 지역 소유, NPC, 대화

1차 시나리오로 맵과 시작 방이 있는 상태에서 한다.

1. admin-console 위쪽 바의 `성·종문`(`/factions/`)에서 성을 만든다. 예: 종류 `성`, 이름 `청석성`.
2. `지역 목록`(`/zones/`)에서 지역(예: 1차에서 만든 `청석숲`)을 `수정` 해 `소유` 를 `청석성 (성)` 으로 고른다. 목록의 `소유` 열에 `청석성 (성)` 이 보인다.
3. 위쪽 바의 `NPC`(`/npcs/`) → `NPC 만들기`(`/npc/`)에서 NPC를 만든다.
   - 이름(띄어쓰기 없이 1~12자) 예: `왕씨`, 인사말 예: `어서 오시오.`
   - 기본 대답(모르는 낱말에) — 새 NPC는 `글쎄, 잘 모르겠구려.` 가 들어 있다.
   - `낱말 추가` 로 낱말과 대답을 넣는다. 예: `단약` → `단약이라면 저기 약방에 가 보시오.`, `일거리` → `요즘 성 밖에 늑대가 많다오.`
   - `LLM 대화` 는 켜도 지금은 정해진 대사로 답한다.
   - 배치: 지역 → 방을 고른다(소유를 정한 지역의 방. 예: `청석숲` → `청석숲 오솔길`). 지역 선택을 `배치 안 함` 으로 두거나 방을 고르지 않으면 배치되지 않는다.
4. 방 화면(`/room/?id=`)의 `이 방의 NPC` 에 그 NPC가 보인다.
5. http://localhost:3000 에서 그 방으로 간다. 방 이름 줄에 `청석숲 오솔길  [청석성]` 처럼 소유가 붙고, 사람 줄 다음에 NPC 줄(`왕씨`)이 다른 색으로 보인다.
6. `대화 왕씨` → `왕씨: "어서 오시오."` 와 `물어볼 수 있는 낱말: [단약] [일거리]`.
7. `대화 왕씨 일거리`(또는 `대화 왕씨 [일거리]`) → `왕씨: "요즘 성 밖에 늑대가 많다오."`.
8. `대화 왕씨 날씨`(모르는 낱말) → `왕씨: "글쎄, 잘 모르겠구려."`.

이미 1차를 띄워 쓰던 compose 볼륨(`pgdata`)에서 그대로 올려도 된다. `ddl-auto=update` 가 새 테이블(`faction`·`npc`·`npc_topic`)과 `zone.owner_id` 열을 더한다(마이그레이션 도구는 아직 없다).

## 3차 시나리오 — 아이템, 영석, 상점, 저물대·귀속, 주기

2차 시나리오까지 해서 맵·시작 방·NPC(예: `왕씨`)가 있는 상태에서 한다. 영석 4종(하품·중품·상품·극품)은 world-server가 뜰 때 만들어 두므로 아이템 목록(`/items/`)에 이미 있다(영석은 고칠 수 없다).

1. admin-console 위쪽 바의 `아이템`(`/items/`)에서 아이템 종류를 만든다.
   - `하급 저물대` — 종류 저물대, 등급 하급, 기준가 30
   - `회춘단(연기 초)` — 단약, 기준가 3
   - `회기단(연기 초)` — 단약, 기준가 4
   - `늑대 가죽` — 재료, 기준가 2
   - `비검` — 법기, 기준가 40
2. 방 화면(`/room/?id=`)의 `바닥 물건` 에서 `늑대 가죽` 3개와 `비검` 1개를 둔다(재등장 분은 기본값 그대로).
3. 위쪽 바의 `시작 소지품`(`/start-items/`)에 하급 저물대 1·하품 영석 30·회춘단(연기 초) 3·회기단(연기 초) 3 을 넣고 저장한다(룰북 시작 소지품. 영수대는 아직 없다). 새로 만든 캐릭터만 받는다.
4. NPC 화면(`/npc/?id=`)의 `상점` 에서 상점 종류를 `단약방` 으로 하고 `회춘단(연기 초)`·`회기단(연기 초)` 를 더한다(값은 빈칸 — 기준가로 판다).
5. http://localhost:3000 에서 새 캐릭터를 만들어 그 방으로 간다. 방에 `늑대 가죽 3개` 줄과 `비검` 줄이 보인다.
6. `소지품` → `[소지품 3/22칸]  하품 영석 30` 과 가진 물건.
7. `줍기 가죽 2` → `버리기 가죽 1` → `보기 가죽`(물건 이름은 앞부분·이름 안 낱말 앞부분으로 고른다).
8. (4차부터 상점은 범인이 쓸 수 없다 — 관리 툴 `캐릭터` 에서 그 캐릭터를 연기 1층으로 지정하거나 입문 옥간을 읽는다. 아래 [4차 시나리오](#4차-시나리오--경지영근공법-배우기저물탁).) 상점 NPC가 있는 방에서 `목록` → `사기 회춘단 2` → `팔기 회춘단 2` → `값 회춘단`. 영석을 깨야 하는 값이면 `확인` 또는 `취소` 로 답한다(10초 안).
9. `줍기 비검` 으로 비검을 얻어 `버리기 비검` → 다시 `줍기 비검`.
10. 다른 브라우저(또는 시크릿 창)로 두 번째 계정을 같은 방에 들인다. 첫 계정에서 `주기 <이름> 회춘단 1`, `주기 <이름> 하품 5` — 받는 사람과 같은 방 다른 사람에게도 알림이 간다.

기존 `pgdata` 에서 그대로 올려도 된다. `ddl-auto=update` 가 새 테이블(`item_type`·`inventory`·`inventory_entry`·`floor_placement`·`dropped_item`·`npc_shop_item`·`world_starting_item`)과 `npc.shop_kind` 열을 더하고, world-server가 뜰 때 영석 4종을 만든다. 이미 있던 캐릭터는 빈 소지품을 가진다. 옛 `tradable`·`bound` 열이 있으면 world-server가 뜰 때 같은 종류 묶음을 합치고 그 열을 지운다.

## 4차 시나리오 — 경지·영근·공법 배우기·저물탁

3차 시나리오까지 해서 맵·시작 방이 있는 상태에서 한다. 값은 룰북 [공법 예시: 장춘공](docs/spec/game-rule/technique.md#공법-예시-장춘공)·[오행 연기 후반 공법](docs/spec/game-rule/technique-list.md#오행-연기-후반-공법) 표를 따른다.

1. admin-console 위쪽 바의 `공법`(`/techniques/`) → `공법 만들기`(`/technique/`)에서 공법 둘을 만든다.
   - `장춘공` — 속성 `목`, 시작 경지 `범인`(입문 공법), 단계 수 9성. 필요 깨달음 0(1성 칸은 입력 없음)·120·190·280·400·560·800·1,100·1,540, 법력 2~9성 +2, 의식 2·4·6·8성 +1, 영력 5·9성 +1, 영근 자질 2~9성 +1. 신통: `화탄술`(1성, 공격, 속성 `화`, 한 대상, 소모 법력 5, 시전 0, 대기 3, 전투 중만).
   - `청목결` — 속성 `목`, 시작 경지 `연기 7층`, 단계 수 8성. 필요 깨달음 0·1,800·2,600·3,500·4,800·6,500·8,700·12,000, 자질 조건 1~4성 15·5~8성 20, 법력 2~8성 +3, 의식 2·4·6·8성 +1, 영력 8성 +1. 신통: `청목전`(1성, 공격, 속성 `목`, 한 대상, 소모 법력 12, 시전 0, 대기 3, 전투 중만), `목령갑`(4성, 방어, 속성 `목`, 자신, 소모 법력 18, 시전 0, 대기 15, 전투 밖에도).
2. `아이템`(`/items/`)에서 종류 `옥간·서책` 아이템을 둘 만들고 `담긴 공법` 을 고른다: `장춘공 옥간`(장춘공), `청목결 옥간`(청목결). 기준가는 아무 값(예: 100). 그리고 종류 `저물대·저물탁`, 등급 `하급 저물탁 (100칸)` 인 `하급 저물탁` 을 만든다(기준가 5,000).
3. 방 화면(`/room/?id=`)의 `바닥 물건` 에 `장춘공 옥간`·`청목결 옥간`·`하급 저물탁` 을 각각 1개 둔다.
4. http://localhost:3000 에서 새 계정으로 이름을 정하고 영근 `목 화` → `확인`. 영근 확인 prompt는 `목·화 진영근 — 목 50, 화 50` 으로 시작한다. 시작 방에서 바닥 물건 방으로 간다.
5. `상태`(`ㅅ`) → `<이름> · 범인 · 목·화 진영근 (목 50, 화 50)` 와 스탯(기혈 10 / 10 …). `목록` → `아직 범인의 몸이라 할 수 없습니다.`
6. `줍기 장춘공` → `줍기 청목결` → `보기 장춘공 옥간`(둘째 줄에 `담긴 공법: 장춘공 (목 · 오행 · 9성 · 범인부터)`).
7. `읽기 장춘공 옥간` → `옥간을 이마에 대자 구결이 머릿속으로 흘러든다. 장춘공 1성에 이르렀습니다!` 와 `단전에 따뜻한 기운이 맺힌다. 연기 1층이 되었습니다. 새 신통: 화탄술`. 옥간은 사라진다. `상태` 는 연기 1층, `공법`·`신통` 에 장춘공 1/9성과 화탄술.
8. `읽기 청목결 옥간` → `지금은 이 공법을 익힐 수 없습니다. (연기 7층 필요)`(물건은 남는다).
9. admin-console `캐릭터`(`/characters/`) → 그 캐릭터 → 경지 `연기 7층` → `경지 지정`. play-client에 `경지가 연기 7층으로 바뀌었습니다. (육신 +6, 근력 +3, 영력 +6, 의식 +12, 정혈 +12)` 가 뜬다(접속 중인 창에만).
10. `상태` → 연기 7층. `읽기 청목결 옥간` → `청목결 1성에 이르렀습니다!` 와 `새 신통을 깨쳤습니다: 청목전`. `공법` · `신통`(`[장춘공 1성]`·`[청목결 1성]` 머리 아래 신통 줄).
11. `줍기 저물탁` → `소지품` 에서 `하급 저물탁 (축기 초기 필요)` 줄이 보이고 칸은 그대로 `/22칸`(기본 2칸 + 시작 소지품의 하급 저물대 20칸). 관리 툴에서 경지를 `축기 초기` 로 지정하면 알림이 오고 `소지품` 칸이 `/122칸` 으로 열린다(저물탁 100칸). 시작 소지품을 비워 두었다면 `/2칸` → `/102칸` 이다.

이미 3차까지 띄워 쓰던 `pgdata` 에서 그대로 올려도 된다. `ddl-auto=update` 가 새 테이블(`technique`·`technique_element`·`technique_stage`·`ability`·`ability_element`·`character_spirit_root`·`character_technique`)과 `player_character.realm`·`item_type.technique_id` 열을 더한다. 4차 전 캐릭터는 world-server가 뜰 때 연기 1층으로 채워지고, 다음 접속 때 영근을 한 번 고른다(고르기 전까지 세계에 들어가지 못한다). 3차 PostgreSQL 이 만든 저물대 등급 CHECK(`item_type_bag_grade_check`)는 world-server가 뜰 때 지운다(저물탁 등급 저장을 막기 때문).

## 5차 시나리오 — 몹·공격·처치·재등장

4차 시나리오까지 해서 맵·시작 방이 있는 상태에서 한다. 서버 틱이 1초마다 돌아 몹이 스스로 움직이므로 시간을 기다리는 단계가 있다. 값은 룰북 [몹](docs/spec/game-rule/npc.md#몹)·[몹 스탯](docs/spec/game-rule/npc.md#몹-스탯)을 따른다.

1. admin-console `아이템`(`/items/`)에서 종류 `재료` 인 `토끼 가죽` 을 만든다(기준가 1).
2. 위쪽 바의 `몹`(`/mobs/`) → `몹 만들기`(`/mob/`)에서 몹 둘을 만든다. 스탯(기혈·육신·위력)은 입력하지 않고 기준 경지·종류·체급으로 계산되어 저장한 뒤 아래에 보인다.
   - `들토끼` — 종류 `요수`, 기준 경지 `연기 1층`, 체급 `일반`, 공격 이름 `뒷발차기`, 재등장(초) `10`, 고정 재료 `토끼 가죽` 1.
   - `쌍두 흑망` — 종류 `요수`, 기준 경지 `축기 대원만`, 체급 `두목`, 공격 계수 `0.6`, 재등장(초) `1800`(두목은 1,800~3,600을 꼭 넣는다).
3. 방 화면(`/room/?id=`)의 `몹 배치` 에서 광장에 `들토끼` 1마리, 다른 방에 `쌍두 흑망` 1마리를 `추가` 한다. 다음 틱(1초 안)에 몹이 나타난다.
4. http://localhost:3000 에서 광장으로 가 `보기` → 사람 줄 다음에 `들토끼 (1급)` 줄이 몹 색으로 보인다. `보기 들토끼` → `들토끼 (1급) — 멀쩡하다.`(묘사를 넣었다면 `—` 뒤에 묘사가 먼저).
5. 관리 툴 `캐릭터`(`/characters/`) → 그 캐릭터 → 경지 `연기 7층` → `경지 지정`.
6. `공격 들토끼` → `들토끼와 싸움이 벌어진다.` 와 `들토끼에게 일격을 날린다. (피해 …)`, 이어 `들토끼가 뒷발차기로 덮친다! (피해 …, 기혈 …/…)` 줄이 몇 초마다 나오고 끝에 `들토끼를 쓰러뜨렸습니다.`. 피해를 입었으므로 싸움이 끝나고 약 10초 뒤 `숨을 고르자 기운이 돌아온다. (기혈 …/…)` 줄이 나온다. 싸우는 동안 `북` 같은 이동이나 `종료` 는 `싸우는 중에는 움직일 수 없습니다.`·`싸우는 중에는 떠날 수 없습니다.`, `상태` 끝에는 `[전투 중] 상대: 들토끼` 줄이 붙는다.
7. `보기` → `들토끼의 시체 (수습 가능)` 줄. `수습 들토끼` → `들토끼의 시체를 수습했습니다: 토끼 가죽 1`(영석이 나오면 `하품 영석 1` 이 더해진다). `소지품` 에서 확인.
8. 쓰러뜨리고 10초 뒤 광장에 `들토끼가 나타난다.` 와 몹 줄이 다시 보인다.
9. 관리 툴에서 그 캐릭터를 `연기 1층` 으로 지정한다. 쌍두 흑망이 있는 방으로 가 `공격 쌍두 흑망` → 곧 `기혈이 다했습니다. 눈앞이 캄캄해진다…` 와 `<시작 방>에서 깨어났습니다. (기혈 1/…)`. 시작 방에서 `상태` 의 기혈이 1이다.
10. 10초 뒤 `숨을 고르자 기운이 돌아온다. (기혈 …/…)` 가 뜨고 `상태` 의 기혈이 가득이다.

이미 4차까지 띄워 쓰던 `pgdata` 에서 그대로 올려도 된다. `ddl-auto=update` 가 새 테이블(`mob_type`·`mob_fixed_drop`·`mob_tier_drop`·`mob_placement`)과 `player_character.qi_blood_lost` 열을 더한다. 기존 캐릭터는 기혈이 가득이다. 서버 틱은 1초(`mud.game.tick-enabled`, 기본 켜짐)이다. 몹·교전·시체는 메모리에만 있어 world-server를 다시 시작하면 처음 상태(몹은 배치대로 다 찬 채 나타나고 시체는 없음)다. 깎인 기혈은 DB에 남는다.

## 6차 시나리오 — 공격 신통·이펙트 문장·깨달음

5차 시나리오까지 해서 맵·시작 방이 있는 상태에서 한다. 서버 틱이 1초마다 돌고 대기시간이 있어 시간을 기다리는 단계가 있다. 값은 룰북 [공법 예시: 장춘공](docs/spec/game-rule/technique.md#공법-예시-장춘공)·[깨달음](docs/spec/game-rule/technique.md#깨달음)을 따른다.

1. admin-console `공법`(`/techniques/`) → `공법 만들기` 에서 공법 `염화결`(속성 `화`, 시작 경지 `범인`, 단계 수 9성, 단계 값은 4차 `장춘공` 과 같게)을 만든다(`장춘공` 은 4차에서 이미 있어 이름이 겹친다). 신통 `화탄술`(1성, 공격, 속성 `화`, 한 대상, 소모 법력 10, 시전 0, 대기 3, 전투 중만)을 넣는다. 신통 행 끝의 `자세히` 를 눌러 펼친다.
   - `이펙트 문장`: 줄 셋을 적는다 — `손끝에서 붉은 불덩이가 피어올라 {대상}을 덮친다!`, `{시전자}의 손바닥에서 화탄이 튀어 나가 {대상}에게 터진다!`, `작은 불덩이가 꼬리를 그으며 {대상}에게 날아든다!`(`문장 추가` 로 줄을 늘린다).
   - `단계별 값`: `채우기` 의 기본값(`2`·`1.2`·`0.2`·`0`)대로 누르면 1성 2 · 1.2 에서 9성 3.6 · 1.2 까지 표가 채워진다. 저장.
2. 이펙트 문장 줄을 하나만 남겨 비우고 저장하면(화면은 줄이 1개일 때 `삭제` 가 비활성이라 0개를 만들 수 없다) 400 `이펙트 문장은 한 줄 1~100자로 적으십시오: 화탄술` 이 보이고 저장되지 않는다. 0개·6개 거절(`이펙트 문장은 1~5개로 정하십시오: 화탄술`)은 화면이 아니라 API·스모크로 본다. 문장을 되돌려 저장한다.
3. `아이템` 에서 `염화결 옥간`(담긴 공법 염화결)을 만들어 방 바닥에 1개 둔다. `몹`(`/mobs/`)에서 몹 `청모랑`(요수, 기준 경지 `연기 1층`, 체급 `일반`, 재등장 10)을 만들고 방에 배치한다.
4. http://localhost:3000 에서 **새 계정**으로 새 캐릭터를 만들어(4·5차 캐릭터는 이미 경지가 있다) 그 방으로 간다. `줍기 염화결` → `읽기 염화결 옥간`(범인이 입문 공법을 읽으면 연기 1층이 되고 `새 신통: 화탄술`). `신통` 으로 확인한다.
5. `화탄술 청모랑` → `청모랑과 싸움이 벌어진다.` 와 이펙트 문장 하나에 `(피해 …, 법력 …/…)` 가 붙은 줄이 나온다(몇 번 쓰면 다른 문장도 나온다). `상태` 에서 법력이 줄고 깨달음 줄(`깨달음  금 0 · 목 … · 화 …`)이 보인다.
6. 곧바로 다시 `화탄술 청모랑` → `아직 기운을 고르는 중입니다. (…초)`(공통 대기 1.5초). 1.5초가 지난 뒤(3초 안에) 다시 → `화탄술은 아직 쓸 수 없습니다. (…초)`(재사용 대기 3초). `신통` 줄 끝에 `(…초 남음)` 도 보인다.
7. 3초씩 건너 쓰다 법력이 모자라면 `법력이 모자랍니다. (필요 10, 남은 것 …)`. `상태`·`공법` 의 `(지금 …)` 에 쌓인 깨달음이 보인다.
8. 자동 공격(3초마다)으로 청모랑을 쓰러뜨린다 → 처치 줄. `수습 청모랑` 은 5차 그대로다.
9. 기다리면 법력이 조금씩 찬다(법력 최대치의 0.5%/초, 알림 없음). `상태` 로 본다.

이미 5차까지 띄워 쓰던 `pgdata` 에서 그대로 올려도 된다. `ddl-auto=update` 가 새 테이블(`ability_stage_power`·`ability_effect_line`·`character_insight`)과 `player_character.mana_lost` 열을 더한다. 서버가 뜰 때 이펙트 문장·단계별 값이 없는 기존 신통을 채운다(이펙트 문장 한 줄, 공격 신통은 룰북 입문 값). 대기시간·시전은 메모리에만 있어 world-server를 다시 시작하면 사라진다. 깎인 법력과 깨달음은 DB에 남는다.

| `대화 <NPC> <낱말>` | 그 낱말을 묻는다. 모르는 낱말이면 기본 대답. NPC 이름은 앞부분만 써도 된다(`대화 왕 단약`). 대답은 묻는 사람에게만 보인다 |
| `누구` | 접속한 사람과 있는 지역 |
| `소지품`, `ㅈ` | 소지품 칸과 가진 영석·물건 (`[소지품 3/22칸]  하품 영석 30`) |
| `공격 <대상>` | 같은 방의 몹과 교전을 시작한다(교전 중이면 노리는 상대를 바꾼다). 이후 3초마다 자동으로 친다. 교전 중에는 이동·`종료`·`줍기`·`수습`·`주기`·`대화`·`읽기`·상점 명령이 막힌다 |
| `<신통> [대상]` | 배운 공격 신통을 같은 방 몹에게 쓴다(`화탄술 청모랑`). 교전 중에 대상을 빼면 노리는 상대에게 쓴다. 공통 대기 1.5초·신통마다 재사용 대기가 있다. 이펙트 문장 하나가 무작위로 보이고 `(피해 …, 법력 …/…)` 가 붙는다 |
| `중지` | 시전 중인 술법을 끊는다 |
| `수습 <시체>` | 같은 방 시체의 물건을 저물대에 거둔다(처음 60초는 처치자만, 3분 뒤 사라진다) |
| `상태`, `ㅅ` | 경지·영근·스탯·수위·깨달음(쌓인 값)·현재 법력 (`status` 메시지) |
| `공법` | 익힌 공법과 단계, 다음 단계 필요 깨달음과 쌓인 깨달음(`(지금 …)`) |
| `신통` | 배운 신통을 공법마다(재사용 대기가 남았으면 줄 끝에 `(1.8초 남음)`) |
| `읽기 <물건>` | 소지품의 옥간·서책을 읽어 공법을 익힌다(읽은 물건은 사라진다. 조건이 모자라면 거절하고 남는다) |
| `줍기 <물건> [수량]` | 방 바닥에서 소지품으로 |
| `버리기 <물건> [수량]` | 소지품에서 방 바닥으로(5분 뒤 사라진다) |
| `주기 <대상> <물건> [수량]` | 같은 방 사람에게 물건을 준다 |
| `목록` | 같은 방 상점의 파는 물건과 값 (범인은 `아직 범인의 몸이라 할 수 없습니다.`. `사기`·`팔기` 도 같다) |
| `사기 <물건> [수량]`, `팔기 <물건> [수량]`, `값 <물건>` | 상점에서 사기·팔기·값 보기 |
| `확인`, `취소` | 영석을 깨야 하는 거래의 확인 질문에 답(10초 안) |
| `도움말` | 명령 목록: `명령: 보기(ㅂ) · 동 서 남 북 북동 북서 남동 남서 위 아래 (e w s n ne nw se sw u d) · 말하기(') · 대화 <NPC> [낱말] · 공격 <대상> · <신통> [대상] · 중지 · 수습 <시체> · 상태(ㅅ) · 공법 · 신통 · 읽기 <물건> · 소지품(ㅈ) · 보기 <물건> · 줍기 <물건> [수량] · 버리기 <물건> [수량] · 주기 <대상> <물건> [수량] · 목록 · 사기 <물건> [수량] · 팔기 <물건> [수량] · 값 <물건> · 확인 · 취소 · 누구 · 도움말 · 종료` |
| `종료` | 접속 끊기 |

새 캐릭터는 생성 때 이름 다음에 영근을 입력한다(`영근을 고르십시오. 오행(금 목 수 화 토) 가운데 1~5개를 띄어 쓰십시오.` → 예 `목 화` → `확인`, `뒤로` 로 돌아간다). 4차 전에 만든 캐릭터는 다음 접속 때 한 번 고른다.

수량은 명령 끝에 적는다: 마지막 낱말이 수면 그 수, `전부` 면 모두, 없으면 1개(`줍기 가죽 2`, `버리기 가죽 전부`, `주기 한 하품 10`). 같은 이름이 여럿이면 `2.가죽` 처럼 번호로 고른다. 영석은 `하품 영석`·`하품` 처럼 등급 낱말로 부른다.

`말하기` 는 플레이어끼리 하는 채팅이다. NPC에게 말을 걸 때는 `대화` 를 쓴다(`말` 이라는 명령은 없다).

명령은 정해진 이름·줄임말로만 알아듣는다(앞부분만 맞춰 쓰기는 안 된다 — 앞부분으로 고를 수 있는 것은 `대화` 의 NPC 이름, 물건 이름(앞부분·이름 안 낱말 앞부분), `주기` 의 받는 사람 이름뿐이다). play-client에서 ↑↓ 로 입력 기록, Tab 으로 명령어·같은 방 사람·NPC·몹·시체·바닥 물건·소지품 물건 이름 자동완성(지운 명령 `귀속` 은 목록에 없다. 배운 신통 이름은 아직 후보에 없다).

## 개발용 로그인

Google 자격 증명 없이 이메일만으로 로그인한다(로컬 수동 확인·스모크 테스트용).

- world-server: **`local` 프로필 그리고 `MUD_DEV_LOGIN_ENABLED=true` 일 때만** `POST /api/auth/dev {email}` 이 생긴다. 그 밖에는 404. 기본은 꺼짐.
- 클라이언트: `NEXT_PUBLIC_DEV_LOGIN=true` 로 빌드했을 때만 이메일 입력 폼이 보인다.
- 관리자 여부는 Google 로그인과 같이 `MUD_ADMIN_EMAILS` 로 정한다.
- **운영에서는 켜지 않는다.** 아무 이메일로나 그 계정이 될 수 있다.

compose로 켜기 — `.env`:

```sh
SPRING_PROFILES_ACTIVE=local
MUD_DEV_LOGIN_ENABLED=true
MUD_ADMIN_EMAILS=admin@example.com
```

(compose는 `MUD_DEV_LOGIN_ENABLED` 값을 두 클라이언트의 `NEXT_PUBLIC_DEV_LOGIN` 빌드 인자로도 넘긴다.)

## 개별 개발 실행

### world-server

```sh
cd world-server
GOOGLE_CLIENT_ID=... GOOGLE_CLIENT_SECRET=... MUD_ADMIN_EMAILS=you@example.com \
  ./gradlew bootRun --args='--spring.profiles.active=local'
```

- `local` 프로필은 `spring-boot-docker-compose` 로 `world-server/compose.yaml` 의 PostgreSQL(`localhost:5432`, DB·사용자·비밀번호 모두 `mud`)을 자동으로 띄우고 접속 정보를 넣는다. 이것은 개발 전용 DB이고 루트 `compose.yaml` 의 DB(볼륨 `pgdata`)와 별개다. 루트 compose와 함께 띄워도 서로 부딪치지 않는다(루트 compose의 postgres는 포트를 열지 않는다). 단 8080 포트는 하나만 쓸 수 있으니 루트 compose의 world-server는 멈춰 둔다.
- 개발용 로그인: 앞에 `MUD_DEV_LOGIN_ENABLED=true` 를 더한다.

### play-client / admin-console

```sh
cd play-client          # 또는 admin-console
nvm install && nvm use
npm ci
npm run dev             # play-client → :3000, admin-console → :3001
```

- world-server 주소는 기본 `http://localhost:8080`. 바꾸려면 `NEXT_PUBLIC_WORLD_SERVER_URL`.
- 개발용 로그인 폼: `NEXT_PUBLIC_DEV_LOGIN=true npm run dev`.

### 스모크 테스트 (compose로 띄운 뒤)

`scripts/smoke-test.mjs` 가 떠 있는 world-server에 REST·WebSocket으로 붙어 1~5차 시나리오를 자동으로 돈다(Node 26 내장 `fetch`·`WebSocket` 만 씀, 설치할 것 없음). 개발용 로그인이 켜져 있어야 한다.

- 관리자 로그인 → 지역·방 `광장`·`북쪽 길`·양방향 출구·시작 방 지정. 플레이어는 관리 API 403, 미로그인 401, `X-MUD-Client` 없는 변경 403.
- 미로그인 WebSocket → `AUTH_REQUIRED` 후 4401, 허용 밖 `Origin` → 핸드셰이크 거절.
- 플레이어 두 명 캐릭터 생성 → 나타난다·보기·이동(떠난다·다가온다)·말하기·누구·종료(1000)·사라진다.
- 관리자가 플레이어가 서 있는 방을 지움 → 시작 방으로 옮겨짐. 같은 계정 재접속 → 앞 연결 4409.
- (2차) 성·종문 만들기 → 지역 소유를 성으로 → 지역 목록 `ownerName`. NPC(인사말·낱말 둘·기본 대답·LLM 켬)를 `광장` 에 배치 → NPC 상세 값.
- (2차) 플레이어 보기 → 방 머리 `owner`(성)와 occupants 의 NPC(`kind: npc`). `대화 <NPC>` 인사말과 낱말, 낱말 대답, 모르는 낱말 → 기본 대답, `도움말` 에 `대화 <NPC> [낱말]`.
- (2차) 소유 지역이 있는 성 삭제 → 409. NPC가 있는 방을 지우면 NPC 배치가 풀림.
- (3차) 아이템 종류 넷(저물대·단약·재료·법기) 만들기, 목록 앞 넷은 영석. `광장` 바닥에 재료 3개 → 방 상세 `floorItems` 남은 수.
- (3차) 시작 소지품을 비우고 플레이어 D 생성(`0/2칸`) → 시작 소지품(저물대·하품 영석 30·단약 3·법기 1) 저장, 칸 넘침 400. 상점 NPC(단약방) 배치, 판매가 너무 낮음 400, 쓰이는 종류 삭제 409.
- (3차) 플레이어 C 생성 → `소지품` `[소지품 3/22칸]  하품 영석 30`. 줍기·버리기(D가 알림 받음)·바닥 묶음·물건 보기. `목록`·`사기`·`팔기`·`값`(영석 30 → 24 → 25), 재료는 단약방이 안 삼.
- (4차 고침) 캐릭터 생성은 이름 → 영근 `목 화` → `확인`. 새 캐릭터는 범인이라 3차 상점 단계 전에 관리 API로 C를 연기 1층으로 지정한다(C가 `growth` 알림을 받음).
- (3차) 지운 `귀속` 은 모르는 명령. D에게 `주기`(단약·하품 5, 받는 문구), 칸 없는 D는 거절, 없는 사람, `도움말` 5차 문구(D92). 끝에(실패해도) 시작 소지품을 처음 값으로 되돌린다.
- (4차) 공법 둘(범인부터 9성·연기 7층부터 8성)과 신통, 명령어 이름 신통 400, 경지 목록 18. 옥간 둘(`techniqueName`), 단약에 공법 400, 옥간 있는 공법 삭제 409. 플레이어 E 생성(겹친 영근 거절·확인 prompt 네 줄) → `상태` 범인, 범인 `목록` 막힘 → 옥간 줍기·보기(담긴 공법)·`읽기`(연기 1층·화탄술, 다시 읽기 거절, 연기 7층 공법 거절) → 관리 API 캐릭터 목록·연기 7층 지정(E가 `growth` 알림, 스탯).
- (4차) 연기 7층 공법 다시 `읽기` → `공법`·`신통` 출력. 저물탁 종류를 바닥에 두고 줍기 → `(축기 초기 필요)`·칸 그대로 → 축기 초기 지정 → 칸 +100, `도움말` 5차 문구(단계 24·35, 5차 고침).
- (5차) 재료 `토끼 가죽`, 몹 `들토끼`(요수·연기 1층·일반, 재등장 10초, 고정 재료 — 스탯 `{42,7,7}`)·`흑망`(축기 대원만·두목, 계수 없이 400 → 0.6, 스탯 `{5400,78,57}`) 정의, 드롭 표, 사냥터(광장 동)와 배치, 쓰이는 재료·배치된 몹 삭제 409. E가 `보기` 를 되풀이해 몹이 나타남을 확인·`보기 들토끼`·공격 거절 셋 → 연기 7층 지정 → `공격` → 틱 교전(일격 19·맞음·이동·종료 막힘·`상태` 전투 줄) → 처치 → 시체 `(수습 가능)`·`수습` 으로 토끼 가죽.
- (5차) 재등장 알림과 교전 뒤 기혈 다시 참(120/120) → 연기 1층으로 내려 흑망을 공격해 짐(`기혈 1/60` 으로 시작 방에서 깨어남) → 다시 참(60/60), `도움말` 에 `공격 <대상> · 수습 <시체>`, 이 실행의 몹 배치를 지움. 몹 행동은 실제 서버 틱(1초)을 제한 시간 안에서 기다려(고정 대기 없음) 4차보다 약 30초 더 걸린다.

`.env` 는 위 [개발용 로그인](#개발용-로그인) 값에 스모크 테스트의 관리자 이메일 `smoke-admin@example.com` 을 더한다.

```sh
# .env
SPRING_PROFILES_ACTIVE=local
MUD_DEV_LOGIN_ENABLED=true
MUD_ADMIN_EMAILS=admin@example.com,smoke-admin@example.com
```

```sh
docker compose up -d --build
source "$NVM_DIR/nvm.sh" && nvm use 26.13.1
node scripts/smoke-test.mjs                      # 기본 http://localhost:8080. 끝에 SMOKE OK, 종료 코드 0
SMOKE_ADMIN_EMAIL=admin@example.com node scripts/smoke-test.mjs   # .env 를 안 고치고 이미 있는 관리자 이메일로
docker compose down                              # 볼륨은 남는다
```

실패하면 어느 단계에서 무엇이 기대와 달랐는지(받은 메시지 포함) 출력하고 종료 코드 1. 실행마다 지역(`스모크 <실행 번호>`)·플레이어 계정·캐릭터(한글 4자)·성(`청석성<숫자 6자리>`)·종문(`황풍곡<숫자>`)·NPC(`왕씨<숫자>`·`점소이<숫자>`·`상인<숫자>`)·아이템 종류(`회춘단<숫자>` 등)·공법(`장춘공<숫자>`·`청목결<숫자>`)을 새로 만들고 지우지 않는다. 시작 소지품은 처음에 읽어 두고 `[]` 로 정한 뒤(E의 칸 때문) 끝에(실패해도) 처음 값으로 되돌린다. 몹(`들토끼<숫자>`·`흑망<숫자>`)·재료·사냥터는 남기고 몹 배치는 끝에 지운다. 시작 방도 그 실행의 `광장` 으로 바뀐다 — 다른 맵을 쓰고 있으면 끝난 뒤 admin-console에서 시작 방을 다시 지정한다.

### 수동 확인 — 브라우저

스모크 테스트가 못 보는 것(화면·입력·실제 쿠키). 개발용 로그인으로 한다.

- [ ] http://localhost:3001 개발용 로그인(관리자 이메일) → 지역·방·출구(방위 → 대상 지역 → 대상 방, `반대 방향도`)를 만들고 시작 방 지정. 위쪽 바에 시작 방이 보인다.
- [ ] 관리자 아닌 이메일로 admin-console 로그인 → `관리자만 쓸 수 있습니다.` 와 로그아웃 버튼.
- [ ] http://localhost:3000 을 두 창(일반 창 + 시크릿 창)에서 서로 다른 이메일로 로그인 → 이름 정하기(한글 입력기로 조합 중인 글자가 Enter에 잘리지 않는지) → `확인`.
- [ ] 이동·말하기가 다른 창에 보인다. ↑↓ 입력 기록, Tab 으로 명령어·같은 방 사람 이름 자동완성.

4차 (위 [4차 시나리오](#4차-시나리오--경지영근공법-배우기저물탁)대로 만든 뒤):

5차 (위 [5차 시나리오](#5차-시나리오--몹공격처치재등장)대로 만든 뒤):

### 수동 확인 — Google 로그인

실제 Google 자격 증명으로 한 번 확인한다(자동 테스트는 Google 없이 돈다).

- [ ] `.env` 에 실제 `GOOGLE_CLIENT_ID`·`GOOGLE_CLIENT_SECRET` 을 넣고, 개발용 로그인은 끈다(`MUD_DEV_LOGIN_ENABLED=false`, `SPRING_PROFILES_ACTIVE=` 비움). `MUD_ADMIN_EMAILS` 에 내 Google 이메일. `docker compose up -d --build` (클라이언트 다시 빌드).
- [ ] world-server 시작 로그에 `Google 로그인이 설정되지 않았습니다` 경고가 **없다**.
- [ ] Google Cloud Console에서 그 클라이언트의 승인된 리디렉션 URI가 `http://localhost:8080/login/oauth2/code/google` 인지 확인한다.
- [ ] 두 클라이언트에 개발용 로그인 폼이 보이지 않고, `POST /api/auth/dev` 가 404.
- [ ] http://localhost:3001 `Google로 로그인` → Google 동의 → admin-console로 돌아와 관리 화면이 보인다.
- [ ] `MUD_ADMIN_EMAILS` 에 없는 Google 계정으로 admin-console 로그인 → `관리자만 쓸 수 있습니다.`
- [ ] http://localhost:3000 `Google로 로그인` → 돌아와 캐릭터 생성 → 이동·말하기.
- [ ] Google 화면에서 취소하면 클라이언트로 돌아와 `로그인하지 못했습니다. 다시 시도하십시오.`
