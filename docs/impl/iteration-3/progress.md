| Task 7 게임 — 물건 명령 해석, 방 바닥, 소지품·줍기·버리기·물건 보기 | | `Amount`·`ItemArguments`·`Command.Inventory/Pick/Drop`, `RoomMessage.items`(`FloorItemView`)·`InventoryMessage`(`StoneView`·`ItemView`)·`SystemMessage.item`·`NoticeMessage.item`(tone `item`), `ItemCommandHandler`(package-private `@Component`), `GameService` 방 보기마다 `roomFloor.look`, 동시 줍기 테스트. 계획에 더한 것: `Amount.MAX_COUNT`(999,999,999, `Count` 컴팩트 생성자 검사 — 앞자리 0은 떼고 셈), 버리기 검사 순서는 주기(D44)와 같게 없음 → 퀘스트 → 귀속 → 수 넘침 → 저물대 칸, 버리기에서 번호 없이 고른 귀속 묶음은 같은 종류의 귀속 안 된 묶음으로(D46), `그런 것은 보이지 않습니다.` 는 tone `error`·사람/NPC는 `info`·물건 묘사는 `item`, 방에 없음 문구의 입력은 `ItemQuery` 로 되살림(번호 포함, 영석 등급 낱말은 `하품 영석` 처럼 전체 이름). 2차 `lookWithArgument` 는 `보기 한립` 이 없는 사람이면 이제 `그런 것은 보이지 않습니다.` 라 한립을 같은 방에 들여 기대값을 지킴. | Task 8 게임 — 상점(목록·사기·팔기·값·확인·취소), 주기, 귀속, 도움말 | | `Command` 상점·주기·귀속·확인·취소(`ShopList`·`Buy`·`Sell`·`Appraise`·`Give`·`Bind`·`Unbind`·`Confirm`·`Cancel`), `ShopCommandHandler`(package-private `@Component`, `Clock` 주입), `GameSession.PendingPurchase`(10초, 정확히 10초는 아직 유효), 주기 알림(`give`), 귀속·귀속 해제, 도움말 D56. 계획과 다른 점: `PurchaseResult.NoRoomForChange.slotsNeeded` → `slotsShort`(거스름까지 넣으면 실제로 모자란 칸 — 문구 `N칸 필요` 용, 도메인 테스트 추가). `ItemArguments.hasAmount`(값에서 수량을 뺐을 때 가진 수를 쓰려고). 판정: 깨는 돌은 늘 마지막 낸 등급 1개라 확인 문구는 `{등급} 영석 1개`. `그만두었습니다.` 는 tone `info`, `확인할 것이 없습니다.`·`그만둘 것이 없습니다.` 는 `error`, 확인 질문·목록·값·성공은 `item`. 주기 대상: 이름 전체 일치(나 포함) → 앞부분 일치 다른 사람 → 앞부분이 내 이름이면 나(자기 자신 문구). 상점이 둘 이상인데 인자가 비면 `상인이 여럿입니다…`. `확인` 때 상점이 방에 없거나 상점이 아니면 `이곳에서는 할 수 없습니다.`, 물건을 더 팔지 않으면 `{NPC}: "그런 물건은 팔지 않소."`. 귀속·귀속 해제 인자는 이름 전체(수량 해석 없음). |
