# 관리 툴

머드 게임 관리 화면. → [목차](index.md)

## 데이터 주도 콘텐츠

- 시스템(엔진 코드)은 틀을 만든다. 그 틀에 담기는 내용은 하드 코딩하지 않고, 관리 툴에서 입력받는다.
  - 예: "NPC가 대사를 한다"는 틀은 엔진이, 어떤 NPC가 어떤 대사를 하는지는 관리 툴에서 입력한 데이터가 정한다.
- 어디까지가 엔진이고 어디부터가 데이터인지는 시스템마다 문서에서 정한다. 아직 정하지 않은 경계는 각 문서의 열린 질문에 남긴다.

## 관리 화면에서 하는 일

창호가 말한 것:

| 대상 | 하는 일 | 관련 문서 |
|---|---|---|
| NPC | 생성하고 배치한다 | [NPC](npc.md), [룰북: 유니크 NPC](../game-rule/npc.md#유니크-npc) |
| 몹 | 생성하고 배치한다 | [룰북: 몹](../game-rule/npc.md#몹) |
| 맵 | 만든다 | [월드 구조](world-structure.md) |

- 위 목록은 "등" 으로 말한 일부다. 나머지 대상은 (미정) → [열린 질문](#열린-질문)

## 열린 질문

- 관리 툴에서 만드는 대상은 NPC·몹·맵 말고 무엇이 있는가? (아이템, 공법·신통, 퀘스트, 이벤트·시나리오, 상점 목록, 비경, 드롭 표 등 — 룰북에 나오는 콘텐츠 중 어디까지?)
- "배치" 는 방 하나에 두는 것인가, 구역을 정해 돌아다니게 하는 것까지 포함하는가? (룰북에는 특정 방에만 있거나 정해진 구역 안을 돌아다님) → [룰북: 몹](../game-rule/npc.md#몹)
- 관리 툴에서 바꾼 내용이 실행 중인 게임에 바로 반영되는가, 다시 시작해야 하는가?
- 관리 툴을 쓰는 사람은 창호 혼자인가? 권한 구분이 필요한가?
- 관리 툴에서 운영 기능(접속자 보기, 플레이어 캐릭터 수정 등)도 하는가?
