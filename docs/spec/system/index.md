# 시스템 스펙

구현할 시스템의 스펙이다. [룰북](../game-rule/index.md)이 "플레이어가 겪는 규칙·수치"라면, 이 문서들은 "그걸 담는 틀"을 다룬다 — 어떤 시스템이 있고, 무엇이 데이터(관리 툴에서 입력)이고 무엇이 엔진 코드인지, 시스템 간 관계.

- 스펙은 얼추 잡고, 구현하면서 이터레이션마다 점점 상세화한다. 한 번에 모든 스펙을 잡지 않는다.
- 게임 규칙·수치는 여기 적지 않고 룰북의 해당 장으로 링크한다.
- 용어는 [용어집](../glossary.md)을 따른다.
- 정해지지 않은 것은 `(미정)` 으로 두거나 각 문서의 `## 열린 질문` 에 남긴다.

## 기본 방향

- 텍스트 머드 게임이다. 기존 텍스트 머드 게임의 문법을 따르되, 이 게임만의 특이한 시스템이 있다.
- 시스템(엔진)은 틀을 만들고, 그 내용은 되도록 하드 코딩하지 않고 관리 툴에서 입력받는다(어쩔 수 없는 하드 코딩은 있을 수 있음). → [관리 툴](admin-tool.md)

## 이터레이션 계획

### 1차 범위: 관리 툴 + 맵 + 인증

- 관리 툴에서 맵(방·출구)을 만들고, 게임에서 그 맵을 돌아다니기까지 구현한다. → [관리 툴](admin-tool.md), [월드 구조](world-structure.md)
- 인증(Google 로그인)도 1차 범위에 넣는다. → [인증](auth.md)
- 1차는 인증과 맵(방·출구)·돌아다니기만 한다. 성·종문 정의와 맵의 소유 지정은 다음 이터레이션으로 미룬다. → [월드 구조](world-structure.md#성--종문-소유)
- 이벤트처럼 관리 툴로 만들기 애매한 부분은 코딩으로 해결한다. → [관리 툴](admin-tool.md#데이터-주도-콘텐츠)
- 구현 계획: [`docs/impl/iteration-1/plan.md`](../../impl/iteration-1/plan.md). 계획이 스펙에 없어서 정한 결정은 이 스펙 문서들에 `(제안)` 으로 옮겼다.

### 2차 범위: NPC 배치 + 기본 대화 + 성·종문 정의

창호가 정했다(2026-11-13).

- 구현 계획: [`docs/impl/iteration-2/plan.md`](../../impl/iteration-2/plan.md). 계획이 스펙에 없어서 정한 결정(D19~D31)은 이 스펙 문서들에 `(제안)` 으로 옮겼다.
- 구현했다(2026-11-14). 진행 기록: [`docs/impl/iteration-2/progress.md`](../../impl/iteration-2/progress.md)

- **NPC 배치:** 관리 툴에서 NPC를 만들고 방에 배치한다. 게임에서 방에 있는 NPC를 본다. → [NPC: 생성과 배치](npc.md#생성과-배치), [관리 툴](admin-tool.md#관리-화면에서-하는-일)
  - 2차의 NPC는 모두 유니크 NPC(세계에 하나)이고 방 하나에 고정한다. 같은 NPC 여러 마리, 구역을 돌아다니는 NPC는 2차에 넣지 않는다.
- **기본 대화:** 게임에서 NPC와 정해진 대사(관리 툴에서 입력)로 대화한다. → [NPC: 고유 대사](npc.md#고유-대사), [룰북: 말 걸기](../game-rule/npc.md#말-걸기)
  - 대사는 룰북의 낱말 묻기 방식으로 입력한다. 관리 툴에서 인사말, 낱말마다 대답, 모르는 낱말에 하는 기본 대답을 입력한다.
  - 조건(단서·경지·종문·퀘스트 단계)에 따라 열리는 낱말은 2차에 넣지 않는다. 다음 이터레이션에서 한다.
  - 대화 명령은 `대화 <NPC> [낱말]` 이다. 1차의 `말하기`(줄임 `'`)는 그대로 같은 방 플레이어에게 말하는 채팅이다. → [명령어 처리](command.md#2차-명령어)
  - NPC가 알아서 말하기(60초마다 무작위 대사)는 2차에 넣지 않는다. NPC는 플레이어가 말을 걸 때만 답한다. 그래서 2차에도 서버 틱은 생기지 않는다.
- **LLM 대화 켬/끔 설정 자리만:** NPC마다 LLM 대화 켬/끔 값을 관리 툴에서 저장할 수 있게 자리만 만든다. 켜도 2차에서는 LLM을 부르지 않는다. → [NPC: 캐릭터 챗](npc.md#캐릭터-챗)
- **성·종문 정의와 지역 소유 지정:** 관리 툴에서 성·종문을 정의하고, 존(지역)마다 소유(성 / 종문 / 없음)를 지정한다. → [월드 구조: 성 · 종문 소유](world-structure.md#성--종문-소유)
  - 성·종문은 이름과 묘사만 가진다.
  - 지역 소유는 게임 방 화면 머리에 보인다(예: `[청석성]`).
- 2차에 넣지 않는 것: LLM 캐릭터 챗, NPC 장기 메모리, 동료 합류, NPC 역할(상점·퀘스트 등), 몹·전투, 퀘스트·공적, 성·종문 가입, 조건으로 열리는 낱말, NPC가 알아서 말하기, 같은 NPC 여러 마리, 돌아다니는 NPC.
- 2차에 걸리는 열린 질문은 [아래](#2차-이터레이션-열린-질문)에 모았다.

### 3차 범위: 아이템 + 영석 + 상점 + 저물대·귀속 + 주기

창호가 정했다(2026-11-14).

- 구현 계획: [`docs/impl/iteration-3/plan.md`](../../impl/iteration-3/plan.md). 계획이 스펙에 없어서 정한 결정(D32~D56)은 이 스펙 문서들에 `(제안)` 으로 옮겼다.
- 구현했다(2026-11-14). 진행 기록: [`docs/impl/iteration-3/progress.md`](../../impl/iteration-3/progress.md)
- 3차를 끝낸 뒤 `귀속`·`귀속 해제` 명령, 소지품의 귀속 상태, 아이템 종류의 `거래 가능` 속성, 직접 귀속 구분을 지웠다(창호, 2026-11-14). 아래 열린 질문의 답은 기록으로 남기고 끝에 `삭제됨` 을 붙였다. 퀘스트 물건은 3차에 종류로만 있고 보통 물건처럼 다룬다(퀘스트 구현 때 정함). 지운 명령은 모르는 명령이다. 옛 DB 열은 기동 때 합치고 지운다. (제안)
- 룰북에 이미 있는 규칙·수치는 그대로 따른다. 스펙과 룰북이 다르면 룰북 원칙을 우선한다. 세부(아래 [열린 질문](#3차-이터레이션-열린-질문))는 구현에서 `(제안)` 으로 정했다. 룰북보다 3차가 줄인 것: 소지품 표시에 `(꺼냄)`·내구도 없음, 상점 목록에 효과 설명 없음. 룰북 규칙은 해당 기능이 생길 때 붙인다.

- **아이템 종류 정의:** 관리 툴에서 아이템 종류를 정의한다. 이름·묘사와 룰북 공통 속성을 가진다. → [관리 툴: 3차 범위](admin-tool.md#3차-범위), [룰북: 아이템 공통 속성](../game-rule/item.md#아이템-공통-속성)
- **방 바닥 배치:** 관리 툴에서 방 바닥에 물건을 둔다. 게임에서 방에 놓인 물건이 보인다. → [월드 구조: 방 바닥 물건](world-structure.md#방-바닥-물건), [룰북: 방 보기](../game-rule/world.md#방-보기)
- **줍기·버리기·소지품 보기·물건 보기:** 게임에서 바닥 물건을 줍고, 버리고, 소지품을 보고, 물건을 자세히 본다. → [명령어 처리: 3차 명령어](command.md#3차-명령어), [룰북: 줍기와 버리기](../game-rule/item.md#줍기와-버리기)
- **시작 소지품:** 관리 툴에서 새 캐릭터가 가지고 시작할 물건을 지정한다. → [룰북: 시작 소지품](../game-rule/item.md#시작-소지품)
- **영석(화폐):** 영석을 소지품으로 가지고 값을 치른다. → [룰북: 영석](../game-rule/item.md#영석), [룰북: 결제](../game-rule/item.md#결제)
- **상점 사고팔기:** 관리 툴에서 NPC에 상점 역할(파는 물건·값)을 준다. 게임에서 그 NPC에게 사고판다. → [NPC: 역할](npc.md#역할), [룰북: 상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기), [룰북: 역할별 이용](../game-rule/npc.md#역할별-이용)
- **저물대:** 저물대가 소지품 칸을 정한다. (`귀속`·`귀속 해제` 명령과 `거래 가능` 속성은 삭제됨 — 창호, 2026-11-14. 필요하면 나중에 넣는다.) → [룰북: 저물대 · 저물탁](../game-rule/item.md#저물대--저물탁)
- **주기:** 같은 방 플레이어에게 물건·영석을 바로 넘긴다. → [룰북: 직접 거래](../game-rule/item.md#직접-거래)
- 3차 완료 시나리오(4차부터 새 캐릭터는 범인이라 상점 단계는 입문한 캐릭터로 한다 → [범인의 상점 막힘](command.md#범인의-상점-막힘)): 관리자로 admin-console 로그인 → 아이템 종류 정의 → 방 바닥에 배치 → 시작 소지품 지정 → NPC에 상점 역할(파는 물건·값) 지정 → play-client에서 새 캐릭터로 시작 소지품·영석 확인 → 바닥 물건 줍기·버리기 → 물건 보기 → 상점 NPC에게 사기·팔기(영석 증감) → 저물대 동작 → 같은 방 다른 플레이어에게 주기.
- 3차에 넣지 않는 것: 아이템을 써서 효과 내기(단약 복용 효과·부적·진법원반·법기 장착 등 — 스탯이 아직 없다), 교환 창·거래소·경매장, 제작, 몹 드롭, 공법·경지, 전투, LLM 챗.
- 3차에 걸리는 열린 질문은 [아래](#3차-이터레이션-열린-질문)에 모았다.

### 4차 범위: 경지·스탯 + 임의 경지 상승 + 공법·신통 배우기

창호가 순서를 정했다(2026-11-14): "아이템 하고, 공법 신통 이런거 배우는거 시작하고 임의로 레벨업 (경지 상승) 하는거 하고 그 다음에 전투해야할것 같아". **아래 범위는 고나가 창호 원문을 해석한 것이고, 창호 확인 전이다.** 세부는 [아래 열린 질문](#4차-이터레이션-열린-질문)에서 `(제안)` 으로 정했다.

- 룰북 규칙·수치는 그대로 따른다. 룰북보다 4차가 줄인 것(서재·`읽기 확인` 없음, 경지 안정 기간 없음, 깨달음·수위가 늘 0, 신통의 단계별 값 없음, 자질 조건은 모든 속성 영근에 같은 값 하나, 여러 속성 필요 깨달음은 똑같이 나눔만, 범인의 청우촌 밖 이동 막힘 없음(튜토리얼과 함께))은 해당 항목에 적었다. 룰북 규칙은 해당 기능이 생길 때 붙인다. (제안)

- **캐릭터 경지·스탯:** 캐릭터가 경지를 가진다. 4차 경지는 범인, 연기 1~13층, 축기 초기~대원만이다(첫 지역 MVP + 축기). 스탯(기혈·법력·의식·정혈·육신·근력·영력)은 룰북 [경지별 스탯 상승](../game-rule/realm.md#경지별-스탯-상승)과 [스탯](../game-rule/stats.md) 표대로 계산하고 `상태`(`ㅅ`)로 본다. → [플랫폼: 4차 월드 상태와 저장](platform.md#4차-월드-상태와-저장), [명령어 처리: 상태](command.md#상태)
- **영근(최소):** 캐릭터 생성에 영근 고르기를 더한다(룰북 생성 절차의 영근 단계). 영근이 없는 기존 캐릭터는 다음 접속 때 한 번 고른다. 영근·자질은 공법 배우기 조건에 쓴다. 성별·외모·출신은 4차에도 없다. → [명령어 처리: 캐릭터 생성 · 영근](command.md#캐릭터-생성--영근-4차), [룰북: 영근 · 영근 자질](../game-rule/stats.md#영근--영근-자질)
- **임의 경지 상승:** 수위·돌파 없이 관리 툴에서 캐릭터 경지를 지정한다(올리기·내리기 모두). 스탯은 바로 새 경지 값이 된다. 게임 안 관리자 명령은 두지 않는다. → [관리 툴: 4차 화면](admin-tool.md#4차-화면)
- **공법·신통 정의:** 관리 툴에서 공법과 그 신통을 정의한다(룰북 [공법이 가지는 것](../game-rule/technique.md#공법이-가지는-것)·[신통이 가지는 것](../game-rule/technique.md#신통이-가지는-것) 가운데 배우기·보기에 쓰는 것). 옥간·서책 아이템 종류에 담긴 공법을 지정한다. → [관리 툴: 4차 데이터](admin-tool.md#4차-데이터)
- **공법 익히기와 목록:** 게임에서 옥간·서책을 `읽기` 로 읽어 공법 1성에 이르고 1성 신통을 배운다. 읽은 물건은 사라진다(룰북). 시작 경지·영근·자질 조건이 맞지 않으면 거절하고 물건은 남는다. 범인이 입문 공법(시작 경지 범인)을 읽으면 연기 1층이 된다(룰북 [입문](../game-rule/character.md#입문)). 익힌 것은 `공법`·`신통` 으로 본다. → [명령어 처리: 4차 명령어](command.md#4차-명령어)
- **3차에서 미룬 것:** 저물탁을 더한다(축기 초기부터 칸이 열림). 나머지(영수대, 아이템 필요 경지 칸, 품질)는 계속 미룬다. → [4차 이터레이션 열린 질문: 3차에서 미룬 것](#4차-이터레이션-열린-질문)
- 4차 완료 시나리오: 관리 툴에서 공법·신통 정의(입문 공법 하나, 연기 7층 공법 하나) → 그 옥간 아이템 종류 정의(담긴 공법 지정) → 시작 소지품이나 바닥에 옥간을 둠 → play-client에서 새 캐릭터를 만들며 영근 고르기 → `상태` 로 범인 스탯 확인 → 입문 공법 옥간 `읽기` 로 1성·연기 1층(스탯 변화 확인) → 연기 7층 공법 옥간 `읽기` 거절(`(연기 7층 필요)`, 옥간 남음) → 관리 툴에서 경지를 연기 7층으로 지정(접속 중 알림 확인) → `상태` 로 스탯 변화 확인 → 다시 `읽기` 성공 → `공법`·`신통` 으로 익힌 목록 확인 → 저물탁 아이템 종류 정의 → 바닥에 둠 → 줍기 → `소지품` 에서 `(축기 초기 필요)` 확인 → 축기 초기로 지정해 저물탁 칸이 열리는지 확인.
- 4차에 넣지 않는 것: 신통 쓰기·전투·몹, 깨달음 쌓기·`참오`(공법 단계 올리기)·잔본·산공·서재(`서재`·`서재 익히기`·`읽기 확인`), 정식 수위 쌓기·소경지 상승·돌파·성공률, 경지 안정 기간, 단약 효과, 본명법보, 귀속(삭제됨, 창호 2026-11-14), 퀘스트, LLM 챗, 튜토리얼(`고르기`·`튜토리얼 건너뛰기`), 성별·외모·출신, 결단 이후 경지.
- 4차에 걸리는 열린 질문은 [아래](#4차-이터레이션-열린-질문)에 모았다.

### 5차 이후 후보 (예정)

창호가 순서를 정했다(2026-11-14). 범위는 그때 정한다. 단, 5차 범위는 창호가 미리 골랐다.

1. **5차: 기본 전투** (예정) → [룰북: 전투](../game-rule/combat.md), [룰북: 몹](../game-rule/npc.md#몹)
   - 넣는 것(창호가 미리 고름): 캐릭터 전투 스탯(룰북 최소한), 관리 툴에서 몹을 만들고 방에 배치, 공격 명령과 서버 틱 자동 교전, 처치·재등장.
   - 그 뒤로 미룬 것: 공법 사용·단약·도주 판정. 선공·배회·드롭·사망·경험은 그때 정한다.
2. 그 뒤 후보 (순서는 그때 정함):
   - LLM 캐릭터 챗 · NPC 장기 메모리 (예정) → [NPC: 캐릭터 챗](npc.md#캐릭터-챗), [함께 쌓는 내러티브](npc.md#함께-쌓는-내러티브)
   - 퀘스트 · 공적 (예정) → [퀘스트 · 공적 교환](quest.md)

## 열린 질문

- 월드 상태의 DB 저장 주기·시점과 게임 틱은? — 1차 저장 시점(캐릭터 위치는 이동할 때마다)과 3차 소지품(바뀌는 명령의 트랜잭션에서 바로)·바닥 물건(DB, 읽을 때 시각 비교)은 제안으로 정했다. 이후 상태·틱은 열려 있다. → [플랫폼](platform.md#열린-질문), [3차 월드 상태와 저장](platform.md#3차-월드-상태와-저장)
- WebSocket JSON 메시지 목록·스키마는? → (제안) 1차 메시지를 정했다. 2·3·4차 변경도 정했다. → [플랫폼: 1차 WebSocket 메시지](platform.md#1차-websocket-메시지), [2차 WebSocket 메시지 변경](platform.md#2차-websocket-메시지-변경), [3차 WebSocket 메시지 변경](platform.md#3차-websocket-메시지-변경), [4차 WebSocket 메시지 변경](platform.md#4차-websocket-메시지-변경)
- NPC 대사의 LLM 연동은 LLM 이터레이션(순서 미정)의 후보로 정했다(예정, [5차 이후 후보](#5차-이후-후보-예정)). 그 전까지 대사는 낱말 묻기 방식으로 입력한다([2차 범위](#2차-범위-npc-배치--기본-대화--성종문-정의)). → [NPC](npc.md)
- NPC 장기 메모리에 무엇을 어떻게 남기는가? (엔진 자동 기록 / LLM 요약 등) → [NPC](npc.md#함께-쌓는-내러티브)

### 2차 이터레이션 열린 질문

2차 구현 전에 정해야 하는 것이었다. 창호가 정하지 않아 구현 때 `(제안)` 으로 정했고, 질문마다 답과 적은 곳을 붙였다.

**NPC 데이터와 배치**
- NPC 하나가 가지는 항목은? (이름, 방에서 보이는 한 줄 묘사, 자세히 볼 때 묘사, 호칭 등) 이름은 세계에서 유일한가? → [룰북: 유니크 NPC](../game-rule/npc.md#유니크-npc)
  - → (제안) 2차 NPC는 이름(띄어쓰기 없이 1~12자, NPC끼리 유일, 영문 대소문자 무시)·인사말·낱말 대답·기본 대답·LLM 대화 켬/끔·배치 방만 가진다. 한 줄 묘사·자세히 볼 때 묘사·호칭은 `보기 <대상>` 이 생길 때 더한다. 캐릭터 이름은 NPC 이름과 겹칠 수 없다. → [NPC: 2차 데이터 모델](npc.md#2차-데이터-모델)
- NPC가 있는 방을 지우면 NPC는 어떻게 되는가? (배치만 풀림 / 시작 방으로 / 삭제)
  - → (제안) 배치만 풀린다. NPC는 남고 관리 목록에 `배치 안 됨` 으로 보인다. → [NPC: 2차 데이터 모델](npc.md#2차-데이터-모델)

**대화 명령어와 화면**
- NPC 이름을 줄여 부르거나(앞글자), 같은 방에 비슷한 이름이 둘일 때 어떻게 고르는가?
  - → (제안) 이름 전체가 같은 NPC를 먼저, 없으면 이름이 입력으로 시작하는 NPC 가운데 방 보기 순서(만든 순서) 첫째를 고른다. 영문은 대소문자를 가리지 않는다. 번호(`2.왕씨`)는 2차에 없다. → [명령어 처리: 2차 명령어](command.md#2차-명령어)
- 플레이어가 NPC와 나눈 대화를 같은 방의 다른 플레이어도 보는가?
  - → (제안) 보지 않는다. NPC의 대답은 묻는 플레이어에게만 간다. → [명령어 처리: 2차 명령어](command.md#2차-명령어)
- 방 화면에서 NPC를 플레이어 목록과 어떻게 구분해 보여주는가? NPC를 자세히 보는 명령(`보기 <NPC>`)이 있는가?
  - → (제안) 플레이어 줄 다음에 NPC 줄을 다른 스타일(`npc`)로 그린다. `보기 <NPC>` 는 1차 그대로 `아직 자세히 볼 수 없습니다.` 다. → [플랫폼: 플레이 화면](platform.md#플레이-화면-play-client), [플랫폼: 2차 WebSocket 메시지 변경](platform.md#2차-websocket-메시지-변경)

**LLM 켬/끔 자리**
- 2차에서 LLM 켬 NPC에 말을 걸면 어떻게 되는가? (그냥 정해진 대사로 답함으로 둘지)
  - → (제안) LLM 끔 NPC와 같은 정해진 대사로 답한다. 2차는 LLM을 부르지 않는다. → [NPC: 캐릭터 챗](npc.md#캐릭터-챗)
- LLM용 캐릭터 설정(성격·말투·배경) 입력 칸도 2차에 자리만 두는가, LLM 이터레이션으로 미루는가? → [NPC: 열린 질문](npc.md#열린-질문)
  - → (제안) LLM 이터레이션(순서 미정)으로 미룬다. 2차에는 칸이 없다.

**성·종문 정의와 소유**
- 성·종문이 소유한 지역이 있으면 그 성·종문을 지울 수 없게 하는가?
  - → (제안) 지울 수 없다(409 `소유한 지역이 있는 성·종문은 지울 수 없습니다`). → [월드 구조: 2차 데이터 모델](world-structure.md#2차-데이터-모델)
- NPC에 소속(성·종문)도 2차에 지정하는가?
  - → (제안) 지정하지 않는다. 가입·종문 규칙이 생길 때 더한다. → [NPC: 2차 데이터 모델](npc.md#2차-데이터-모델)

### 3차 이터레이션 열린 질문

3차 구현 전에 정해야 하는 세부였다. 창호가 정하지 않아 구현 때 `(제안)` 으로 정했고, 질문마다 답과 적은 곳을 붙였다. 룰북에 이미 답이 있으면 `→ 룰북:` 으로 적었다. 룰북 규칙·수치는 그대로 따른다.

**아이템 종류**
- 3차의 아이템 종류가 가지는 항목은? (이름·묘사 + 공통 속성 가운데 무엇을 3차에 두는가) 이름은 유일한가? → 룰북: 이름·종류·필요 경지·품질·겹침·기준가·거래 가능·귀속 → [아이템 공통 속성](../game-rule/item.md#아이템-공통-속성)
  - → (제안) 이름(1~20자, 띄어쓰기 허용, 유일·영문 대소문자 무시, 영석 등급 낱말·마지막 낱말이 수나 `전부`·`N.` 시작 금지)·묘사·종류·기준가·거래 가능·저물대 등급(저물대만)을 둔다. 겹침은 종류가 정한다. → [관리 툴: 3차 아이템 데이터](admin-tool.md#3차-아이템-데이터) → 삭제됨 (창호, 2026-11-14): 거래 가능 칸
- 종류(법기·단약·부적 …) 목록을 3차에 모두 고르게 하는가, 일부만 두는가? 쓰는 효과가 없는 3차에서 종류는 무엇을 가르는가? (겹침·매입 비율·귀속 가능 여부) → 룰북: [겹침 규칙](../game-rule/item.md#아이템-공통-속성), [매입 비율](../game-rule/item.md#상점에서-사고팔기), [직접 귀속](../game-rule/item.md#귀속)
  - → (제안) 룰북 종류 15개를 모두 두되 영석은 엔진이 만든다. 3차에 종류가 가르는 것은 겹침·매입 비율·직접 귀속 가능·칸 차지뿐이다. → [관리 툴: 종류 표](admin-tool.md#종류카테고리-표-itemcategory) → 삭제됨 (창호, 2026-11-14): 직접 귀속 가능 구분
- 품질을 3차에 두는가? 둔다면 이름 앞에 붙는 품질과 판매가·매입 배율을 계산하는가? → 룰북: [품질](../game-rule/item.md#품질)
  - → (제안) 두지 않는다. 모두 하계로 본다(배율 ×1). → [관리 툴: 3차 아이템 데이터](admin-tool.md#3차-아이템-데이터)
- 필요 경지는 경지가 없는 3차에 입력만 받는가, 빼는가? → 룰북: 모자라도 가지고 다니고 거래할 수 있다 → [아이템 공통 속성](../game-rule/item.md#아이템-공통-속성)
  - → (제안) 칸도 두지 않는다. 경지가 생길 때 더한다. → [관리 툴: 3차 아이템 데이터](admin-tool.md#3차-아이템-데이터)
- 아이템 종류를 지울 때 바닥·소지품·상점·시작 소지품에 그 물건이 있으면 어떻게 하는가?
  - → (제안) 어디든 쓰이면 지울 수 없고(409) 종류·저물대 등급도 바꿀 수 없다. → [관리 툴: 관리 툴 변경의 반영](admin-tool.md#관리-툴-변경의-반영)
- 같은 종류의 물건이 개체마다 다른 값(귀속 여부, 법기 내구도 등)을 가지는가? 3차에 개체 단위로 저장해야 하는 것은 귀속뿐인가?
  - → (제안) 3차에 개체 단위로 저장하는 것은 귀속 여부뿐이다(귀속된 것과 안 된 것은 다른 묶음). → [관리 툴: 3차 아이템 데이터](admin-tool.md#3차-아이템-데이터), [플랫폼: 3차 월드 상태와 저장](platform.md#3차-월드-상태와-저장) → 삭제됨 (창호, 2026-11-14): 귀속 구분이 없어 같은 종류는 한 묶음
- 관리 툴에서 바꾼 아이템 종류·바닥 배치·시작 소지품·상점 역할이 실행 중인 게임에 바로 반영되는가? → [관리 툴: 관리 툴 변경의 반영](admin-tool.md#관리-툴-변경의-반영)
  - → (제안) 바로 반영된다(게임이 명령마다 DB에서 읽음). 바닥은 다음 방 보기부터, 시작 소지품은 그 뒤 만드는 캐릭터부터, 상점은 다음 상점 명령부터다. → [관리 툴: 관리 툴 변경의 반영](admin-tool.md#관리-툴-변경의-반영)

**영석**
- 3차에 영석 4등급(하품·중품·상품·극품)을 모두 두는가, 하품만 두는가? → 룰북: 4등급, 결제 때 한 등급 위 1개 = 아래 100개, 낮은 등급부터 내고 거스름은 하품 → [영석](../game-rule/item.md#영석), [결제](../game-rule/item.md#결제)
  - → (제안) 4등급을 모두 둔다. → [관리 툴: 영석](admin-tool.md#영석), [명령어 처리: 결제와 `확인`](command.md#결제와-확인)
- 영석은 아이템 종류 데이터인가, 엔진이 아는 고정 물건인가?
  - → (제안) 엔진이 서버 시작 때 심는 아이템 종류 4개다. 소지품 칸을 차지하는 일반 물건이고 관리 툴로 고치거나 지울 수 없다. → [관리 툴: 영석](admin-tool.md#영석)
- 상위 등급 깨기 확인(`확인`)과 거스름 넘침을 3차에 하는가? → 룰북: [결제](../game-rule/item.md#결제)
  - → (제안) 둘 다 한다. 확인은 그 돌을 실제로 깰 때만 묻고(10초), 거스름이 칸에 안 들어가면 결제하지 않는다. → [명령어 처리: 결제와 `확인`](command.md#결제와-확인)

**상점**
- 상점 역할의 데이터는? (파는 물건 목록, 사 주는 종류, 값을 기준가에서 계산할지 상점마다 입력할지) → 룰북: 판매가 = 기준가 × 품질 판매가 배율, 매입가 = 하계 기준가 × 매입 비율 × 품질 매입 배율 → [상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기), [상점 종류](../game-rule/game-structure.md#상점)
  - → (제안) 상점 종류(엔진 enum 7종) + 파는 물건 `[{itemTypeId, price}]`(50개까지). 값은 비우면 기준가에서 계산하고 매입가는 입력받지 않는다(룰북 식). → [NPC: 3차 상점 역할 데이터](npc.md#3차-상점-역할-데이터)
- 상점 재고는 끝없이 있는가, 수가 정해져 있는가? → 룰북: 재고는 무한이고 가격은 바뀌지 않는다. 플레이어가 판 물건은 다시 팔지 않고 사라진다, 매입 수량 한도 없음 → [상점](../game-rule/game-structure.md#상점), [상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기)
  - → (제안) 무한이다(룰북 그대로). → [NPC: 3차 상점 역할 데이터](npc.md#3차-상점-역할-데이터)
- 상점 종류(단약방·법기점 …)를 3차에 데이터로 두는가, 사 주는 종류를 NPC마다 직접 고르는가? → 룰북: [상점](../game-rule/game-structure.md#상점)
  - → (제안) 엔진 enum이다. 사 주는 것은 종류가 정하고 파는 물건도 그 종류의 종류만 둘 수 있다. → [NPC: 3차 상점 역할 데이터](npc.md#3차-상점-역할-데이터)
- `값 <물건>` 을 3차에 넣는가? → 룰북: [역할별 이용](../game-rule/npc.md#역할별-이용)
  - → (제안) 넣는다. → [명령어 처리: 상점 명령](command.md#상점-명령)
- 상점 불변식(매입가 < 판매가 × 0.5)을 관리 툴이 검사하는가? → 룰북: [상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기)
  - → (제안) 검사한다(상점 저장 때 400, 기준가를 바꿀 때 409). 제작물 불변식은 제작이 없어 검사하지 않는다. → [NPC: 3차 상점 역할 데이터](npc.md#3차-상점-역할-데이터)

**소지품 · 저물대 · 귀속**
- 소지품 한도는? → 룰북: 무게 없음, 칸 수로만. 기본 2칸 + 저물대·저물탁 칸 합. 저물대 3개·저물탁 1개까지, 저물대 하급 20 · 중급 40 · 상급 80칸 → [저물대 · 저물탁](../game-rule/item.md#저물대--저물탁)
  - → (제안) 칸 = 기본 2칸 + 가진 저물대 칸의 합, `(종류, 귀속)` 묶음마다 `올림(수 ÷ 겹침)` 칸이다. → [플랫폼: 3차 월드 상태와 저장](platform.md#3차-월드-상태와-저장) → 삭제됨 (창호, 2026-11-14): 묶음은 `(종류)` 마다 하나
- 저물대 크기는 아이템 종류의 속성인가? 저물탁(필요 경지 축기 초기)을 경지가 없는 3차에 어떻게 다루는가?
  - → (제안) 저물대 등급(하급 20·중급 40·상급 80칸)이 아이템 종류의 속성이다. 저물탁은 3차에 없다(경지·의식이 없음, 4차에 더함). → [관리 툴: 3차 아이템 데이터](admin-tool.md#3차-아이템-데이터)
- 귀속 시점은? 3차에 생기는 귀속 경우는 무엇인가? (처음부터 귀속된 물건을 관리 툴에서 정하는가, `귀속` 명령만인가) → 룰북: 퀘스트 물건·본명법보·퀘스트 보상·직접 귀속 → [귀속](../game-rule/item.md#귀속)
  - → (제안) `귀속` 명령뿐이다(직접 귀속 종류만). 처음부터 귀속된 물건은 만들지 않는다. → [명령어 처리: 귀속](command.md#귀속) → 삭제됨 (창호, 2026-11-14)
- 직접 귀속은 정혈 최대치의 10% 를 쓰는데 3차에는 정혈 스탯이 없다. 3차의 `귀속` 은 무엇을 소모하는가? → 룰북: [귀속](../game-rule/item.md#귀속)
  - → (제안) 아무것도 소모하지 않는다. 정혈 소모는 스탯이 생기는 이터레이션에서 붙인다. → [명령어 처리: 귀속](command.md#귀속) → 삭제됨 (창호, 2026-11-14)
- 시작 소지품의 영수대는 영수가 없는 3차에 어떻게 하는가? → 룰북: [시작 소지품](../game-rule/item.md#시작-소지품)
  - → (제안) 넣지 않는다. 영수가 생길 때 더한다. → [관리 툴: 시작 소지품](admin-tool.md#시작-소지품-worldsettingsstartingitems)

**바닥 물건**
- 관리 툴로 배치한 바닥 물건은 주우면 다시 나타나는가(얼마 뒤), 한 번뿐인가? 캐릭터마다인가, 모두 한 번인가? → 룰북: 플레이어가 버린 물건만 정했다(5분 남고 사라짐) → [줍기와 버리기](../game-rule/item.md#줍기와-버리기)
  - → (제안) 모두가 함께 쓰는 하나이고, 비운 뒤 재등장 분(1~1,440, 기본 10분)이 지나면 처음 수로 다시 놓인다. 재등장 없음이면 한 번뿐이다. → [월드 구조: 3차 데이터 모델](world-structure.md#3차-데이터-모델)
- 버린 물건이 5분 뒤 사라지려면 시간을 재는 무언가(서버 틱·예약 작업)가 필요하다. 3차에 무엇으로 하는가? → [플랫폼: 3차 월드 상태](platform.md#3차-월드-상태와-저장)
  - → (제안) 틱·예약 작업 없이 바닥을 읽을 때(방 보기·줍기·보기) 시각을 비교해 지운다. → [플랫폼: 3차 월드 상태와 저장](platform.md#3차-월드-상태와-저장), [월드 구조: 3차 데이터 모델](world-structure.md#3차-데이터-모델)
- 서버를 다시 시작하면 바닥 물건은 남는가?
  - → (제안) 남는다(둘 다 DB). → [월드 구조: 3차 데이터 모델](world-structure.md#3차-데이터-모델)
- 바닥 물건을 방 보기에 어떻게 보이는가? 같은 물건은 묶는가? → 룰북: 대상 목록의 맨 끝, `하품 영석 3개` → [방 보기](../game-rule/world.md#방-보기)
  - → (제안) 대상 목록 맨 끝에 같은 종류를 한 줄로 묶어 `하품 영석 3개`(1개면 이름만)로 보인다. → [월드 구조: 3차 데이터 모델](world-structure.md#3차-데이터-모델)

**명령 · 화면**
- `보기 <물건>` 은 바닥 물건만 보는가, 내 소지품도 보는가? 찾는 순서는? → 룰북: 물건은 이름과 설명을 보여준다 → [방 보기](../game-rule/world.md#방-보기), [대상 지정](../game-rule/commands.md#대상-지정)
  - → (제안) 방의 대상(플레이어 → NPC → 바닥 물건)을 먼저 보고, 없으면 내 소지품에서 찾는다. → [명령어 처리: 줍기·버리기·소지품·물건 보기](command.md#줍기버리기소지품물건-보기)
- 물건 이름 찾기(앞부분·낱말 앞부분 일치, 번호 `2.가죽`, 수량 `전부`)를 3차에 어디까지 하는가? → 룰북: [입력 문법](../game-rule/commands.md#입력-문법), [대상 지정](../game-rule/commands.md#대상-지정)
  - → (제안) 전체·앞부분·낱말 앞부분 일치, 번호 `2.가죽`, `전부` 모두 한다(전체 일치 우선). → [명령어 처리: 물건 이름 찾기와 수량](command.md#물건-이름-찾기와-수량)
- `주기` 를 받는 쪽이 접속하지 않았거나 같은 방에 없으면? → 룰북: `여기에 한립은 없습니다.` → [직접 거래](../game-rule/item.md#직접-거래)
  - → (제안) 룰북 문구 `여기에 한립은 없습니다.` 를 그대로 쓴다. → [명령어 처리: 주기](command.md#주기)
- 물건이 오가면 같은 방 다른 사람에게 알리는가? (줍기·버리기·주기)
  - → (제안) 줍기·버리기·주기는 알린다(`notice` tone `item`). 상점 거래·보기는 알리지 않는다. → [명령어 처리: 3차 같은 방 알림](command.md#3차-같은-방-알림)

### 4차 이터레이션 열린 질문

4차 구현 전에 정해야 하는 세부다. 창호가 정하지 않아 고나 쪽에서 `(제안)` 으로 정했고, 질문마다 답과 적은 곳을 붙였다. 룰북에 이미 답이 있으면 `→ 룰북:` 으로 적었다. 룰북 규칙·수치는 그대로 따른다.

**경지와 스탯의 데이터**
- 4차에 어느 경지까지 두는가? → 룰북: 대경지 13개, 연기 1~13층, 축기부터 초기·중기·후기·대원만 → [경지](../game-rule/realm.md#경지)
  - → (제안) 범인, 연기 1~13층, 축기 초기~대원만(18단계)만 둔다. 결단 이후는 콘텐츠·수치가 생길 때 더한다. → [플랫폼: 4차 월드 상태와 저장](platform.md#4차-월드-상태와-저장)
- 스탯은 저장하는가, 계산하는가? 현재 수치와 최대치는?
  - → (제안) 저장하는 것은 경지, 영근(오행과 처음 자질), 익힌 공법(공법과 단계)뿐이다. 최대치와 포인트 스탯(육신·근력·영력·의식·정혈·기혈·법력·영근 자질)은 명령마다 경지 몫 + 익힌 공법 단계 몫으로 계산한다. 4차에는 현재 수치를 깎는 것(전투·소모·사망)이 없어 현재 수치는 늘 최대치이므로 저장하지 않는다. 현재 수치 저장은 깎는 것이 생기는 5차에 더한다. → [플랫폼: 4차 월드 상태와 저장](platform.md#4차-월드-상태와-저장)
- 경지 몫 스탯 수치는? → 룰북: [경지별 스탯 상승](../game-rule/realm.md#경지별-스탯-상승), [육신](../game-rule/stats.md#육신)·[근력](../game-rule/stats.md#근력)·[영력](../game-rule/stats.md#영력-진원)·[의식](../game-rule/stats.md#의식)·[정혈](../game-rule/stats.md#정혈) 표
  - → (제안) 룰북 규칙을 식으로 옮긴 표를 엔진 상수로 둔다(축기 소경지는 초기 몫 × (1 + k/6) 을 반올림 — 룰북 표 값과 맞는 쪽). → [플랫폼: 경지 몫 스탯 표](platform.md#경지-몫-스탯-표)
- 기존 캐릭터와 새 캐릭터의 처음 경지는? → 룰북: 새 캐릭터는 범인으로 시작하고 입문 공법 1성에 이르면 연기 1층 → [입문](../game-rule/character.md#입문)
  - → (제안) 새 캐릭터는 룰북대로 범인이다. 4차 전에 만든 캐릭터는 연기 1층으로 한다(서버가 뜰 때 경지가 빈 행을 채움). 기존 캐릭터는 공법 없이 연기 1층이 되는 셈이지만 3차까지 상점을 쓰던 캐릭터가 범인 막힘에 걸리지 않게 하려는 것이다. → [플랫폼: 4차 월드 상태와 저장](platform.md#4차-월드-상태와-저장)
- 경지가 바뀌면 현재 수치는? → 룰북: 오르면 오른 만큼 현재 수치도 오르고(영력은 안정 기간 동안 차오름), 내려가면 새 최대치까지 깎임 → [최대치가 바뀔 때](../game-rule/stats.md#최대치가-바뀔-때)
  - → (제안) 4차 현재 수치는 늘 최대치라 룰북 규칙과 어긋나지 않는다. **관리 툴 경지 지정은 경지 안정 기간 없이 영력도 바로 찬다.** 룰북의 안정 기간은 수위로 경지가 오를 때의 규칙이고, 관리자 지정은 룰북 경지 상승이 아니라 시험용 도구이기 때문이다(입문의 '안정 기간 없이 바로' 와 같게 다룬다). 안정 기간은 정식 소경지 상승·돌파와 함께 붙인다.

**영근 (최소)**
- 무엇을 저장하고 언제 정하는가? → 룰북: 생성 때 오행 1~5개를 고르고 자질 총량 100을 균등하게 나눔, 확인한 뒤 바꿀 수 없음 → [영근 · 영근 자질](../game-rule/stats.md#영근--영근-자질), [생성 절차](../game-rule/character.md#생성-절차)
  - → (제안) 오행마다 처음 자질(소수, 100 ÷ 개수)을 저장한다. 생성 절차는 이름 → 영근 → 확인이다(성별·외모·출신은 아직 없음). 문구는 룰북 예를 그대로 쓴다. → [명령어 처리: 캐릭터 생성 · 영근](command.md#캐릭터-생성--영근-4차)
- 영근이 없는 기존 캐릭터는?
  - → (제안) 다음 접속 때 세계에 들어가기 전에 한 번 고른다(같은 영근 prompt·확인). 관리 툴로 정하거나 바꾸지 않는다(룰북: 확인 뒤 바꿀 수 없음). → [명령어 처리: 캐릭터 생성 · 영근](command.md#캐릭터-생성--영근-4차)
- 영근이 4차 스탯·배우기에 영향을 주는가? → 룰북: 공법 속성 영근이 있어야 하고 1성 자질 조건을 맞춰야 익힘. 연체술은 조건 없음 → [공법](../game-rule/technique.md#공법)
  - → (제안) 배우기 조건에만 쓴다. 영근 자질은 `상태` 에 보이고 공법 단계의 영근 자질 증가가 더해진다. 위력·돌파 성공률은 4차에 없다.

**공법·신통 정의**
- 공법이 가지는 항목은? → 룰북: [공법이 가지는 것](../game-rule/technique.md#공법이-가지는-것)
  - → (제안) 이름·묘사·속성(0~5, 없으면 연체술)·시작 경지·단계 수(1~12)·단계 표(단계마다 필요 깨달음 합, 영근 자질 조건, 법력·의식·영력·정혈·육신·근력·영근 자질 증가)·신통을 둔다. 계열은 속성으로 정해진다(룰북). 수위(주는지·계수·마지막 경지)·잔본·충돌·얻는 곳은 `참오`·잔본·산공이 생길 때 더한다. 여러 속성의 필요 깨달음은 룰북 기본(속성 수로 똑같이 나눔)만, 자질 조건은 모든 속성 영근에 같은 값 하나만 둔다. → [관리 툴: 4차 데이터](admin-tool.md#4차-데이터)
- 신통이 가지는 항목은? 신통은 공법에 딸리는가, 따로 있는가? → 룰북: [신통이 가지는 것](../game-rule/technique.md#신통이-가지는-것). 같은 이름 신통이 공법마다 속성이 다름(경신술) → [오행 입문 공법](../game-rule/technique-list.md#오행-입문-공법)
  - → (제안) 신통은 한 공법에 딸리고 배우는 단계를 가진다. 이름(공법 안에서 유일, 명령어와 같으면 안 됨)·종류·속성·대상·소모(스탯·양·한 번에/틱마다)·시전 시간·재사용 대기시간·쓸 수 있는 때를 둔다. 단계별 값(위력·계수 등)은 신통 쓰기·전투가 생길 때 더한다. 1성에 신통이 하나 이상 있어야 하고(룰북), 연체술 공법의 신통은 법력을 소모하지 않는다(룰북). → [관리 툴: 4차 데이터](admin-tool.md#4차-데이터)
- 옥간·서책 아이템은 공법과 어떻게 이어지는가?
  - → (제안) 종류가 옥간·서책(`SCROLL`)인 아이템 종류에 `담긴 공법`(공법 하나 또는 없음)을 둔다. 한 공법을 여러 아이템(옥간·서책)에 담을 수 있다. 다른 종류에는 둘 수 없다. 제작법은 제작이 생길 때 더한다. → [관리 툴: 옥간·서책의 담긴 공법](admin-tool.md#옥간서책의-담긴-공법)
- 공법을 지우거나 고칠 때는?
  - → (제안) 누군가 익혔거나 아이템에 담겨 있으면 지울 수 없다(409). 고치는 것은 막지 않고 바로 반영된다(배운 신통·스탯은 계산이라 바뀐 정의를 따름). 단계 수를 익힌 캐릭터의 단계보다 줄이는 것만 막는다(409). → [관리 툴: 4차 데이터](admin-tool.md#4차-데이터)

**읽기와 배우는 조건**
- 명령 이름과 흐름은? 읽으면 물건이 사라지는가? → 룰북: `읽기 <옥간·서책·잔엽>`, 읽으면 사라지고 1성에 이름, 범인이 입문 공법 1성이면 연기 1층 → [공법](../game-rule/technique.md#공법), [성장](../game-rule/commands.md#성장), [튜토리얼](../game-rule/character.md#튜토리얼)
  - → (제안) 룰북 그대로다. 성공하면 그 물건 1개가 사라진다. 문구는 룰북 예를 쓴다. → [명령어 처리: 읽기](command.md#읽기)
- 조건이 맞지 않으면? → 룰북: 알려 주고 '읽기 확인' 으로 서재에 남길지 묻는다 → [서재](../game-rule/technique.md#서재)
  - → (제안) **4차에는 서재가 없어 거절만 하고 물건은 남는다.** 문구는 룰북 앞부분(`지금은 이 공법을 익힐 수 없습니다. (연기 7층 필요)`)만 쓰고 `읽기 확인` 안내는 뺀다. 서재가 생기면 룰북대로 붙인다. → [명령어 처리: 읽기](command.md#읽기)
- 조건 검사 순서는? → 룰북: `참오` 의 순서(익혔는가 → … → 시작 경지 → 자질) → [공법 단계 올리기](../game-rule/technique.md#공법-단계-올리기)
  - → (제안) 인자 → 소지품에 있음 → 옥간·서책 → 담긴 공법 → 이미 익힘 → 시작 경지 → 속성 영근(오행 순) → 1성 자질 조건(오행 순). 처음 걸린 것만 알린다. → [명령어 처리: 읽기](command.md#읽기)
- 이미 익힌 공법의 옥간을 또 읽으면? → 룰북: 이미 서재에 있는 잔엽은 읽을 수 없고 사라지지 않음 `이미 깨친 내용입니다. (청원검결 3/9장)` → [잔본 규칙](../game-rule/technique.md#잔본-규칙)
  - → (제안) 같게 다룬다: `이미 깨친 내용입니다. (장춘공 1/9성)`, 물건은 남는다.
- 익힐 수 있는 공법 수 제한은? → 룰북: 제한 없음 → [공법](../game-rule/technique.md#공법)
  - → (제안) 두지 않는다.

**명령 · 화면**
- `상태`·`공법`·`신통` 출력은? → 룰북: [정보 명령 출력 형식](../game-rule/commands.md#정보)
  - → (제안) 룰북 형식에서 4차에 값이 있는 줄만 쓴다(성별·영기·지속 효과·전투 줄·대기 남은 시간·법기·서재 줄 없음). 깨달음·수위 줄은 늘 0이지만 룰북 형식대로 보인다. 칸 맞춤 공백은 3차 `목록` 처럼 하지 않는다. → [명령어 처리: 상태](command.md#상태), [공법 · 신통](command.md#공법--신통)
- 범인의 막힘을 4차에 하는가? → 룰북: 범인은 청우촌 밖 이동·`명상`·법기 `꺼내기`·상점(`목록`·`사기`·`팔기`)이 막힘 → [상태별로 쓸 수 없는 명령](../game-rule/commands.md#상태별로-쓸-수-없는-명령)
  - → (제안) 상점 막힘만 한다(`아직 범인의 몸이라 할 수 없습니다.`). 청우촌 밖 막힘은 튜토리얼 NPC 대사로 막는 콘텐츠라 튜토리얼과 함께, `명상`·`꺼내기` 는 명령이 생길 때 붙인다. → [명령어 처리: 범인의 상점 막힘](command.md#범인의-상점-막힘)
- 게임 안 관리자 명령(경지 지정)을 두는가?
  - → (제안) 두지 않는다. 관리 툴로 충분하고, 게임 명령에 권한 검사를 새로 넣지 않는다. → [관리 툴: 4차 화면](admin-tool.md#4차-화면)
- 관리 툴 경지 지정은 실행 중인 게임에 어떻게 반영되는가? 알리는가?
  - → (제안) 바로 반영된다(경지는 명령마다 DB에서 읽음). 커밋 뒤 접속 중인 그 캐릭터에게만 `경지가 연기 7층으로 바뀌었습니다. (육신 +6, …)` 를 보낸다. 같은 방 알림은 없다. → [플랫폼: 4차 월드 상태와 저장](platform.md#4차-월드-상태와-저장), [명령어 처리: 경지가 바뀔 때](command.md#경지가-바뀔-때)
- play-client에 상태 창(늘 보이는 패널)을 두는가?
  - → (제안) 두지 않는다. `상태` 는 로그에 그린다. 패널을 나중에 붙일 수 있게 `status` 메시지는 구조를 가진다. → [플랫폼: 4차 WebSocket 메시지 변경](platform.md#4차-websocket-메시지-변경)
- 같은 방 알림은? → 룰북: 소경지 상승 때 `○○의 기운이 한층 짙어진다.` → [소경지 상승](../game-rule/realm.md#소경지-상승)
  - → (제안) 4차에는 없다. 읽기·관리자 경지 지정은 룰북 소경지 상승이 아니다. 정식 소경지 상승이 생길 때 붙인다.

**3차에서 미룬 것**
- 저물탁 → 룰북: 1개까지, 하급 100·중급 200·상급 400칸, 필요 경지 축기 초기 → [저물대 · 저물탁](../game-rule/item.md#저물대--저물탁)
  - → (제안) 4차에 넣는다. 축기 초기 아래에서는 가지고 다니고 거래할 수 있지만 칸이 0이다(룰북 필요 경지: 모자라도 가지고 다님). '의식으로 여닫음' 은 의식 소모가 없는 설명으로 본다. → [관리 툴: 저물탁](admin-tool.md#저물탁), [플랫폼: 4차 월드 상태와 저장](platform.md#4차-월드-상태와-저장)
- 영수대 → (제안) 계속 미룬다. 영수 시스템이 없다.
- 아이템 필요 경지 칸 → (제안) 계속 미룬다. 4차에 아이템을 쓰는 것은 `읽기`(조건은 공법의 시작 경지)와 저물탁(룰북이 축기 초기로 정함)뿐이라 쓰는 곳이 없다. 단약·부적·법기 쓰기가 생길 때 더한다.
- 품질 → (제안) 계속 미룬다. 품질 있는 물건을 얻는 길(제작·드롭)이 없다.
- 2차에서 미룬 경지 조건 낱말(NPC 대화) → (제안) 계속 미룬다. 단서·종문·퀘스트 조건과 한 틀로 만들 것이라 퀘스트 이터레이션에서 한다.
- 방 보기 지역 줄의 권장 경지(`◇ 지역 (권장: …)`) → (제안) 계속 미룬다. 권장 경지는 몹 세기와 함께 정하는 것이라 5차(몹)에서 붙인다.
