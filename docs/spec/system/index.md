# 시스템 스펙

구현할 시스템의 스펙이다. [룰북](../game-rule/index.md)이 "플레이어가 겪는 규칙·수치"라면, 이 문서들은 "그걸 담는 틀"을 다룬다 — 어떤 시스템이 있고, 무엇이 데이터(관리 툴에서 입력)이고 무엇이 엔진 코드인지, 시스템 간 관계.

- 스펙은 얼추 잡고, 구현하면서 이터레이션마다 점점 상세화한다. 한 번에 모든 스펙을 잡지 않는다.
- 게임 규칙·수치는 여기 적지 않고 룰북의 해당 장으로 링크한다.
- 용어는 [용어집](../glossary.md)을 따른다.
- 정해지지 않은 것은 `(미정)` 으로 두거나 각 문서의 `## 열린 질문` 에 남긴다.

## 기본 방향

- 텍스트 머드 게임이다. 기존 텍스트 머드 게임의 문법을 따르되, 이 게임만의 특이한 시스템이 있다.
- 시스템(엔진)은 틀을 만들고, 그 내용은 되도록 하드 코딩하지 않고 관리 툴에서 입력받는다(어쩔 수 없는 하드 코딩은 있을 수 있음). → [관리 툴](admin-tool.md)

## 이터레이션 계획

### 1차 범위: 관리 툴 + 맵 + 인증

- 관리 툴에서 맵(방·출구)을 만들고, 게임에서 그 맵을 돌아다니기까지 구현한다. → [관리 툴](admin-tool.md), [월드 구조](world-structure.md)
- 인증(Google 로그인)도 1차 범위에 넣는다. → [인증](auth.md)
- 1차는 인증과 맵(방·출구)·돌아다니기만 한다. 성·종문 정의와 맵의 소유 지정은 다음 이터레이션으로 미룬다. → [월드 구조](world-structure.md#성--종문-소유)
- 이벤트처럼 관리 툴로 만들기 애매한 부분은 코딩으로 해결한다. → [관리 툴](admin-tool.md#데이터-주도-콘텐츠)
- 구현 계획: [`docs/impl/iteration-1/plan.md`](../../impl/iteration-1/plan.md). 계획이 스펙에 없어서 정한 결정은 이 스펙 문서들에 `(제안)` 으로 옮겼다.

### 2차 범위: NPC 배치 + 기본 대화 + 성·종문 정의

창호가 정했다(2026-11-13).

- 구현 계획: [`docs/impl/iteration-2/plan.md`](../../impl/iteration-2/plan.md). 계획이 스펙에 없어서 정한 결정(D19~D31)은 이 스펙 문서들에 `(제안)` 으로 옮겼다.
- 구현했다(2026-11-14). 진행 기록: [`docs/impl/iteration-2/progress.md`](../../impl/iteration-2/progress.md)

- **NPC 배치:** 관리 툴에서 NPC를 만들고 방에 배치한다. 게임에서 방에 있는 NPC를 본다. → [NPC: 생성과 배치](npc.md#생성과-배치), [관리 툴](admin-tool.md#관리-화면에서-하는-일)
  - 2차의 NPC는 모두 유니크 NPC(세계에 하나)이고 방 하나에 고정한다. 같은 NPC 여러 마리, 구역을 돌아다니는 NPC는 2차에 넣지 않는다.
- **기본 대화:** 게임에서 NPC와 정해진 대사(관리 툴에서 입력)로 대화한다. → [NPC: 고유 대사](npc.md#고유-대사), [룰북: 말 걸기](../game-rule/npc.md#말-걸기)
  - 대사는 룰북의 낱말 묻기 방식으로 입력한다. 관리 툴에서 인사말, 낱말마다 대답, 모르는 낱말에 하는 기본 대답을 입력한다.
  - 조건(단서·경지·종문·퀘스트 단계)에 따라 열리는 낱말은 2차에 넣지 않는다. 다음 이터레이션에서 한다.
  - 대화 명령은 `대화 <NPC> [낱말]` 이다. 1차의 `말하기`(줄임 `'`)는 그대로 같은 방 플레이어에게 말하는 채팅이다. → [명령어 처리](command.md#2차-명령어)
  - NPC가 알아서 말하기(60초마다 무작위 대사)는 2차에 넣지 않는다. NPC는 플레이어가 말을 걸 때만 답한다. 그래서 2차에도 서버 틱은 생기지 않는다.
- **LLM 대화 켬/끔 설정 자리만:** NPC마다 LLM 대화 켬/끔 값을 관리 툴에서 저장할 수 있게 자리만 만든다. 켜도 2차에서는 LLM을 부르지 않는다. → [NPC: 캐릭터 챗](npc.md#캐릭터-챗)
- **성·종문 정의와 지역 소유 지정:** 관리 툴에서 성·종문을 정의하고, 존(지역)마다 소유(성 / 종문 / 없음)를 지정한다. → [월드 구조: 성 · 종문 소유](world-structure.md#성--종문-소유)
  - 성·종문은 이름과 묘사만 가진다.
  - 지역 소유는 게임 방 화면 머리에 보인다(예: `[청석성]`).
- 2차에 넣지 않는 것: LLM 캐릭터 챗, NPC 장기 메모리, 동료 합류, NPC 역할(상점·퀘스트 등), 몹·전투, 퀘스트·공적, 성·종문 가입, 조건으로 열리는 낱말, NPC가 알아서 말하기, 같은 NPC 여러 마리, 돌아다니는 NPC.
- 2차에 걸리는 열린 질문은 [아래](#2차-이터레이션-열린-질문)에 모았다.

### 3차 범위: 아이템 + 영석 + 상점 + 저물대·귀속 + 주기

창호가 정했다(2026-11-14).

- 구현 계획: [`docs/impl/iteration-3/plan.md`](../../impl/iteration-3/plan.md). 계획이 스펙에 없어서 정한 결정(D32~D56)은 이 스펙 문서들에 `(제안)` 으로 옮겼다.
- 구현했다(2026-11-14). 진행 기록: [`docs/impl/iteration-3/progress.md`](../../impl/iteration-3/progress.md)
- 3차를 끝낸 뒤 `귀속`·`귀속 해제` 명령, 소지품의 귀속 상태, 아이템 종류의 `거래 가능` 속성, 직접 귀속 구분을 지웠다(창호, 2026-11-14). 아래 열린 질문의 답은 기록으로 남기고 끝에 `삭제됨` 을 붙였다. 퀘스트 물건은 3차에 종류로만 있고 보통 물건처럼 다룬다(퀘스트 구현 때 정함). 지운 명령은 모르는 명령이다. 옛 DB 열은 기동 때 합치고 지운다. (제안)
- 룰북에 이미 있는 규칙·수치는 그대로 따른다. 스펙과 룰북이 다르면 룰북 원칙을 우선한다. 세부(아래 [열린 질문](#3차-이터레이션-열린-질문))는 구현에서 `(제안)` 으로 정했다. 룰북보다 3차가 줄인 것: 소지품 표시에 `(꺼냄)`·내구도 없음, 상점 목록에 효과 설명 없음. 룰북 규칙은 해당 기능이 생길 때 붙인다.

- **아이템 종류 정의:** 관리 툴에서 아이템 종류를 정의한다. 이름·묘사와 룰북 공통 속성을 가진다. → [관리 툴: 3차 범위](admin-tool.md#3차-범위), [룰북: 아이템 공통 속성](../game-rule/item.md#아이템-공통-속성)
- **방 바닥 배치:** 관리 툴에서 방 바닥에 물건을 둔다. 게임에서 방에 놓인 물건이 보인다. → [월드 구조: 방 바닥 물건](world-structure.md#방-바닥-물건), [룰북: 방 보기](../game-rule/world.md#방-보기)
- **줍기·버리기·소지품 보기·물건 보기:** 게임에서 바닥 물건을 줍고, 버리고, 소지품을 보고, 물건을 자세히 본다. → [명령어 처리: 3차 명령어](command.md#3차-명령어), [룰북: 줍기와 버리기](../game-rule/item.md#줍기와-버리기)
- **시작 소지품:** 관리 툴에서 새 캐릭터가 가지고 시작할 물건을 지정한다. → [룰북: 시작 소지품](../game-rule/item.md#시작-소지품)
- **영석(화폐):** 영석을 소지품으로 가지고 값을 치른다. → [룰북: 영석](../game-rule/item.md#영석), [룰북: 결제](../game-rule/item.md#결제)
- **상점 사고팔기:** 관리 툴에서 NPC에 상점 역할(파는 물건·값)을 준다. 게임에서 그 NPC에게 사고판다. → [NPC: 역할](npc.md#역할), [룰북: 상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기), [룰북: 역할별 이용](../game-rule/npc.md#역할별-이용)
- **저물대:** 저물대가 소지품 칸을 정한다. (`귀속`·`귀속 해제` 명령과 `거래 가능` 속성은 삭제됨 — 창호, 2026-11-14. 필요하면 나중에 넣는다.) → [룰북: 저물대 · 저물탁](../game-rule/item.md#저물대--저물탁)
- **주기:** 같은 방 플레이어에게 물건·영석을 바로 넘긴다. → [룰북: 직접 거래](../game-rule/item.md#직접-거래)
- 3차 완료 시나리오(4차부터 새 캐릭터는 범인이라 상점 단계는 입문한 캐릭터로 한다 → [범인의 상점 막힘](command.md#범인의-상점-막힘)): 관리자로 admin-console 로그인 → 아이템 종류 정의 → 방 바닥에 배치 → 시작 소지품 지정 → NPC에 상점 역할(파는 물건·값) 지정 → play-client에서 새 캐릭터로 시작 소지품·영석 확인 → 바닥 물건 줍기·버리기 → 물건 보기 → 상점 NPC에게 사기·팔기(영석 증감) → 저물대 동작 → 같은 방 다른 플레이어에게 주기.
- 3차에 넣지 않는 것: 아이템을 써서 효과 내기(단약 복용 효과·부적·진법원반·법기 장착 등 — 스탯이 아직 없다), 교환 창·거래소·경매장, 제작, 몹 드롭, 공법·경지, 전투, LLM 챗.
- 3차에 걸리는 열린 질문은 [아래](#3차-이터레이션-열린-질문)에 모았다.

### 4차 범위: 경지·스탯 + 임의 경지 상승 + 공법·신통 배우기

창호가 순서를 정했다(2026-11-14): "아이템 하고, 공법 신통 이런거 배우는거 시작하고 임의로 레벨업 (경지 상승) 하는거 하고 그 다음에 전투해야할것 같아". 아래 범위는 고나가 창호 원문을 해석한 것이고, 창호 확인함 (2026-11-15). 세부는 [아래 열린 질문](#4차-이터레이션-열린-질문)에서 `(제안)` 으로 정했다.

- 룰북 규칙·수치는 그대로 따른다. 룰북보다 4차가 줄인 것(서재·`읽기 확인` 없음, 경지 안정 기간 없음, 깨달음·수위가 늘 0, 신통의 단계별 값 없음, 자질 조건은 모든 속성 영근에 같은 값 하나, 여러 속성 필요 깨달음은 똑같이 나눔만, 범인의 청우촌 밖 이동 막힘 없음(튜토리얼과 함께))은 해당 항목에 적었다. 룰북 규칙은 해당 기능이 생길 때 붙인다. (제안)

- **캐릭터 경지·스탯:** 캐릭터가 경지를 가진다. 4차 경지는 범인, 연기 1~13층, 축기 초기~대원만이다(첫 지역 MVP + 축기). 스탯(기혈·법력·의식·정혈·육신·근력·영력)은 룰북 [경지별 스탯 상승](../game-rule/realm.md#경지별-스탯-상승)과 [스탯](../game-rule/stats.md) 표대로 계산하고 `상태`(`ㅅ`)로 본다. → [플랫폼: 4차 월드 상태와 저장](platform.md#4차-월드-상태와-저장), [명령어 처리: 상태](command.md#상태)
- **영근(최소):** 캐릭터 생성에 영근 고르기를 더한다(룰북 생성 절차의 영근 단계). 영근이 없는 기존 캐릭터는 다음 접속 때 한 번 고른다. 영근·자질은 공법 배우기 조건에 쓴다. 성별·외모·출신은 4차에도 없다. → [명령어 처리: 캐릭터 생성 · 영근](command.md#캐릭터-생성--영근-4차), [룰북: 영근 · 영근 자질](../game-rule/stats.md#영근--영근-자질)
- **임의 경지 상승:** 수위·돌파 없이 관리 툴에서 캐릭터 경지를 지정한다(올리기·내리기 모두). 스탯은 바로 새 경지 값이 된다. 게임 안 관리자 명령은 두지 않는다. → [관리 툴: 4차 화면](admin-tool.md#4차-화면)
- **공법·신통 정의:** 관리 툴에서 공법과 그 신통을 정의한다(룰북 [공법이 가지는 것](../game-rule/technique.md#공법이-가지는-것)·[신통이 가지는 것](../game-rule/technique.md#신통이-가지는-것) 가운데 배우기·보기에 쓰는 것). 옥간·서책 아이템 종류에 담긴 공법을 지정한다. → [관리 툴: 4차 데이터](admin-tool.md#4차-데이터)

- **공격 신통 정의 보강:** 관리 툴의 4차 신통 정의에 룰북 [신통이 가지는 것](../game-rule/technique.md#신통이-가지는-것) 가운데 공격 신통에 필요한 남은 것, **단계별 값(기본 위력·신통 계수)** 을 더한다. 종류·속성·대상·소모·시전 시간·재사용 대기시간·쓸 수 있는 때는 4차에 이미 있다. 6차에 게임에서 쓸 수 있는 것은 종류 `공격`, 대상 `한 대상`, 소모 `없음`·`법력`(한 번에)인 신통이다. 다른 종류도 4차처럼 정의는 할 수 있다. → [관리 툴: 6차 데이터](admin-tool.md#6차-데이터)
- **이펙트 문장 (창호):** 신통마다 이펙트 문장을 최소 1개 ~ 최대 5개 입력받고, 신통을 쓸 때 그 가운데 하나를 고르게(무작위) 골라 보인다. 문장에는 자리표시 `{대상}`·`{시전자}` 를 쓸 수 있고 바로 뒤 조사는 받침에 맞춰 바뀐다. 0개·6개는 저장을 거절한다. (자리표시는 제안) → [관리 툴: 이펙트 문장](admin-tool.md#이펙트-문장), [명령어 처리: 신통 교전 메시지](command.md#신통-교전-메시지)
- **신통 쓰기:** 배운 공격 신통을 `<신통> [대상]` 으로 같은 방의 몹에게 쓴다(룰북 [입력 문법](../game-rule/commands.md#입력-문법)·[대상 지정](../game-rule/combat.md#대상-지정): 신통 이름이 곧 명령어, 명령어가 먼저). 교전을 시작할 때도, 교전 중에도 쓴다. 법력을 쓰고, 공통 대기시간(1.5초)·재사용 대기시간·시전 시간을 따른다. 위력은 룰북 [공격력 · 방어력](../game-rule/combat.md#공격력--방어력) 식이다: 오행 신통 = (기본 위력 + 영력 × 계수) × 영근 자질 배율(신통 속성 영근, 영력 발휘 제한 적용), 연체술 신통 = 기본 위력 + 근력 × 계수. 기본 위력·계수는 그 신통이 속한 공법의 지금 단계 값이다. 피해는 5차 교전의 피해 흐름(육신 층 → 기혈)·위협·처치자에 합친다. 법력 부족·대기시간·시전 중·익히지 않음 같은 거절 문구를 둔다. → [명령어 처리: 신통 쓰기](command.md#신통-쓰기)
- **법력 현재 수치·회복:** 5차 기혈처럼 깎인 법력을 저장한다. 룰북에는 법력 자연 회복이 있으므로(영기 농도 '보통' 최대치의 0.5%/초, 전투 중에도) 6차에 그대로 넣는다. 방의 영기 농도 데이터가 아직 없어 모든 방을 '보통' 으로 본다. 기혈 같은 임시 규칙은 두지 않는다. → [명령어 처리: 법력 회복](command.md#법력-회복), [플랫폼: 6차 월드 상태와 저장](platform.md#6차-월드-상태와-저장) (제안)
- **깨달음 쌓기:** 신통을 쓰면 룰북 [깨달음](../game-rule/technique.md#깨달음) 절대로 깨달음이 쌓인다: 법력 소모량(법력을 쓰지 않는 신통은 기준 소모) × 상황 계수를 신통 속성에 나눠 쌓고, 공법 속성 가운데 신통 속성에 없는 것에 그 0.5배(공법 깨달음)를 더한다. 연체술 신통은 연체 깨달음에 쌓인다. 한 상대 상한(그 상대의 기혈 최대치)을 지킨다. 6차의 공격 신통은 늘 교전을 일으키므로 전투 밖 계수·상한이 쓰이는 일은 없다. `상태` 의 깨달음 줄과 `공법` 의 `(지금 …)` 에 보인다(룰북 [정보](../game-rule/commands.md#정보) 형식). `신통` 목록에는 룰북대로 재사용 대기 남은 시간이 붙는다. → [명령어 처리: 깨달음 쌓기](command.md#깨달음-쌓기), [명령어 처리: 6차 정보 명령](command.md#6차-정보-명령)
- 6차 완료 시나리오: 관리 툴에서 공법과 그 공격 신통(이펙트 문장 여러 개, 단계별 값) 정의 → 이펙트 문장 0개·6개 저장 거절 확인(REST·스모크로 확인) → 그 옥간을 둠 → play-client에서 `읽기` 로 익힘 → `신통` 으로 확인 → 몹에게 `화탄술 청모랑` → 교전 시작·이펙트 문장 가운데 하나와 피해 출력 → `상태` 로 법력 감소 확인 → 곧바로 다시 써서 공통 대기 거절(`아직 기운을 고르는 중입니다. (0.3초)` 꼴), 1.5초 뒤 다시 써서 재사용 대기 거절(`화탄술은 아직 쓸 수 없습니다. (1.4초)` 꼴) 확인 → 법력이 모자랄 때까지 써서 법력 부족 거절 확인 → `상태`·`공법` 으로 깨달음이 쌓인 것 확인 → 처치(시체·수습은 5차 그대로) → 시간이 지나 법력이 조금씩 차는 것 확인.
- 6차에 넣지 않는 것: 상성에 따른 피해 증감(나중 (창호) — 룰북 [피해 흐름](../game-rule/combat.md#피해-흐름)의 '받는 쪽 속성 배율' 자리만 두고 6차에는 늘 ×1), 공격 외 신통 쓰기(범위 공격·방어·회피·치료·둔술·탐지·은신·렴기·보조), 무리한 사용(법력 0%에서 영력·기혈이 깎임), 공통 대기시간 끝의 신통 예약, `대상` 명령, 깨달음으로 공법 단계 올리기(`참오`)·수위 쌓기·소경지 상승·돌파, 잔본·산공·서재, 법기 꺼내기·법기 공격, 단약·영석·영약, 명상, 방의 영기 농도 데이터, 도주·막기·추격·정혈 태우기, 정식 사망·부활·사망 페널티, 기절, 선공·배회·무리·몹 대사·몹 신통 여럿, 적대 수선자의 법력, 지속 피해(독), 방어 신통·방어 법기 층, 부적, 안전 장소·PvP, 파티·영수·괴뢰, 퀘스트 처치 수, 권장 경지 표시, LLM 챗.

- 결정이 열어 둔 세부(API 모양, 접속 중 거절 문구, 확인 창 문구, 로그 형식, 지운 뒤 갈 화면, 몹이 사라지는 때)는 해당 절에 `(제안)` 으로 적었다. 룰북은 결정과 부딪치는 문장이 없어 고치지 않았다.

### 방위 초성 약자 (direction-abbrev)

방위 이동을 한글 초성 약자로도 하게 한다(2026-11-20). 구현 계획: [`docs/impl/direction-abbrev/plan.md`](../../impl/direction-abbrev/plan.md), 진행: [progress.md](../../impl/direction-abbrev/progress.md).

| 대상 | 결정 | 출처 | 스펙 |
|---|---|---|---|
| 방위 | 방위 이동을 `ㄷ` `ㅅ` `ㄴ` `ㅂ` `ㅂㅅ` `ㄴㄷ` 처럼 초성 약자로도 한다. `보기` 의 줄임말은 `ㅂ` 대신 `봐`·`보` | 창호 지시 (2026-11-20) | [명령어 처리: 방위 초성 약자](command.md#방위-초성-약자-direction-abbrev) |
| 방위 | 게임에 있는 방위 열 개 전부에 초성 약자(`ㅂㄷ`·`ㄴㅅ`·`ㅇ`·`ㅇㄹ` 포함) | 고나 판단 (2026-11-20, 창호 위임) | 같은 절 |
| 겹침 | 다른 명령 줄임말과 겹치면 방위가 먼저. `ㅅ` 은 `상태` → `서`, `상태` 의 새 줄임말은 `ㅅㅌ` (제안) | 고나 판단 (2026-11-20, 창호 위임) | 같은 절 |

- 다음 일은 `봐 동`(방위 보기)이다. 이번에는 만들지 않고, 보기 인자를 그대로 두며 방위 낱말 풀이를 한곳에 둔다. → [다음 일: `봐 동`](command.md#다음-일-봐-동) **방위 보기에 만들었다** → [방위 보기](#방위-보기-look-direction)
- 룰북 [줄임말](../game-rule/commands.md#줄임말)·[출구](../game-rule/world.md#출구)·[방 보기](../game-rule/world.md#방-보기) 의 `ㅂ`·`ㅅ` 을 결정대로 고쳤다.

### 방위 보기 (look-direction)

`보기`·`봐`·`보` 뒤에 방위를 쓰면 그 방위 너머 방의 이름을 본다(2026-11-20). 구현 계획: [`docs/impl/look-direction/plan.md`](../../impl/look-direction/plan.md), 진행: [progress.md](../../impl/look-direction/progress.md).

| 대상 | 결정 | 출처 | 스펙 |
|---|---|---|---|
| 보기 | `봐 동`·`보기 동`·`보 동` 처럼 방위를 보면 그 방위 방의 짧은 설명(이름)이 `동쪽으로 ○○○가 보인다.` 로 보인다 | 창호 지시 (2026-11-20) | [명령어 처리: 방위 보기](command.md#방위-보기-look-direction) |
| 방위 낱말 | 이름·초성 약자·영문 모두(`봐 ㄷ`, `보 북동`, `보기 e`). 위·아래도 같게(`위로 ○○○가 보인다.`) | 고나 판단 (2026-11-20, 창호 위임) | 같은 절 |
| 보이는 것 | 그 방 이름만. 묘사·몹·NPC·물건은 안 보임. 조사는 받침에 맞춤 | 고나 판단 (2026-11-20, 창호 위임) | 같은 절 |
| 출구 없음 | 이동 실패와 같은 `그쪽으로는 길이 없습니다.` | 고나 판단 (2026-11-20, 창호 위임) | 같은 절 |
| 겹침 | 방위 낱말과 같은 이름의 대상이 방에 있어도 방위가 먼저 | 고나 판단 (2026-11-20, 창호 위임) | 같은 절 |

- 문체(`보인다` 를 살림), 이름 있는 출구·비밀문은 대상 밖, 교전·시전 중에도 됨, `system/info` 그대로, 도움말에 `보기 <방위>` 를 더함은 `(제안)` 으로 같은 절에 적었다. 새 의존성·DB·메시지 모양 변경은 없다.
- 룰북 [이동 · 보기](../game-rule/commands.md#이동--보기) 표와 [방 보기](../game-rule/world.md#방-보기)에 방위 보기를 더했다.

### 시체 보기 (look-corpse)

`보기`·`봐`·`보` 로 시체를 보면 수습할 수 있는 물건이 보인다(2026-11-20). 구현 계획: [`docs/impl/look-corpse/plan.md`](../../impl/look-corpse/plan.md), 진행: [progress.md](../../impl/look-corpse/progress.md).

| 대상 | 결정 | 출처 | 스펙 |
|---|---|---|---|
| 보기 | `봐 시체` 처럼 시체를 보면 그 안의 수습할 수 있는 물건이 보인다 | 창호 지시 (2026-11-20) | [명령어 처리: 시체 보기](command.md#시체-보기-look-corpse) |
| 여러 시체 | 지금 대상 고르기 규칙대로 첫째(쓰러진 순). 둘째부터는 지금 번호 규칙 `봐 2.시체`. 고르는 방식 개선은 다음 일(창호 요청 2번) | 고나 판단 (2026-11-20, 창호 위임) | 같은 절 |
| 권한 | 수습 권한과 상관없이 누구나 본다. 아직 내 몫이 아니면 남은 시간을 함께 보인다 | 고나 판단 (2026-11-20, 창호 위임) | 같은 절 |
| 겹침 | 방위 보기가 먼저(`시체` 는 방위 낱말이 아님) | 고나 판단 (2026-11-20, 창호 위임) | 같은 절 |

- 출력 모양(`청모랑의 시체 — 거둘 것: …` / `… — 거둘 것이 없다.`), 지워진 종류는 안 보임, `system/item`, 시체를 바꾸지 않음, 교전 중에도 됨, 도움말 그대로는 `(제안)` 으로 같은 절에 적었다. 새 의존성·DB·메시지 모양 변경은 없다.
- 룰북 [시체와 수습](../game-rule/npc.md#시체와-수습)과 [이동 · 보기](../game-rule/commands.md#이동--보기) 표에 시체 보기를 더했다.

### 시체 번호 (corpse-numbering)

방에 시체가 둘 이상이면 방 보기 시체 줄에 번호를 붙여 `봐 2.시체`·`수습 2.시체` 로 고를 수 있게 한다(2026-11-20). 구현 계획: [`docs/impl/corpse-numbering/plan.md`](../../impl/corpse-numbering/plan.md), 진행: [progress.md](../../impl/corpse-numbering/progress.md).

| 대상 | 결정 | 출처 | 스펙 |
|---|---|---|---|
| 고르기 | 지금의 `2.이름` 그대로. 뒤 숫자(`봐 시체 2`)·붙여쓰기(`시체2`)는 하지 않는다 | 창호 결정 (2026-11-20) | [명령어 처리: 시체 번호](command.md#시체-번호-corpse-numbering) |
| 표시 | 시체가 여럿이면 묶지 않고 줄마다 번호(1. 2. …), 순서는 `2.이름` 고르기 순서와 같게. 하나면 번호 없음 | 창호 결정 (2026-11-20) | 같은 절 |

- 다른 이름 시체가 섞여도 시체 전체를 함께 셈(`N.시체` 와 맞춤), 줄 모양 `2.청모랑의 시체 (수습 가능)`, 몹·물건 줄은 그대로, 서버가 `corpses[].ordinal` 을 보냄은 `(제안)` 으로 같은 절에 적었다. 메시지 변경 → [플랫폼: 시체 번호 WebSocket 메시지 변경](platform.md#시체-번호-websocket-메시지-변경). 새 의존성·DB 변경은 없다.
- 룰북 [방 보기](../game-rule/world.md#방-보기)·[대상 지정](../game-rule/commands.md#대상-지정)에 시체 번호를 더했다.

### 2차 이터레이션 열린 질문

2차 구현 전에 정해야 하는 것이었다. 창호가 정하지 않아 구현 때 `(제안)` 으로 정했고, 질문마다 답과 적은 곳을 붙였다.

**NPC 데이터와 배치**
- NPC 하나가 가지는 항목은? (이름, 방에서 보이는 한 줄 묘사, 자세히 볼 때 묘사, 호칭 등) 이름은 세계에서 유일한가? → [룰북: 유니크 NPC](../game-rule/npc.md#유니크-npc)
  - → (제안) 2차 NPC는 이름(띄어쓰기 없이 1~12자, NPC끼리 유일, 영문 대소문자 무시)·인사말·낱말 대답·기본 대답·LLM 대화 켬/끔·배치 방만 가진다. 한 줄 묘사·자세히 볼 때 묘사·호칭은 `보기 <대상>` 이 생길 때 더한다. 캐릭터 이름은 NPC 이름과 겹칠 수 없다. → [NPC: 2차 데이터 모델](npc.md#2차-데이터-모델)
- NPC가 있는 방을 지우면 NPC는 어떻게 되는가? (배치만 풀림 / 시작 방으로 / 삭제)
  - → (제안) 배치만 풀린다. NPC는 남고 관리 목록에 `배치 안 됨` 으로 보인다. → [NPC: 2차 데이터 모델](npc.md#2차-데이터-모델)

**대화 명령어와 화면**
- NPC 이름을 줄여 부르거나(앞글자), 같은 방에 비슷한 이름이 둘일 때 어떻게 고르는가?
  - → (제안) 이름 전체가 같은 NPC를 먼저, 없으면 이름이 입력으로 시작하는 NPC 가운데 방 보기 순서(만든 순서) 첫째를 고른다. 영문은 대소문자를 가리지 않는다. 번호(`2.왕씨`)는 2차에 없다. → [명령어 처리: 2차 명령어](command.md#2차-명령어)
- 플레이어가 NPC와 나눈 대화를 같은 방의 다른 플레이어도 보는가?
  - → (제안) 보지 않는다. NPC의 대답은 묻는 플레이어에게만 간다. → [명령어 처리: 2차 명령어](command.md#2차-명령어)
- 방 화면에서 NPC를 플레이어 목록과 어떻게 구분해 보여주는가? NPC를 자세히 보는 명령(`보기 <NPC>`)이 있는가?
  - → (제안) 플레이어 줄 다음에 NPC 줄을 다른 스타일(`npc`)로 그린다. `보기 <NPC>` 는 1차 그대로 `아직 자세히 볼 수 없습니다.` 다. → [플랫폼: 플레이 화면](platform.md#플레이-화면-play-client), [플랫폼: 2차 WebSocket 메시지 변경](platform.md#2차-websocket-메시지-변경)

**LLM 켬/끔 자리**
- 2차에서 LLM 켬 NPC에 말을 걸면 어떻게 되는가? (그냥 정해진 대사로 답함으로 둘지)
  - → (제안) LLM 끔 NPC와 같은 정해진 대사로 답한다. 2차는 LLM을 부르지 않는다. → [NPC: 캐릭터 챗](npc.md#캐릭터-챗)
- LLM용 캐릭터 설정(성격·말투·배경) 입력 칸도 2차에 자리만 두는가, LLM 이터레이션으로 미루는가? → [NPC: 열린 질문](npc.md#열린-질문)
  - → (제안) LLM 이터레이션(순서 미정)으로 미룬다. 2차에는 칸이 없다.

**성·종문 정의와 소유**
- 성·종문이 소유한 지역이 있으면 그 성·종문을 지울 수 없게 하는가?
  - → (제안) 지울 수 없다(409 `소유한 지역이 있는 성·종문은 지울 수 없습니다`). → [월드 구조: 2차 데이터 모델](world-structure.md#2차-데이터-모델)
- NPC에 소속(성·종문)도 2차에 지정하는가?
  - → (제안) 지정하지 않는다. 가입·종문 규칙이 생길 때 더한다. → [NPC: 2차 데이터 모델](npc.md#2차-데이터-모델)

### 3차 이터레이션 열린 질문

3차 구현 전에 정해야 하는 세부였다. 창호가 정하지 않아 구현 때 `(제안)` 으로 정했고, 질문마다 답과 적은 곳을 붙였다. 룰북에 이미 답이 있으면 `→ 룰북:` 으로 적었다. 룰북 규칙·수치는 그대로 따른다.

**아이템 종류**
- 3차의 아이템 종류가 가지는 항목은? (이름·묘사 + 공통 속성 가운데 무엇을 3차에 두는가) 이름은 유일한가? → 룰북: 이름·종류·필요 경지·품질·겹침·기준가·거래 가능·귀속 → [아이템 공통 속성](../game-rule/item.md#아이템-공통-속성)
  - → (제안) 이름(1~20자, 띄어쓰기 허용, 유일·영문 대소문자 무시, 영석 등급 낱말·마지막 낱말이 수나 `전부`·`N.` 시작 금지)·묘사·종류·기준가·거래 가능·저물대 등급(저물대만)을 둔다. 겹침은 종류가 정한다. → [관리 툴: 3차 아이템 데이터](admin-tool.md#3차-아이템-데이터) → 삭제됨 (창호, 2026-11-14): 거래 가능 칸
- 종류(법기·단약·부적 …) 목록을 3차에 모두 고르게 하는가, 일부만 두는가? 쓰는 효과가 없는 3차에서 종류는 무엇을 가르는가? (겹침·매입 비율·귀속 가능 여부) → 룰북: [겹침 규칙](../game-rule/item.md#아이템-공통-속성), [매입 비율](../game-rule/item.md#상점에서-사고팔기), [직접 귀속](../game-rule/item.md#귀속)
  - → (제안) 룰북 종류 15개를 모두 두되 영석은 엔진이 만든다. 3차에 종류가 가르는 것은 겹침·매입 비율·직접 귀속 가능·칸 차지뿐이다. → [관리 툴: 종류 표](admin-tool.md#종류카테고리-표-itemcategory) → 삭제됨 (창호, 2026-11-14): 직접 귀속 가능 구분
- 품질을 3차에 두는가? 둔다면 이름 앞에 붙는 품질과 판매가·매입 배율을 계산하는가? → 룰북: [품질](../game-rule/item.md#품질)
  - → (제안) 두지 않는다. 모두 하계로 본다(배율 ×1). → [관리 툴: 3차 아이템 데이터](admin-tool.md#3차-아이템-데이터)
- 필요 경지는 경지가 없는 3차에 입력만 받는가, 빼는가? → 룰북: 모자라도 가지고 다니고 거래할 수 있다 → [아이템 공통 속성](../game-rule/item.md#아이템-공통-속성)
  - → (제안) 칸도 두지 않는다. 경지가 생길 때 더한다. → [관리 툴: 3차 아이템 데이터](admin-tool.md#3차-아이템-데이터)
- 아이템 종류를 지울 때 바닥·소지품·상점·시작 소지품에 그 물건이 있으면 어떻게 하는가?
  - → (제안) 어디든 쓰이면 지울 수 없고(409) 종류·저물대 등급도 바꿀 수 없다. → [관리 툴: 관리 툴 변경의 반영](admin-tool.md#관리-툴-변경의-반영)
- 같은 종류의 물건이 개체마다 다른 값(귀속 여부, 법기 내구도 등)을 가지는가? 3차에 개체 단위로 저장해야 하는 것은 귀속뿐인가?
  - → (제안) 3차에 개체 단위로 저장하는 것은 귀속 여부뿐이다(귀속된 것과 안 된 것은 다른 묶음). → [관리 툴: 3차 아이템 데이터](admin-tool.md#3차-아이템-데이터), [플랫폼: 3차 월드 상태와 저장](platform.md#3차-월드-상태와-저장) → 삭제됨 (창호, 2026-11-14): 귀속 구분이 없어 같은 종류는 한 묶음
- 관리 툴에서 바꾼 아이템 종류·바닥 배치·시작 소지품·상점 역할이 실행 중인 게임에 바로 반영되는가? → [관리 툴: 관리 툴 변경의 반영](admin-tool.md#관리-툴-변경의-반영)
  - → (제안) 바로 반영된다(게임이 명령마다 DB에서 읽음). 바닥은 다음 방 보기부터, 시작 소지품은 그 뒤 만드는 캐릭터부터, 상점은 다음 상점 명령부터다. → [관리 툴: 관리 툴 변경의 반영](admin-tool.md#관리-툴-변경의-반영)

**영석**
- 3차에 영석 4등급(하품·중품·상품·극품)을 모두 두는가, 하품만 두는가? → 룰북: 4등급, 결제 때 한 등급 위 1개 = 아래 100개, 낮은 등급부터 내고 거스름은 하품 → [영석](../game-rule/item.md#영석), [결제](../game-rule/item.md#결제)
  - → (제안) 4등급을 모두 둔다. → [관리 툴: 영석](admin-tool.md#영석), [명령어 처리: 결제와 `확인`](command.md#결제와-확인)
- 영석은 아이템 종류 데이터인가, 엔진이 아는 고정 물건인가?
  - → (제안) 엔진이 서버 시작 때 심는 아이템 종류 4개다. 소지품 칸을 차지하는 일반 물건이고 관리 툴로 고치거나 지울 수 없다. → [관리 툴: 영석](admin-tool.md#영석)
- 상위 등급 깨기 확인(`확인`)과 거스름 넘침을 3차에 하는가? → 룰북: [결제](../game-rule/item.md#결제)
  - → (제안) 둘 다 한다. 확인은 그 돌을 실제로 깰 때만 묻고(10초), 거스름이 칸에 안 들어가면 결제하지 않는다. → [명령어 처리: 결제와 `확인`](command.md#결제와-확인)

**상점**
- 상점 역할의 데이터는? (파는 물건 목록, 사 주는 종류, 값을 기준가에서 계산할지 상점마다 입력할지) → 룰북: 판매가 = 기준가 × 품질 판매가 배율, 매입가 = 하계 기준가 × 매입 비율 × 품질 매입 배율 → [상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기), [상점 종류](../game-rule/game-structure.md#상점)
  - → (제안) 상점 종류(엔진 enum 7종) + 파는 물건 `[{itemTypeId, price}]`(50개까지). 값은 비우면 기준가에서 계산하고 매입가는 입력받지 않는다(룰북 식). → [NPC: 3차 상점 역할 데이터](npc.md#3차-상점-역할-데이터)
- 상점 재고는 끝없이 있는가, 수가 정해져 있는가? → 룰북: 재고는 무한이고 가격은 바뀌지 않는다. 플레이어가 판 물건은 다시 팔지 않고 사라진다, 매입 수량 한도 없음 → [상점](../game-rule/game-structure.md#상점), [상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기)
  - → (제안) 무한이다(룰북 그대로). → [NPC: 3차 상점 역할 데이터](npc.md#3차-상점-역할-데이터)
- 상점 종류(단약방·법기점 …)를 3차에 데이터로 두는가, 사 주는 종류를 NPC마다 직접 고르는가? → 룰북: [상점](../game-rule/game-structure.md#상점)
  - → (제안) 엔진 enum이다. 사 주는 것은 종류가 정하고 파는 물건도 그 종류의 종류만 둘 수 있다. → [NPC: 3차 상점 역할 데이터](npc.md#3차-상점-역할-데이터)
- `값 <물건>` 을 3차에 넣는가? → 룰북: [역할별 이용](../game-rule/npc.md#역할별-이용)
  - → (제안) 넣는다. → [명령어 처리: 상점 명령](command.md#상점-명령)
- 상점 불변식(매입가 < 판매가 × 0.5)을 관리 툴이 검사하는가? → 룰북: [상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기)
  - → (제안) 검사한다(상점 저장 때 400, 기준가를 바꿀 때 409). 제작물 불변식은 제작이 없어 검사하지 않는다. → [NPC: 3차 상점 역할 데이터](npc.md#3차-상점-역할-데이터)

**소지품 · 저물대 · 귀속**
- 소지품 한도는? → 룰북: 무게 없음, 칸 수로만. 기본 2칸 + 저물대·저물탁 칸 합. 저물대 3개·저물탁 1개까지, 저물대 하급 20 · 중급 40 · 상급 80칸 → [저물대 · 저물탁](../game-rule/item.md#저물대--저물탁)
  - → (제안) 칸 = 기본 2칸 + 가진 저물대 칸의 합, `(종류, 귀속)` 묶음마다 `올림(수 ÷ 겹침)` 칸이다. → [플랫폼: 3차 월드 상태와 저장](platform.md#3차-월드-상태와-저장) → 삭제됨 (창호, 2026-11-14): 묶음은 `(종류)` 마다 하나
- 저물대 크기는 아이템 종류의 속성인가? 저물탁(필요 경지 축기 초기)을 경지가 없는 3차에 어떻게 다루는가?
  - → (제안) 저물대 등급(하급 20·중급 40·상급 80칸)이 아이템 종류의 속성이다. 저물탁은 3차에 없다(경지·의식이 없음, 4차에 더함). → [관리 툴: 3차 아이템 데이터](admin-tool.md#3차-아이템-데이터)
- 귀속 시점은? 3차에 생기는 귀속 경우는 무엇인가? (처음부터 귀속된 물건을 관리 툴에서 정하는가, `귀속` 명령만인가) → 룰북: 퀘스트 물건·본명법보·퀘스트 보상·직접 귀속 → [귀속](../game-rule/item.md#귀속)
  - → (제안) `귀속` 명령뿐이다(직접 귀속 종류만). 처음부터 귀속된 물건은 만들지 않는다. → [명령어 처리: 귀속](command.md#귀속) → 삭제됨 (창호, 2026-11-14)
- 직접 귀속은 정혈 최대치의 10% 를 쓰는데 3차에는 정혈 스탯이 없다. 3차의 `귀속` 은 무엇을 소모하는가? → 룰북: [귀속](../game-rule/item.md#귀속)
  - → (제안) 아무것도 소모하지 않는다. 정혈 소모는 스탯이 생기는 이터레이션에서 붙인다. → [명령어 처리: 귀속](command.md#귀속) → 삭제됨 (창호, 2026-11-14)
- 시작 소지품의 영수대는 영수가 없는 3차에 어떻게 하는가? → 룰북: [시작 소지품](../game-rule/item.md#시작-소지품)
  - → (제안) 넣지 않는다. 영수가 생길 때 더한다. → [관리 툴: 시작 소지품](admin-tool.md#시작-소지품-worldsettingsstartingitems)

**바닥 물건**
- 관리 툴로 배치한 바닥 물건은 주우면 다시 나타나는가(얼마 뒤), 한 번뿐인가? 캐릭터마다인가, 모두 한 번인가? → 룰북: 플레이어가 버린 물건만 정했다(5분 남고 사라짐) → [줍기와 버리기](../game-rule/item.md#줍기와-버리기)
  - → (제안) 모두가 함께 쓰는 하나이고, 비운 뒤 재등장 분(1~1,440, 기본 10분)이 지나면 처음 수로 다시 놓인다. 재등장 없음이면 한 번뿐이다. → [월드 구조: 3차 데이터 모델](world-structure.md#3차-데이터-모델)
- 버린 물건이 5분 뒤 사라지려면 시간을 재는 무언가(서버 틱·예약 작업)가 필요하다. 3차에 무엇으로 하는가? → [플랫폼: 3차 월드 상태](platform.md#3차-월드-상태와-저장)
  - → (제안) 틱·예약 작업 없이 바닥을 읽을 때(방 보기·줍기·보기) 시각을 비교해 지운다. → [플랫폼: 3차 월드 상태와 저장](platform.md#3차-월드-상태와-저장), [월드 구조: 3차 데이터 모델](world-structure.md#3차-데이터-모델)
- 서버를 다시 시작하면 바닥 물건은 남는가?
  - → (제안) 남는다(둘 다 DB). → [월드 구조: 3차 데이터 모델](world-structure.md#3차-데이터-모델)
- 바닥 물건을 방 보기에 어떻게 보이는가? 같은 물건은 묶는가? → 룰북: 대상 목록의 맨 끝, `하품 영석 3개` → [방 보기](../game-rule/world.md#방-보기)
  - → (제안) 대상 목록 맨 끝에 같은 종류를 한 줄로 묶어 `하품 영석 3개`(1개면 이름만)로 보인다. → [월드 구조: 3차 데이터 모델](world-structure.md#3차-데이터-모델)

**명령 · 화면**

  - → (제안) 방의 대상(플레이어 → NPC → 바닥 물건)을 먼저 보고, 없으면 내 소지품에서 찾는다. → [명령어 처리: 줍기·버리기·소지품·물건 보기](command.md#줍기버리기소지품물건-보기)
- 물건 이름 찾기(앞부분·낱말 앞부분 일치, 번호 `2.가죽`, 수량 `전부`)를 3차에 어디까지 하는가? → 룰북: [입력 문법](../game-rule/commands.md#입력-문법), [대상 지정](../game-rule/commands.md#대상-지정)
  - → (제안) 전체·앞부분·낱말 앞부분 일치, 번호 `2.가죽`, `전부` 모두 한다(전체 일치 우선). → [명령어 처리: 물건 이름 찾기와 수량](command.md#물건-이름-찾기와-수량)
- `주기` 를 받는 쪽이 접속하지 않았거나 같은 방에 없으면? → 룰북: `여기에 한립은 없습니다.` → [직접 거래](../game-rule/item.md#직접-거래)
  - → (제안) 룰북 문구 `여기에 한립은 없습니다.` 를 그대로 쓴다. → [명령어 처리: 주기](command.md#주기)
- 물건이 오가면 같은 방 다른 사람에게 알리는가? (줍기·버리기·주기)
  - → (제안) 줍기·버리기·주기는 알린다(`notice` tone `item`). 상점 거래·보기는 알리지 않는다. → [명령어 처리: 3차 같은 방 알림](command.md#3차-같은-방-알림)

### 4차 이터레이션 열린 질문

4차 구현 전에 정해야 하는 세부다. 창호가 정하지 않아 고나 쪽에서 `(제안)` 으로 정했고, 질문마다 답과 적은 곳을 붙였다. 룰북에 이미 답이 있으면 `→ 룰북:` 으로 적었다. 룰북 규칙·수치는 그대로 따른다.

**경지와 스탯의 데이터**
- 4차에 어느 경지까지 두는가? → 룰북: 대경지 13개, 연기 1~13층, 축기부터 초기·중기·후기·대원만 → [경지](../game-rule/realm.md#경지)
  - → (제안) 범인, 연기 1~13층, 축기 초기~대원만(18단계)만 둔다. 결단 이후는 콘텐츠·수치가 생길 때 더한다. → [플랫폼: 4차 월드 상태와 저장](platform.md#4차-월드-상태와-저장)
- 스탯은 저장하는가, 계산하는가? 현재 수치와 최대치는?
  - → (제안) 저장하는 것은 경지, 영근(오행과 처음 자질), 익힌 공법(공법과 단계)뿐이다. 최대치와 포인트 스탯(육신·근력·영력·의식·정혈·기혈·법력·영근 자질)은 명령마다 경지 몫 + 익힌 공법 단계 몫으로 계산한다. 4차에는 현재 수치를 깎는 것(전투·소모·사망)이 없어 현재 수치는 늘 최대치이므로 저장하지 않는다. 현재 수치 저장은 깎는 것이 생기는 5차에 더한다. → [플랫폼: 4차 월드 상태와 저장](platform.md#4차-월드-상태와-저장)
- 경지 몫 스탯 수치는? → 룰북: [경지별 스탯 상승](../game-rule/realm.md#경지별-스탯-상승), [육신](../game-rule/stats.md#육신)·[근력](../game-rule/stats.md#근력)·[영력](../game-rule/stats.md#영력-진원)·[의식](../game-rule/stats.md#의식)·[정혈](../game-rule/stats.md#정혈) 표
  - → (제안) 룰북 규칙을 식으로 옮긴 표를 엔진 상수로 둔다(축기 소경지는 초기 몫 × (1 + k/6) 을 반올림 — 룰북 표 값과 맞는 쪽). → [플랫폼: 경지 몫 스탯 표](platform.md#경지-몫-스탯-표)
- 기존 캐릭터와 새 캐릭터의 처음 경지는? → 룰북: 새 캐릭터는 범인으로 시작하고 입문 공법 1성에 이르면 연기 1층 → [입문](../game-rule/character.md#입문)
  - → (제안) 새 캐릭터는 룰북대로 범인이다. 4차 전에 만든 캐릭터는 연기 1층으로 한다(서버가 뜰 때 경지가 빈 행을 채움). 기존 캐릭터는 공법 없이 연기 1층이 되는 셈이지만 3차까지 상점을 쓰던 캐릭터가 범인 막힘에 걸리지 않게 하려는 것이다. → [플랫폼: 4차 월드 상태와 저장](platform.md#4차-월드-상태와-저장)
- 경지가 바뀌면 현재 수치는? → 룰북: 오르면 오른 만큼 현재 수치도 오르고(영력은 안정 기간 동안 차오름), 내려가면 새 최대치까지 깎임 → [최대치가 바뀔 때](../game-rule/stats.md#최대치가-바뀔-때)
  - → (제안) 4차 현재 수치는 늘 최대치라 룰북 규칙과 어긋나지 않는다. **관리 툴 경지 지정은 경지 안정 기간 없이 영력도 바로 찬다.** 룰북의 안정 기간은 수위로 경지가 오를 때의 규칙이고, 관리자 지정은 룰북 경지 상승이 아니라 시험용 도구이기 때문이다(입문의 '안정 기간 없이 바로' 와 같게 다룬다). 안정 기간은 정식 소경지 상승·돌파와 함께 붙인다.

**영근 (최소)**
- 무엇을 저장하고 언제 정하는가? → 룰북: 생성 때 오행 1~5개를 고르고 자질 총량 100을 균등하게 나눔, 확인한 뒤 바꿀 수 없음 → [영근 · 영근 자질](../game-rule/stats.md#영근--영근-자질), [생성 절차](../game-rule/character.md#생성-절차)
  - → (제안) 오행마다 처음 자질(소수, 100 ÷ 개수)을 저장한다. 생성 절차는 이름 → 영근 → 확인이다(성별·외모·출신은 아직 없음). 문구는 룰북 예를 그대로 쓴다. → [명령어 처리: 캐릭터 생성 · 영근](command.md#캐릭터-생성--영근-4차)
- 영근이 없는 기존 캐릭터는?
  - → (제안) 다음 접속 때 세계에 들어가기 전에 한 번 고른다(같은 영근 prompt·확인). 관리 툴로 정하거나 바꾸지 않는다(룰북: 확인 뒤 바꿀 수 없음). → [명령어 처리: 캐릭터 생성 · 영근](command.md#캐릭터-생성--영근-4차)
- 영근이 4차 스탯·배우기에 영향을 주는가? → 룰북: 공법 속성 영근이 있어야 하고 1성 자질 조건을 맞춰야 익힘. 연체술은 조건 없음 → [공법](../game-rule/technique.md#공법)
  - → (제안) 배우기 조건에만 쓴다. 영근 자질은 `상태` 에 보이고 공법 단계의 영근 자질 증가가 더해진다. 위력·돌파 성공률은 4차에 없다.

**공법·신통 정의**
- 공법이 가지는 항목은? → 룰북: [공법이 가지는 것](../game-rule/technique.md#공법이-가지는-것)
  - → (제안) 이름·묘사·속성(0~5, 없으면 연체술)·시작 경지·단계 수(1~12)·단계 표(단계마다 필요 깨달음 합, 영근 자질 조건, 법력·의식·영력·정혈·육신·근력·영근 자질 증가)·신통을 둔다. 계열은 속성으로 정해진다(룰북). 수위(주는지·계수·마지막 경지)·잔본·충돌·얻는 곳은 `참오`·잔본·산공이 생길 때 더한다. 여러 속성의 필요 깨달음은 룰북 기본(속성 수로 똑같이 나눔)만, 자질 조건은 모든 속성 영근에 같은 값 하나만 둔다. → [관리 툴: 4차 데이터](admin-tool.md#4차-데이터)
- 신통이 가지는 항목은? 신통은 공법에 딸리는가, 따로 있는가? → 룰북: [신통이 가지는 것](../game-rule/technique.md#신통이-가지는-것). 같은 이름 신통이 공법마다 속성이 다름(경신술) → [오행 입문 공법](../game-rule/technique-list.md#오행-입문-공법)
  - → (제안) 신통은 한 공법에 딸리고 배우는 단계를 가진다. 이름(공법 안에서 유일, 명령어와 같으면 안 됨)·종류·속성·대상·소모(스탯·양·한 번에/틱마다)·시전 시간·재사용 대기시간·쓸 수 있는 때를 둔다. 단계별 값(위력·계수 등)은 신통 쓰기·전투가 생길 때 더한다. 1성에 신통이 하나 이상 있어야 하고(룰북), 연체술 공법의 신통은 법력을 소모하지 않는다(룰북). → [관리 툴: 4차 데이터](admin-tool.md#4차-데이터)
- 옥간·서책 아이템은 공법과 어떻게 이어지는가?
  - → (제안) 종류가 옥간·서책(`SCROLL`)인 아이템 종류에 `담긴 공법`(공법 하나 또는 없음)을 둔다. 한 공법을 여러 아이템(옥간·서책)에 담을 수 있다. 다른 종류에는 둘 수 없다. 제작법은 제작이 생길 때 더한다. → [관리 툴: 옥간·서책의 담긴 공법](admin-tool.md#옥간서책의-담긴-공법)
- 공법을 지우거나 고칠 때는?
  - → (제안) 누군가 익혔거나 아이템에 담겨 있으면 지울 수 없다(409). 고치는 것은 막지 않고 바로 반영된다(배운 신통·스탯은 계산이라 바뀐 정의를 따름). 단계 수를 익힌 캐릭터의 단계보다 줄이는 것만 막는다(409). → [관리 툴: 4차 데이터](admin-tool.md#4차-데이터)

**읽기와 배우는 조건**
- 명령 이름과 흐름은? 읽으면 물건이 사라지는가? → 룰북: `읽기 <옥간·서책·잔엽>`, 읽으면 사라지고 1성에 이름, 범인이 입문 공법 1성이면 연기 1층 → [공법](../game-rule/technique.md#공법), [성장](../game-rule/commands.md#성장), [튜토리얼](../game-rule/character.md#튜토리얼)
  - → (제안) 룰북 그대로다. 성공하면 그 물건 1개가 사라진다. 문구는 룰북 예를 쓴다. → [명령어 처리: 읽기](command.md#읽기)
- 조건이 맞지 않으면? → 룰북: 알려 주고 '읽기 확인' 으로 서재에 남길지 묻는다 → [서재](../game-rule/technique.md#서재)
  - → (제안) **4차에는 서재가 없어 거절만 하고 물건은 남는다.** 문구는 룰북 앞부분(`지금은 이 공법을 익힐 수 없습니다. (연기 7층 필요)`)만 쓰고 `읽기 확인` 안내는 뺀다. 서재가 생기면 룰북대로 붙인다. → [명령어 처리: 읽기](command.md#읽기)
- 조건 검사 순서는? → 룰북: `참오` 의 순서(익혔는가 → … → 시작 경지 → 자질) → [공법 단계 올리기](../game-rule/technique.md#공법-단계-올리기)
  - → (제안) 인자 → 소지품에 있음 → 옥간·서책 → 담긴 공법 → 이미 익힘 → 시작 경지 → 속성 영근(오행 순) → 1성 자질 조건(오행 순). 처음 걸린 것만 알린다. → [명령어 처리: 읽기](command.md#읽기)
- 이미 익힌 공법의 옥간을 또 읽으면? → 룰북: 이미 서재에 있는 잔엽은 읽을 수 없고 사라지지 않음 `이미 깨친 내용입니다. (청원검결 3/9장)` → [잔본 규칙](../game-rule/technique.md#잔본-규칙)
  - → (제안) 같게 다룬다: `이미 깨친 내용입니다. (장춘공 1/9성)`, 물건은 남는다.
- 익힐 수 있는 공법 수 제한은? → 룰북: 제한 없음 → [공법](../game-rule/technique.md#공법)
  - → (제안) 두지 않는다.

**명령 · 화면**
- `상태`·`공법`·`신통` 출력은? → 룰북: [정보 명령 출력 형식](../game-rule/commands.md#정보)
  - → (제안) 룰북 형식에서 4차에 값이 있는 줄만 쓴다(성별·영기·지속 효과·전투 줄·대기 남은 시간·법기·서재 줄 없음). 깨달음·수위 줄은 늘 0이지만 룰북 형식대로 보인다. 칸 맞춤 공백은 3차 `목록` 처럼 하지 않는다. → [명령어 처리: 상태](command.md#상태), [공법 · 신통](command.md#공법--신통)
- 범인의 막힘을 4차에 하는가? → 룰북: 범인은 청우촌 밖 이동·`명상`·법기 `꺼내기`·상점(`목록`·`사기`·`팔기`)이 막힘 → [상태별로 쓸 수 없는 명령](../game-rule/commands.md#상태별로-쓸-수-없는-명령)
  - → (제안) 상점 막힘만 한다(`아직 범인의 몸이라 할 수 없습니다.`). 청우촌 밖 막힘은 튜토리얼 NPC 대사로 막는 콘텐츠라 튜토리얼과 함께, `명상`·`꺼내기` 는 명령이 생길 때 붙인다. → [명령어 처리: 범인의 상점 막힘](command.md#범인의-상점-막힘)
- 게임 안 관리자 명령(경지 지정)을 두는가?
  - → (제안) 두지 않는다. 관리 툴로 충분하고, 게임 명령에 권한 검사를 새로 넣지 않는다. → [관리 툴: 4차 화면](admin-tool.md#4차-화면)
- 관리 툴 경지 지정은 실행 중인 게임에 어떻게 반영되는가? 알리는가?
  - → (제안) 바로 반영된다(경지는 명령마다 DB에서 읽음). 커밋 뒤 접속 중인 그 캐릭터에게만 `경지가 연기 7층으로 바뀌었습니다. (육신 +6, …)` 를 보낸다. 같은 방 알림은 없다. → [플랫폼: 4차 월드 상태와 저장](platform.md#4차-월드-상태와-저장), [명령어 처리: 경지가 바뀔 때](command.md#경지가-바뀔-때)
- play-client에 상태 창(늘 보이는 패널)을 두는가?
  - → (제안) 두지 않는다. `상태` 는 로그에 그린다. 패널을 나중에 붙일 수 있게 `status` 메시지는 구조를 가진다. → [플랫폼: 4차 WebSocket 메시지 변경](platform.md#4차-websocket-메시지-변경)
- 같은 방 알림은? → 룰북: 소경지 상승 때 `○○의 기운이 한층 짙어진다.` → [소경지 상승](../game-rule/realm.md#소경지-상승)
  - → (제안) 4차에는 없다. 읽기·관리자 경지 지정은 룰북 소경지 상승이 아니다. 정식 소경지 상승이 생길 때 붙인다.

**3차에서 미룬 것**
- 저물탁 → 룰북: 1개까지, 하급 100·중급 200·상급 400칸, 필요 경지 축기 초기 → [저물대 · 저물탁](../game-rule/item.md#저물대--저물탁)
  - → (제안) 4차에 넣는다. 축기 초기 아래에서는 가지고 다니고 거래할 수 있지만 칸이 0이다(룰북 필요 경지: 모자라도 가지고 다님). '의식으로 여닫음' 은 의식 소모가 없는 설명으로 본다. → [관리 툴: 저물탁](admin-tool.md#저물탁), [플랫폼: 4차 월드 상태와 저장](platform.md#4차-월드-상태와-저장)
- 영수대 → (제안) 계속 미룬다. 영수 시스템이 없다.
- 아이템 필요 경지 칸 → (제안) 계속 미룬다. 4차에 아이템을 쓰는 것은 `읽기`(조건은 공법의 시작 경지)와 저물탁(룰북이 축기 초기로 정함)뿐이라 쓰는 곳이 없다. 단약·부적·법기 쓰기가 생길 때 더한다.
- 품질 → (제안) 계속 미룬다. 품질 있는 물건을 얻는 길(제작·드롭)이 없다.
- 2차에서 미룬 경지 조건 낱말(NPC 대화) → (제안) 계속 미룬다. 단서·종문·퀘스트 조건과 한 틀로 만들 것이라 퀘스트 이터레이션에서 한다.
- 방 보기 지역 줄의 권장 경지(`◇ 지역 (권장: …)`) → (제안) 계속 미룬다. 권장 경지는 몹 세기와 함께 정하는 것이라 5차(몹)에서 붙인다. → 5차에도 미룬다(5차 열린 질문).

### 5차 이터레이션 열린 질문

5차 구현 전에 정해야 하는 세부다. 창호가 정하지 않아 고나 쪽에서 `(제안)` 으로 정했고, 질문마다 답과 적은 곳을 붙였다. 룰북에 이미 답이 있으면 `→ 룰북:` 으로 적었다. 룰북 규칙·수치는 그대로 따른다.

**몹 데이터**
- 몹 유형이 가지는 것은? → 룰북: 이름·묘사·종류·급 또는 경지(기준 경지)·체급·스탯(식)·신통·선공·무리·둔술·추격·위치·재등장 시간·드롭 표·대사 → [몹이 가지는 것](../game-rule/npc.md#몹이-가지는-것)
  - → (제안) 이름·묘사·종류·기준 경지·체급·공격 이름(3초마다 쓰는 신통 하나)·두목 공격 계수·재등장(비우면 체급 기준)·드롭 표만 둔다. 스탯은 입력받지 않고 식으로 계산한다. 선공·무리·둔술·추격·배회 구역·대사·신통 여럿은 그 규칙이 생길 때 더한다. → [관리 툴: 몹 `MobType`](admin-tool.md#몹-mobtype)
- 종류는 무엇을 두는가? → 룰북: 요수·적대 수선자·귀물·음혼·괴뢰·마을주민 → [몹](../game-rule/npc.md#몹)
  - → (제안) 요수·적대 수선자·귀물·음혼(하나로)·괴뢰를 둔다. 마을주민은 공격할 수 없는 보호 NPC라 2차 NPC로 만든다. 5차에 종류가 가르는 것은 육신 보정(요수 ×1.2, 귀물·음혼 ×0.5, 괴뢰 ×1.5)과 괴뢰 기혈 ×0.8, 방 보기의 급/경지 표시뿐이다(룰북 [몹 스탯](../game-rule/npc.md#몹-스탯)). 귀물의 화 속성 약점·연체 ×0.5, 적대 수선자의 법력·도주는 신통이 생길 때 붙인다. → [관리 툴: 몹 `MobType`](admin-tool.md#몹-mobtype)
- 기준 경지와 급은? → 룰북: 요수는 급(1급 연기 1~7층, 2급 연기 8~13층, 3급 축기), 나머지는 경지 → [영수 등급과 경지](../game-rule/companion.md#영수)
  - → (제안) 모든 종류에 기준 경지(연기 1층 ~ 축기 대원만, 4차 경지 범위)를 입력받고, 요수의 급은 기준 경지에서 룰북 표로 정한다. 범인은 몹 기준 경지로 받지 않는다(마을주민 몫). → [관리 툴: 몹 `MobType`](admin-tool.md#몹-mobtype)
- 몹 신통은? → 룰북: 신통마다 속성·위력·재사용 대기, 공격 위력은 3초마다 한 번 쓰는 신통 하나 기준 → [몹 스탯](../game-rule/npc.md#몹-스탯)
  - → (제안) 몹마다 공격 하나(이름만 입력, 속성 없음, 위력은 식, 3초마다)만 둔다. 6초마다 2배 같은 나눔·여러 신통은 신통이 생길 때. → [관리 툴: 몹 `MobType`](admin-tool.md#몹-mobtype)
- 같은 이름 몹이 여럿일 때 이름은? → 룰북: 같은 몹은 한 줄로 묶고 `2.늑대` 처럼 번호로 가리킨다 → [대상 지정](../game-rule/commands.md#대상-지정)
  - → (제안) 몹 유형 이름은 몹끼리 유일(대소문자 무시)이고 띄어쓰기를 허용한다(`적안 독사`). 방의 몹은 배치 순서로 번호가 붙는다. → [명령어 처리: 공격](command.md#공격)

**공격과 교전**
- 공격 명령은? → 룰북: 기본 공격은 없고 신통·법기 고유 신통 이름이 명령이다. 틱마다 자동으로 진행되는 공격은 없다 → [진행 방식](../game-rule/combat.md#진행-방식). 그런데 창호가 5차에 공격 명령과 틱 단위 자동 교전을 정했고 신통 쓰기는 5차가 아니다.
  - → (제안) 5차 임시 명령 `공격 <몹>` 을 둔다. 교전을 시작하고 그 뒤 교전이 이어지는 동안 플레이어도 몹처럼 3초마다 자동으로 친다(룰북 몹 공격 위력·비검 재사용 대기 3초 기준). 신통·법기 쓰기가 생기면 `공격` 을 어떻게 할지(없앨지, 법기 기본 공격으로 남길지) 그때 정한다. 창호 확인이 필요하다. → [명령어 처리: 공격](command.md#공격)
- 임시 공격의 위력은? → 룰북: 오행 신통 위력 = (기본 위력 + 영력 × 계수) × 영근 자질 배율, 몹 공격 위력 기준 P = 3 + 1.8 × 영력(화탄술 1성·화영근 자질 50) → [공격력 · 방어력](../game-rule/combat.md#공격력--방어력), [몹 스탯](../game-rule/npc.md#몹-스탯)
  - → (제안) 플레이어 임시 공격 위력 = 3 + 1.8 × 영력 최대치(4차 계산, 공법 몫 포함). 몹 처치 시간 목표(같은 경지, 화탄술 기준)와 맞는 값이다. 법력을 쓰지 않고 영근 자질 배율·속성이 없다. 범인은 영력 0이라 위력 3이다. → [명령어 처리: 공격](command.md#공격)
- 틱과 행동 간격은? → 룰북: 틱 1초. 명령은 즉시 처리. 몹은 교전 1.5초 뒤 첫 행동, 그 뒤 공통 대기·재사용 대기를 따름, 몹 공격은 3초마다 → [처리 순서](../game-rule/combat.md#처리-순서), [몹과 파티원의 행동](../game-rule/combat.md#몹과-파티원의-행동)
  - → (제안) 서버 틱은 1초다. `공격` 은 즉시 한 번 치고(앞 공격에서 3초가 지났을 때), 그 뒤 3초마다 친다. 몹은 교전 1.5초 뒤 첫 공격, 그 뒤 3초마다다. 틱마다 때가 된 행동을 때가 이른 순서로 하나씩 처리하고, 한 행동의 결과를 다 반영한 뒤 다음 행동을 한다(룰북). 쓰러진 쪽의 남은 행동은 취소된다. → [플랫폼: 서버 틱](platform.md#서버-틱)
- 명중·피해는? → 룰북: 늘 명중, 피해 흐름 방어 신통 → 방어 법기 → 육신(위력 − 육신 × 0.5, 최소 0) → 기혈 → [피해 흐름](../game-rule/combat.md#피해-흐름)
  - → (제안) 룰북 그대로이고 5차에는 육신 층만 있다(방어 신통·방어 법기 없음). 표시 수는 룰북 [소수점](../game-rule/stats.md#소수점) 규칙. → [명령어 처리: 교전 메시지](command.md#교전-메시지)
- 몹이 누구를 치는가, 처치자는? → 룰북: 위협이 가장 높은 상대(처음 교전한 상대 1에서 시작, 바꾸려면 1.1배), 처치자는 가장 많은 피해(층 전 위력)를 준 플레이어 → [몹과 파티원의 행동](../game-rule/combat.md#몹과-파티원의-행동), [처치 보상 귀속](../game-rule/npc.md#처치-보상-귀속)
  - → (제안) 룰북 그대로다(치료가 없어 위협은 준 피해뿐). 같은 방의 다른 몹은 끼어들지 않는다(룰북, 무리 없음).
- 교전 중에 막히는 명령은? → 룰북: 이동(도주로만), `종료`, `줍기`·`수습`, NPC 역할 명령, `읽기`, `주기`, `대화` 등 → [상태별로 쓸 수 없는 명령](../game-rule/commands.md#상태별로-쓸-수-없는-명령)
  - → (제안) 룰북 표에서 5차에 있는 명령만 막는다. 도주가 없어 교전은 한쪽이 쓰러질 때까지 이어진다. 그래서 이동 거절 문구는 룰북 앞부분(`싸우는 중에는 움직일 수 없습니다.`)만, `종료` 거절도 룰북 앞부분(`싸우는 중에는 떠날 수 없습니다.`)만 쓴다(30초 남는 몸이 없음). 창호 확인이 필요하다(도주 없이 강한 몹과 붙으면 반드시 진다). → [명령어 처리: 공격](command.md#공격)
- 교전 중에 연결이 끊기면? → 룰북: 몸이 30초 남음 → [접속 종료](../game-rule/combat.md#접속-종료)
  - → (제안) 5차에는 바로 세계에서 사라지고 교전도 끝난다(몹은 상대가 없어지면 10초 뒤 다 참). 30초 규칙은 정식 사망·도주와 함께 붙인다. → [플랫폼: 5차 월드 상태와 저장](platform.md#5차-월드-상태와-저장)

**처치·보상·재등장**
- 드롭은 바닥인가, 바로 획득인가? → 룰북: 시체가 남고 `수습` 으로 저물대에 들어옴, 처음 60초 처치자만, 3분 뒤 사라짐, 굴림은 쓰러질 때 정함, 못 넣은 것은 시체에 남음 → [시체와 수습](../game-rule/npc.md#시체와-수습)
  - → (제안) 룰북 그대로 시체와 `수습` 을 둔다. 시체는 메모리에만 있다(서버를 다시 시작하면 사라짐). → [명령어 처리: 수습](command.md#수습)
- 드롭 표는? → 룰북: 고정 재료(매번), 영석 30%(고정 재료 매입가 합 × 1~2, 버림, 0이면 1), 계층 드롭(고급 8% · 희귀 0.5% · 진귀 0.04%에 보상 배율, 100% 넘으면 확정 + 나머지 확률) → [드롭 표](../game-rule/npc.md#드롭-표)
  - → (제안) 룰북 그대로 계산한다. 관리자는 고정 재료(물건·수)와 계층마다 물건 목록만 넣고, 영석은 엔진이 하품 영석으로 정한다. 고정 재료 값이 기준값(I × 보상 배율 ÷ 60)에 맞는지는 콘텐츠를 만드는 사람이 지키고 관리 툴은 검사하지 않는다. → [관리 툴: 드롭 표](admin-tool.md#드롭-표)
- 재등장은? → 룰북: 체급 기준, 쓰러진 순간부터 셈, 같은 방, 플레이어가 있어도 나타남, 나타날 때 글이 보임 → [재등장](../game-rule/npc.md#재등장)
  - → (제안) 룰북 그대로다. 나타날 때 글은 몹마다 입력하지 않고 `청모랑이 나타난다.` 로 하나다(룰북 예 `수풀을 헤치고 …` 는 콘텐츠 문구). → [명령어 처리: 교전 메시지](command.md#교전-메시지)
- 몹이 다시 차는 때는? → 룰북: 교전 상대가 모두 사라지고 10초 뒤 소모 스탯이 다 참, 피해 기록도 지움 → [몹 스탯](../game-rule/npc.md#몹-스탯)
  - → (제안) 룰북 그대로다.
- 관리 툴로 몹·배치를 바꾸면 게임에 언제 반영되는가?
  - → (제안) 배치는 다음 틱에 반영된다(틱이 배치를 읽어 맞춘다). 바뀌거나 지운 배치의 살아 있는 몹은 사라지고(교전도 끝남) 새 배치대로 나타난다. 몹 정의를 고치면 살아 있는 몹은 그대로이고 다음에 나타날 때부터 새 값이다. → [관리 툴: 관리 툴 변경의 반영](admin-tool.md#관리-툴-변경의-반영)

**질 때와 회복**
- 플레이어 기혈이 0이 되면? → 룰북: 사망 — 페널티(수위·영력·소지품), 5초 뒤 부활 장소(본명패, 없으면 처음 시작한 곳), 부활 직후 소모 스탯 일부, 보호 60초 → [사망](../game-rule/death.md). 정식 사망은 5차가 아니다(창호).
  - → (제안) 최소 처리: 그 순간 모든 교전이 끝나고, 페널티 없이 바로 시작 방으로 옮겨져 기혈 1로 깨어난다. 첫 줄은 룰북 문구 `기혈이 다했습니다. 눈앞이 캄캄해진다…` 를 쓴다. → [명령어 처리: 질 때](command.md#질-때-5차-최소)
- 깎인 기혈은 어떻게 차는가? → 룰북: 기혈 자연 회복은 없고 명상·단약·치료 신통으로만 찬다 → [기혈](../game-rule/stats.md#기혈). 명상·단약은 5차가 아니다.
  - → (제안) 5차 임시 규칙: 플레이어도 몹과 같이 교전 상대가 모두 사라지고 10초가 지나면 기혈이 다 찬다(10초 안에 다시 교전하면 채우지 않음). 접속할 때 기혈이 깎여 있으면 들어온 뒤 10초에 찬다. 명상·단약이 생기면 이 규칙을 지운다. 창호 확인이 필요하다. → [명령어 처리: 교전 뒤 기혈](command.md#교전-뒤-기혈)

**화면**
- 방 보기·`보기 <몹>`·`상태` 에 몹과 교전은 어떻게 보이는가? → 룰북: 대상 목록 플레이어 → NPC → 몹 → 시체 → 물건, `청모랑 (1급) ×3`, `[강적]`, `(전투 중)`, `청모랑의 시체 (수습 가능)`, 기혈 상태 4구간, `[전투 중] 상대: …` → [방 보기](../game-rule/world.md#방-보기), [전투 상태](../game-rule/combat.md#전투-상태)
  - → (제안) 룰북 그대로다(경지를 헤아릴 수 없음 규칙 포함). `상태` 의 전투 줄에 붙는 기혈 상태는 4구간 이름(`다침` 등)을 쓴다. → [명령어 처리: 교전 메시지](command.md#교전-메시지), [플랫폼: 5차 WebSocket 메시지 변경](platform.md#5차-websocket-메시지-변경)
- 지역 권장 경지 표시는? → (제안) 5차에도 미룬다. 권장 경지는 지역의 몹 기준 경지 범위에서 나오는데 지역 데이터에 몹 배치표·권장 경지 칸이 아직 없다.

### 6차 이터레이션 열린 질문

6차 구현 전에 정해야 하는 세부다. 창호가 정하지 않은 것은 고나 쪽에서 `(제안)` 으로 정했고, 질문마다 답과 적은 곳을 붙였다. 룰북에 이미 답이 있으면 `→ 룰북:` 으로 적었다. 룰북 규칙·수치는 그대로 따른다.

**신통 데이터**
- 공격 신통에 4차 정의 말고 무엇을 더하는가? → 룰북: 이름·종류·속성·대상·단계별 값(기본 위력·신통 계수)·소모·시전 시간·재사용 대기시간·쓸 수 있는 때 → [신통이 가지는 것](../game-rule/technique.md#신통이-가지는-것). 4차에는 단계별 값만 없다.
  - → (제안) 공격 신통에 배우는 단계부터 마지막 단계까지 단계마다 기본 위력(0~10,000, 소수 둘째 자리까지)·신통 계수(0~100, 소수 셋째 자리까지)를 둔다. 룰북 예(화탄술 2 → 단계마다 +0.2, 계수 1.2 → 단계마다 2% 안쪽)를 적을 수 있는 자리 수다. 공격이 아닌 신통에는 6차에 단계별 값을 두지 않는다. → [관리 툴: 공격 신통의 단계별 값](admin-tool.md#공격-신통의-단계별-값)
- 6차에 게임에서 쓸 수 있는 신통의 꼴은? 쓸 수 없는 꼴을 관리 툴이 막는가? → 룰북: 종류 10가지, 대상 3가지, 소모 스탯 여럿·틱마다 → [신통이 가지는 것](../game-rule/technique.md#신통이-가지는-것)
  - → (제안) 종류 `공격` · 대상 `한 대상` · 소모 `없음` 또는 `법력`(한 번에)만 쓴다. 의식·정혈은 현재 수치를 저장하지 않고, 틱마다 소모는 공격에 맞지 않으며, `방의 모든 적` 은 룰북 종류 '범위 공격' 의 몫이기 때문이다. 관리 툴은 룰북이 허락하는 꼴을 막지 않고(나중 이터레이션에서 쓰게 됨), 게임이 `어풍결은 아직 쓸 수 없는 신통입니다.` 로 거절한다. → [명령어 처리: 신통 쓰기](command.md#신통-쓰기)
- 4차에 만든 신통(단계별 값·이펙트 문장이 없음)은 어떻게 하는가?
  - → (제안) 서버가 뜰 때 한 번 채운다. 이펙트 문장이 없는 신통에는 기본 문장 하나(공격이면 `{대상}에게 화탄술을 펼친다!`, 그 밖은 `화탄술을 펼친다.`), 단계별 값이 없는 공격 신통에는 룰북 입문 공격 신통 값(오행 기본 2·계수 1.2·단계마다 기본 +0.2, 연체 기본 5·계수 2.2·단계마다 기본 +0.5 — [공법 목록](../game-rule/technique-list.md))을 넣는다. → [관리 툴: 기존 신통 채우기](admin-tool.md#기존-신통-채우기)

**이펙트 문장 (창호)**
- 몇 개, 어떻게 고르는가? → 창호: 최소 1개 ~ 최대 5개, 쓸 때 무작위로 하나.
  - → (제안) 모든 종류의 신통에 1~5개를 받는다(창호 원문이 '신통 사용할때' 라 공격만이 아니다. 공격 외 신통은 쓰게 될 때 바로 쓴다). 쓸 때 같은 확률로 하나를 고른다. 연달아 같은 문장이 나와도 막지 않는다. → [관리 툴: 이펙트 문장](admin-tool.md#이펙트-문장)
- 문장 길이·모양과 자리표시는? 룰북에 아직 없음.
  - → (제안) 앞뒤 공백을 자른 뒤 1~100자, 한 줄, 한 신통 안에서 같은 문장 두 번은 안 됨. 자리표시는 `{대상}`(대상 이름, `2.` 번호 없이)·`{시전자}`(쓴 캐릭터 이름) 둘이다. 자리표시 바로 뒤의 조사(`이/가` `을/를` `은/는` `과/와` `으로/로`)는 엔진이 받침에 맞춰 고친다(룰북 [공통 오류 메시지](../game-rule/commands.md#공통-오류-메시지): 조사는 앞 낱말 받침에 맞춰 바꿈). `{대상}` 은 대상이 `한 대상` 인 신통에만 쓸 수 있다. 다른 `{…}` 는 저장을 거절한다. → [관리 툴: 이펙트 문장](admin-tool.md#이펙트-문장)
- 누가 보는가? 피해·법력 수치는 어디에 붙는가?
  - → (제안) 쓴 사람에게만 보인다(5차: 교전하지 않는 같은 방 사람에게는 치는 줄마다 알리지 않음). 문장 뒤에 5차 교전 줄처럼 `(피해 8, 법력 20/25)` 를 붙인다. 같은 방 사람에게 보일 때를 위해 `{시전자}` 를 미리 둔다. → [명령어 처리: 신통 교전 메시지](command.md#신통-교전-메시지)

**신통 명령**
- 명령 문법과 이름 해석은? → 룰북: `<신통> [대상]`, 신통 이름이 곧 명령어, 명령어가 먼저, 전투 중 대상을 빼면 현재 대상, 전투 밖에서 빼면 `누구에게 쓰시겠습니까? (예: 화탄술 늑대)` → [입력 문법](../game-rule/commands.md#입력-문법), [대상 지정](../game-rule/combat.md#대상-지정), [이름 겹침 정리](../game-rule/commands.md#이름-겹침-정리)
  - → (제안) 룰북 그대로다. 첫 낱말이 명령어가 아니면 배운 신통 이름(영문 대소문자 무시, 줄여 쓰기 없음)에서 찾는다. 대상 찾기·거절은 5차 `공격` 과 같다(몹 → NPC → 플레이어). 현재 대상은 5차의 '노리는 상대' 다. → [명령어 처리: 신통 쓰기](command.md#신통-쓰기)
- 다른 공법에서 같은 이름의 신통을 배웠으면? (룰북 경신술은 공법마다 속성이 다른 같은 이름) 룰북에 없음.
  - → (제안) 먼저 익힌 공법의 신통을 쓴다. 다른 쪽을 고르는 문법은 6차에 없다(6차에 쓰는 공격 신통은 룰북 콘텐츠에서 이름이 겹치지 않음). → [명령어 처리: 신통 쓰기](command.md#신통-쓰기)
- 배우지 않은 신통 이름을 치면? 룰북에 없음.
  - → (제안) 어느 공법에든 그 이름의 신통이 정의되어 있으면 `화탄술은 아직 깨치지 못한 신통입니다.`(룰북에 아직 없음), 아니면 모르는 명령이다. → [명령어 처리: 신통 쓰기](command.md#신통-쓰기)
- 검사 순서와 거절 문구는? → 룰북: 공통 대기 `아직 기운을 고르는 중입니다. (0.6초)`, 재사용 대기 `화탄술은 아직 쓸 수 없습니다. (1.8초)`, 시전 중 `술법을 펼치는 중입니다. (끊으려면 '중지')` → [대기시간 중 입력](../game-rule/combat.md#대기시간-중-입력), [시전 시간](../game-rule/combat.md#시전-시간)
  - → (제안) 이름 → 쓸 수 있는 꼴 → 시전 중 → 대상 → 영력 0 → 공통 대기 → 재사용 대기 → 법력 순. 처음 걸린 것만 알리고 소모·대기는 없다. → [명령어 처리: 신통 쓰기](command.md#신통-쓰기)
- 법력이 모자라면? → 룰북: 거절하지 않고 무리한 사용으로 쓴다(남은 법력을 다 쓰고 모자란 몫만큼 영력 ÷ 10·기혈 × 1 이 깎임, 깎인 영력은 단약으로만 회복) → [법력](../game-rule/stats.md#법력), [영력 (진원)](../game-rule/stats.md#영력-진원)
  - → (제안) **6차는 거절한다** `법력이 모자랍니다. (필요 5, 남은 것 3)`(룰북 정혈 태우기 문구 `정혈이 모자랍니다. (필요 2, 남은 것 1)` 의 모양, 룰북에 아직 없음). 단약이 없는 6차에 무리한 사용을 넣으면 깎인 영력을 되돌릴 길이 없어 캐릭터가 영구히 약해지기 때문이다. 영력 현재 수치를 저장하지 않아도 되는 이점도 있다. 무리한 사용은 단약과 함께 붙인다. 룰북과 다르므로 창호 확인이 필요하다. → [명령어 처리: 신통 쓰기](command.md#신통-쓰기)
- 공통 대기시간 끝의 예약(0.3초 이하 남았을 때 들어온 신통 하나)을 하는가? → 룰북: [대기시간 중 입력](../game-rule/combat.md#대기시간-중-입력)
  - → (제안) 6차에는 하지 않고 거절만 한다. 서버 틱이 1초라 '끝나는 순간 실행' 을 맞추려면 틱보다 잘게 도는 예약이 따로 필요하다. 거절 문구의 남은 시간으로 다시 치면 된다.
- 재사용 대기시간은 어떻게 보이는가? → 룰북: `신통` 목록에 남은 것만 `(4.2초 남음)`, 거절 문구에 남은 시간 → [정보](../game-rule/commands.md#정보)
  - → (제안) 룰북 그대로다. 남은 시간은 4차 시간 문체(60초 미만은 소수 첫째 자리까지)다. → [명령어 처리: 6차 정보 명령](command.md#6차-정보-명령)

**시전 시간**
- 시전 시간이 있는 신통은? → 룰북: 명령하면 시전 상태, 공통 대기는 시전 시작 때, 시전 중 다른 신통·이동 불가, 공격받아도 끊기지 않음, 기절·사망·도주·`중지` 로 끊김, 대상이 죽거나 떠나면 실패, 소모·재사용 대기는 발동 때 → [시전 시간](../game-rule/combat.md#시전-시간)
  - → (제안) 룰북 그대로 넣고 `중지` 도 넣는다(룰북 문구). 발동은 서버 틱의 행동 단계에서 처리해 1초 안쪽으로 늦을 수 있다. 시전 시작 줄은 신통마다의 문구가 없어 `화탄술을 펼치기 시작한다… (2초)`(룰북에 아직 없음) 하나다. 교전은 발동할 때 시작된다. 룰북 공법 목록의 공격 신통은 모두 시전 0이라 6차 콘텐츠에서는 드물다. → [명령어 처리: 시전과 `중지`](command.md#시전과-중지)
- 시전 중에 5차 자동 공격은?
  - → (제안) 멈추지 않는다. 5차 자동 공격은 신통·법기 명령이 아니라 틱의 임시 행동이기 때문이다. 법기가 생기면 다시 정한다. → [명령어 처리: 시전과 `중지`](command.md#시전과-중지)

**교전 시작과 5차 `공격`**
- 신통으로 교전을 시작하는가? `쓸 수 있는 때: 전투 중만` 인 공격 신통은 교전을 시작할 수 있는가? → 룰북: 공격 신통을 쓰는 순간 양쪽이 전투 상태가 된다. 룰북 예 `화탄술 왕노인`·`> 화탄술` `누구에게 쓰시겠습니까?` 는 전투 밖에서 공격 신통을 쓰는 것이다 → [진행 방식](../game-rule/combat.md#진행-방식), [대상 지정](../game-rule/combat.md#대상-지정). '전투 중만' 이 교전 시작을 막는지는 룰북에 없음.
  - → (제안) 공격 신통은 몹에게 쓰면 늘 교전을 시작한다(5차 `공격` 과 같은 교전). 공격 신통에는 `쓸 수 있는 때` 를 보지 않는다 — 쓰는 순간 전투 상태가 되므로 '전투 밖에서 쓰는' 공격 신통이 없다. 이 칸은 대상이 없는 신통(치료·탐지 등)이 생길 때 쓴다. → [명령어 처리: 신통 쓰기](command.md#신통-쓰기)
- 5차 임시 `공격` 과 3초 자동 공격은 남기는가? → 룰북: 기본 공격은 없고 법기 공격이 그 몫이다 → [진행 방식](../game-rule/combat.md#진행-방식). 5차 열린 질문에서 '신통·법기가 생기면 그때 정한다' 고 했다.
  - → (제안) 6차에도 그대로 둔다. 법기가 없어 신통만으로는 같은 경지 상대를 쓰러뜨리지 못하고(룰북 화탄술: 연기 1층 법력 25로 5발, 상대는 7발), 무리한 사용도 막았기 때문이다. 신통은 자동 공격과 따로 쓰는 덤 공격이다. 신통으로 교전을 시작하면 첫 자동 공격은 그 3초 뒤다. 법기가 생길 때 `공격` 을 법기 기본 공격으로 바꿀지 없앨지 정한다. 창호 확인이 필요하다. → [명령어 처리: 신통 쓰기](command.md#신통-쓰기)
- 신통 피해의 위협·처치자는? → 룰북: 위협 = 준 피해(층을 거치기 전 위력), 처치자 = 가장 많은 피해 → [몹과 파티원의 행동](../game-rule/combat.md#몹과-파티원의-행동), [처치 보상 귀속](../game-rule/npc.md#처치-보상-귀속)
  - → (제안) 룰북 그대로 5차 위협·피해 기록에 더한다. 쓰러뜨린 뒤는 5차(시체·수습·재등장) 그대로다.
- 영력 발휘 제한(법력 20% 미만)을 넣는가? → 룰북: 신통을 쓰는 순간, 소모 전 남은 법력으로 판정 → [법력](../game-rule/stats.md#법력)
  - → (제안) 신통 위력에 넣는다. 5차 임시 `공격` 위력(3 + 1.8 × 영력 최대치)은 바꾸지 않는다. 룰북의 '법력이 바닥났습니다. 이대로 법력을 쓰면 진원이 상합니다.' 경고는 무리한 사용이 없어 쓰지 않는다. → [명령어 처리: 신통 쓰기](command.md#신통-쓰기)
- 상성(속성에 따른 피해 증감)은? → 창호: 나중. 룰북에는 받는 쪽 속성 배율(귀물·음혼 화 ×1.3, 연체 ×0.5)이 이미 있다 → [피해 흐름](../game-rule/combat.md#피해-흐름)
  - → (제안) 6차에는 넣지 않는다(나중 (창호)). 피해 계산에 '층을 거치기 전 피해에 곱하는 받는 쪽 배율' 자리를 두고 6차에는 늘 ×1 로 둔다. 상성을 붙일 때 룰북 귀물·음혼 배율과 한 틀로 정한다. → [명령어 처리: 신통 쓰기](command.md#신통-쓰기)

**법력 저장·회복**
- 법력 현재 수치를 어떻게 저장하는가? → (제안) 5차 기혈과 같이 깎인 법력을 그 열만 쓰는 쿼리로 저장한다. 관리 툴 경지 지정으로 최대치가 내려가면 같은 트랜잭션에서 깎인 법력을 줄인다(5차와 같음). → [플랫폼: 6차 월드 상태와 저장](platform.md#6차-월드-상태와-저장)
- 법력은 어떻게 차는가? → 룰북: 자연 회복(영기 농도마다, 보통 최대치의 0.5%/초, 전투 중에도), 접속을 끊은 동안은 회복 없음 → [영기 농도](../game-rule/recovery.md#영기-농도), [회복과 휴식](../game-rule/recovery.md#회복과-휴식)
  - → (제안) 룰북 그대로 서버 틱마다 접속해 세계에 있는 캐릭터의 법력을 최대치의 0.5%씩 채운다(모든 방을 '보통' 으로 봄 — 방의 영기 농도 칸은 명상·돌파와 함께 더함). 0에서 다 차는 데 200초다. 5차 기혈의 '교전 뒤 10초에 다 참' 같은 임시 규칙은 두지 않는다. 질 때(5차 최소)에도 법력은 그대로다. → [명령어 처리: 법력 회복](command.md#법력-회복)

**깨달음**
- 쌓이는 양과 나뉨은? → 룰북: G = 법력 소모량(법력을 쓰지 않으면 기준 소모 = 기준 경지 법력 기준값 ÷ 5 × 재사용 대기 ÷ 3초) × 상황 계수(전투 중 1.0, 대상이 소경지 3 이상 낮음 0.5, 대경지 1 이상 낮음 0.1, 전투 밖 0.1), 신통 속성에 G(여럿이면 나눔), 신통 속성에 없는 공법 속성에 G × 0.5, 연체술 신통은 연체에 G → [쌓이는 양](../game-rule/technique.md#쌓이는-양), [속성에 나뉘어 쌓이는 양](../game-rule/technique.md#속성에-나뉘어-쌓이는-양)
  - → (제안) 룰북 그대로다. 대상 몹의 경지는 기준 경지다(룰북). 오행도 연체도 아닌 공격 신통은 신통 속성 몫이 없고 공법 깨달음만 쌓인다(룰북 식 그대로). → [명령어 처리: 깨달음 쌓기](command.md#깨달음-쌓기)
- 상한은? → 룰북: 한 상대와의 한 교전에서 얻는 깨달음 합 ≤ 그 상대의 기혈 최대치, 전투 밖 60분 상한, 걸리면 알림 → [쌓이는 양](../game-rule/technique.md#쌓이는-양)
  - → (제안) 한 상대 상한을 넣는다. 남은 상한보다 많으면 남은 만큼만 쌓고(속성마다 같은 비율로 줄임), 상한에 처음 닿은 교전에서 한 번 `같은 상대에게서는 더 깨닫는 것이 없습니다.`(룰북)를 보인다. 전투 밖 상한은 6차 공격 신통이 늘 교전 중이라 생기지 않아 넣지 않는다. → [명령어 처리: 깨달음 쌓기](command.md#깨달음-쌓기)
- 저장과 표시는? → 룰북: 내부 소수, 화면은 버림, `상태` 에 속성별 → [속성에 나뉘어 쌓이는 양](../game-rule/technique.md#속성에-나뉘어-쌓이는-양)
  - → (제안) 캐릭터마다 여섯 갈래(금·목·수·화·토·연체)를 소수로 DB에 저장하고(신통이 발동하는 트랜잭션에서 바로), `상태`·`공법` 에 버린 정수로 보인다. 쓸 때마다 따로 알리지 않는다. 관리 툴 캐릭터 상세에도 읽기 전용으로 보인다. → [플랫폼: 6차 월드 상태와 저장](platform.md#6차-월드-상태와-저장), [관리 툴: 6차 화면](admin-tool.md#6차-화면)

**메시지 · 화면**
- WebSocket 메시지는 무엇이 바뀌는가? → (제안) 새 `type` 은 없다. 신통 줄은 `system` `tone: "combat"`, 거절은 `tone: "error"`, `status` 에 `insight` 와 저장된 현재 법력이 들어간다. → [플랫폼: 6차 WebSocket 메시지 변경](platform.md#6차-websocket-메시지-변경)
- 관리 툴 화면은? → (제안) 4차 공법 화면의 신통 행마다 펼치는 칸에 `이펙트 문장`(1~5칸)과 공격 신통의 `단계별 값` 표를 둔다. → [관리 툴: 6차 화면](admin-tool.md#6차-화면)
- 자동완성에 신통 이름을 넣는가? → (제안) 6차에는 넣지 않는다. 배운 신통 목록을 구조로 보내는 메시지가 없다(`신통` 은 `system/info` 글). 넣으려면 메시지를 더해야 해 뒤로 미룬다. → [명령어 처리: 6차 도움말](command.md#6차-도움말)
- 재사용 대기·공통 대기·시전은 어디에 두는가? → 룰북: 재사용 대기는 접속을 끊은 동안에도 흐르고, 세계에서 사라지면 시전은 끝난다 → [접속 종료](../game-rule/combat.md#접속-종료)
  - → (제안) 메모리에 끝나는 시각으로 두고(5차 다음 공격 시각처럼 끊겨도 남음), 서버를 다시 시작하면 사라진다. 시전은 끊기면 끝난다(소모 없음). → [플랫폼: 6차 월드 상태와 저장](platform.md#6차-월드-상태와-저장)
