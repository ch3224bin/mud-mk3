# 시스템 스펙

구현할 시스템의 스펙이다. [룰북](../game-rule/index.md)이 "플레이어가 겪는 규칙·수치"라면, 이 문서들은 "그걸 담는 틀"을 다룬다 — 어떤 시스템이 있고, 무엇이 데이터(관리 툴에서 입력)이고 무엇이 엔진 코드인지, 시스템 간 관계.

- 스펙은 얼추 잡고, 구현하면서 이터레이션마다 점점 상세화한다. 한 번에 모든 스펙을 잡지 않는다.
- 게임 규칙·수치는 여기 적지 않고 룰북의 해당 장으로 링크한다.
- 용어는 [용어집](../glossary.md)을 따른다.
- 정해지지 않은 것은 `(미정)` 으로 두거나 각 문서의 `## 열린 질문` 에 남긴다.

## 기본 방향

- 텍스트 머드 게임이다. 기존 텍스트 머드 게임의 문법을 따르되, 이 게임만의 특이한 시스템이 있다.
- 시스템(엔진)은 틀을 만들고, 그 내용은 되도록 하드 코딩하지 않고 관리 툴에서 입력받는다(어쩔 수 없는 하드 코딩은 있을 수 있음). → [관리 툴](admin-tool.md)

## 이터레이션 계획

### 1차 범위: 관리 툴 + 맵 + 인증

- 관리 툴에서 맵(방·출구)을 만들고, 게임에서 그 맵을 돌아다니기까지 구현한다. → [관리 툴](admin-tool.md), [월드 구조](world-structure.md)
- 인증(Google 로그인)도 1차 범위에 넣는다. → [인증](auth.md)
- 1차는 인증과 맵(방·출구)·돌아다니기만 한다. 성·종문 정의와 맵의 소유 지정은 다음 이터레이션으로 미룬다. → [월드 구조](world-structure.md#성--종문-소유)
- 이벤트처럼 관리 툴로 만들기 애매한 부분은 코딩으로 해결한다. → [관리 툴](admin-tool.md#데이터-주도-콘텐츠)
- 구현 계획: [`docs/impl/iteration-1/plan.md`](../../impl/iteration-1/plan.md). 계획이 스펙에 없어서 정한 결정은 이 스펙 문서들에 `(제안)` 으로 옮겼다.

### 2차 범위: NPC 배치 + 기본 대화 + 성·종문 정의

창호가 정했다(2026-11-13). 구현은 아직 시작하지 않았다.

- **NPC 배치:** 관리 툴에서 NPC를 만들고 방에 배치한다. 게임에서 방에 있는 NPC를 본다. → [NPC: 생성과 배치](npc.md#생성과-배치), [관리 툴](admin-tool.md#관리-화면에서-하는-일)
  - 2차의 NPC는 모두 유니크 NPC(세계에 하나)이고 방 하나에 고정한다. 같은 NPC 여러 마리, 구역을 돌아다니는 NPC는 2차에 넣지 않는다.
- **기본 대화:** 게임에서 NPC와 정해진 대사(관리 툴에서 입력)로 대화한다. → [NPC: 고유 대사](npc.md#고유-대사), [룰북: 말 걸기](../game-rule/npc.md#말-걸기)
  - 대사는 룰북의 낱말 묻기 방식으로 입력한다. 관리 툴에서 인사말, 낱말마다 대답, 모르는 낱말에 하는 기본 대답을 입력한다.
  - 조건(단서·경지·종문·퀘스트 단계)에 따라 열리는 낱말은 2차에 넣지 않는다. 다음 이터레이션에서 한다.
  - 대화 명령은 `대화 <NPC> [낱말]` 이다. 1차의 `말하기`(줄임 `'`)는 그대로 같은 방 플레이어에게 말하는 채팅이다. → [명령어 처리](command.md#2차-명령어)
  - NPC가 알아서 말하기(60초마다 무작위 대사)는 2차에 넣지 않는다. NPC는 플레이어가 말을 걸 때만 답한다. 그래서 2차에도 서버 틱은 생기지 않는다.
- **LLM 대화 켬/끔 설정 자리만:** NPC마다 LLM 대화 켬/끔 값을 관리 툴에서 저장할 수 있게 자리만 만든다. 켜도 2차에서는 LLM을 부르지 않는다. → [NPC: 캐릭터 챗](npc.md#캐릭터-챗)
- **성·종문 정의와 지역 소유 지정:** 관리 툴에서 성·종문을 정의하고, 존(지역)마다 소유(성 / 종문 / 없음)를 지정한다. → [월드 구조: 성 · 종문 소유](world-structure.md#성--종문-소유)
  - 성·종문은 이름과 묘사만 가진다.
  - 지역 소유는 게임 방 화면 머리에 보인다(예: `[청석성]`).
- 2차에 넣지 않는 것: LLM 캐릭터 챗, NPC 장기 메모리, 동료 합류, NPC 역할(상점·퀘스트 등), 몹·전투, 퀘스트·공적, 성·종문 가입, 조건으로 열리는 낱말, NPC가 알아서 말하기, 같은 NPC 여러 마리, 돌아다니는 NPC.
- 2차에 걸리는 열린 질문은 [아래](#2차-이터레이션-열린-질문)에 모았다.

### 3차 이후 후보 (예정)

순서대로 후보다. 범위는 그때 정한다.

1. LLM 캐릭터 챗 · NPC 장기 메모리 (예정) → [NPC: 캐릭터 챗](npc.md#캐릭터-챗), [함께 쌓는 내러티브](npc.md#함께-쌓는-내러티브)
2. 몹 · 전투 (예정) → [룰북: 몹](../game-rule/npc.md#몹)
3. 퀘스트 · 공적 (예정) → [퀘스트 · 공적 교환](quest.md)

## 열린 질문

- 월드 상태의 DB 저장 주기·시점과 게임 틱은? — 1차 저장 시점(캐릭터 위치는 이동할 때마다)은 제안으로 정했다. 이후 상태·틱은 열려 있다. → [플랫폼](platform.md#열린-질문)
- WebSocket JSON 메시지 목록·스키마는? → (제안) 1차 메시지를 정했다. → [플랫폼: 1차 WebSocket 메시지](platform.md#1차-websocket-메시지)
- NPC 대사의 LLM 연동은 3차 이후 후보로 정했다(예정). 그 전까지 대사는 낱말 묻기 방식으로 입력한다([2차 범위](#2차-범위-npc-배치--기본-대화--성종문-정의)). → [NPC](npc.md)
- NPC 장기 메모리에 무엇을 어떻게 남기는가? (엔진 자동 기록 / LLM 요약 등) → [NPC](npc.md#함께-쌓는-내러티브)

### 2차 이터레이션 열린 질문

2차 구현 전에 정해야 하는 것이다. 창호가 정하지 않으면 구현 때 `(제안)` 으로 정한다.

**NPC 데이터와 배치**
- NPC 하나가 가지는 항목은? (이름, 방에서 보이는 한 줄 묘사, 자세히 볼 때 묘사, 호칭 등) 이름은 세계에서 유일한가? → [룰북: 유니크 NPC](../game-rule/npc.md#유니크-npc)
- NPC가 있는 방을 지우면 NPC는 어떻게 되는가? (배치만 풀림 / 시작 방으로 / 삭제)

**대화 명령어와 화면**
- NPC 이름을 줄여 부르거나(앞글자), 같은 방에 비슷한 이름이 둘일 때 어떻게 고르는가?
- 플레이어가 NPC와 나눈 대화를 같은 방의 다른 플레이어도 보는가?
- 방 화면에서 NPC를 플레이어 목록과 어떻게 구분해 보여주는가? NPC를 자세히 보는 명령(`보기 <NPC>`)이 있는가?

**LLM 켬/끔 자리**
- 2차에서 LLM 켬 NPC에 말을 걸면 어떻게 되는가? (그냥 정해진 대사로 답함으로 둘지)
- LLM용 캐릭터 설정(성격·말투·배경) 입력 칸도 2차에 자리만 두는가, 3차로 미루는가? → [NPC: 열린 질문](npc.md#열린-질문)

**성·종문 정의와 소유**
- 성·종문이 소유한 지역이 있으면 그 성·종문을 지울 수 없게 하는가?
- NPC에 소속(성·종문)도 2차에 지정하는가?
