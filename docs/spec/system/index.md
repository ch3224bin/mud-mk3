# 시스템 스펙

구현할 시스템의 스펙이다. [룰북](../game-rule/index.md)이 "플레이어가 겪는 규칙·수치"라면, 이 문서들은 "그걸 담는 틀"을 다룬다 — 어떤 시스템이 있고, 무엇이 데이터(관리 툴에서 입력)이고 무엇이 엔진 코드인지, 시스템 간 관계.

- 스펙은 얼추 잡고, 구현하면서 이터레이션마다 점점 상세화한다. 한 번에 모든 스펙을 잡지 않는다.
- 게임 규칙·수치는 여기 적지 않고 룰북의 해당 장으로 링크한다.
- 용어는 [용어집](../glossary.md)을 따른다.
- 정해지지 않은 것은 `(미정)` 으로 두거나 각 문서의 `## 열린 질문` 에 남긴다.

## 기본 방향

- 텍스트 머드 게임이다. 기존 텍스트 머드 게임의 문법을 따르되, 이 게임만의 특이한 시스템이 있다.
- 시스템(엔진)은 틀을 만들고, 그 내용은 되도록 하드 코딩하지 않고 관리 툴에서 입력받는다(어쩔 수 없는 하드 코딩은 있을 수 있음). → [관리 툴](admin-tool.md)

## 이터레이션 계획

### 1차 범위: 관리 툴 + 맵 + 인증

- 관리 툴에서 맵(방·출구)을 만들고, 게임에서 그 맵을 돌아다니기까지 구현한다. → [관리 툴](admin-tool.md), [월드 구조](world-structure.md)
- 인증(Google 로그인)도 1차 범위에 넣는다. → [인증](auth.md)
- 1차는 인증과 맵(방·출구)·돌아다니기만 한다. 성·종문 정의와 맵의 소유 지정은 다음 이터레이션으로 미룬다. → [월드 구조](world-structure.md#성--종문-소유)
- 이벤트처럼 관리 툴로 만들기 애매한 부분은 코딩으로 해결한다. → [관리 툴](admin-tool.md#데이터-주도-콘텐츠)
- 구현 계획: [`docs/impl/iteration-1/plan.md`](../../impl/iteration-1/plan.md). 계획이 스펙에 없어서 정한 결정은 이 스펙 문서들에 `(제안)` 으로 옮겼다.

### 2차 범위: NPC 배치 + 기본 대화 + 성·종문 정의

창호가 정했다(2026-11-13).

- 구현 계획: [`docs/impl/iteration-2/plan.md`](../../impl/iteration-2/plan.md). 계획이 스펙에 없어서 정한 결정(D19~D31)은 이 스펙 문서들에 `(제안)` 으로 옮겼다.
- 구현했다(2026-11-14). 진행 기록: [`docs/impl/iteration-2/progress.md`](../../impl/iteration-2/progress.md)

- **NPC 배치:** 관리 툴에서 NPC를 만들고 방에 배치한다. 게임에서 방에 있는 NPC를 본다. → [NPC: 생성과 배치](npc.md#생성과-배치), [관리 툴](admin-tool.md#관리-화면에서-하는-일)
  - 2차의 NPC는 모두 유니크 NPC(세계에 하나)이고 방 하나에 고정한다. 같은 NPC 여러 마리, 구역을 돌아다니는 NPC는 2차에 넣지 않는다.
- **기본 대화:** 게임에서 NPC와 정해진 대사(관리 툴에서 입력)로 대화한다. → [NPC: 고유 대사](npc.md#고유-대사), [룰북: 말 걸기](../game-rule/npc.md#말-걸기)
  - 대사는 룰북의 낱말 묻기 방식으로 입력한다. 관리 툴에서 인사말, 낱말마다 대답, 모르는 낱말에 하는 기본 대답을 입력한다.
  - 조건(단서·경지·종문·퀘스트 단계)에 따라 열리는 낱말은 2차에 넣지 않는다. 다음 이터레이션에서 한다.
  - 대화 명령은 `대화 <NPC> [낱말]` 이다. 1차의 `말하기`(줄임 `'`)는 그대로 같은 방 플레이어에게 말하는 채팅이다. → [명령어 처리](command.md#2차-명령어)
  - NPC가 알아서 말하기(60초마다 무작위 대사)는 2차에 넣지 않는다. NPC는 플레이어가 말을 걸 때만 답한다. 그래서 2차에도 서버 틱은 생기지 않는다.
- **LLM 대화 켬/끔 설정 자리만:** NPC마다 LLM 대화 켬/끔 값을 관리 툴에서 저장할 수 있게 자리만 만든다. 켜도 2차에서는 LLM을 부르지 않는다. → [NPC: 캐릭터 챗](npc.md#캐릭터-챗)
- **성·종문 정의와 지역 소유 지정:** 관리 툴에서 성·종문을 정의하고, 존(지역)마다 소유(성 / 종문 / 없음)를 지정한다. → [월드 구조: 성 · 종문 소유](world-structure.md#성--종문-소유)
  - 성·종문은 이름과 묘사만 가진다.
  - 지역 소유는 게임 방 화면 머리에 보인다(예: `[청석성]`).
- 2차에 넣지 않는 것: LLM 캐릭터 챗, NPC 장기 메모리, 동료 합류, NPC 역할(상점·퀘스트 등), 몹·전투, 퀘스트·공적, 성·종문 가입, 조건으로 열리는 낱말, NPC가 알아서 말하기, 같은 NPC 여러 마리, 돌아다니는 NPC.
- 2차에 걸리는 열린 질문은 [아래](#2차-이터레이션-열린-질문)에 모았다.

### 3차 범위: 아이템 + 영석 + 상점 + 저물대·귀속 + 주기

창호가 정했다(2026-11-14).

- 구현 계획: (작성 예정) `docs/impl/iteration-3/plan.md`. 계획이 정하는 결정은 이 스펙 문서들에 `(제안)` 으로 옮긴다.
- 룰북에 이미 있는 규칙·수치는 그대로 따른다. 스펙과 룰북이 다르면 룰북 원칙을 우선한다. 세부(아래 [열린 질문](#3차-이터레이션-열린-질문))는 구현 때 `(제안)` 으로 정한다.

- **아이템 종류 정의:** 관리 툴에서 아이템 종류를 정의한다. 이름·묘사와 룰북 공통 속성을 가진다. → [관리 툴: 3차 범위](admin-tool.md#3차-범위), [룰북: 아이템 공통 속성](../game-rule/item.md#아이템-공통-속성)
- **방 바닥 배치:** 관리 툴에서 방 바닥에 물건을 둔다. 게임에서 방에 놓인 물건이 보인다. → [월드 구조: 방 바닥 물건](world-structure.md#방-바닥-물건), [룰북: 방 보기](../game-rule/world.md#방-보기)
- **줍기·버리기·소지품 보기·물건 보기:** 게임에서 바닥 물건을 줍고, 버리고, 소지품을 보고, 물건을 자세히 본다. → [명령어 처리: 3차 명령어](command.md#3차-명령어), [룰북: 줍기와 버리기](../game-rule/item.md#줍기와-버리기)
- **시작 소지품:** 관리 툴에서 새 캐릭터가 가지고 시작할 물건을 지정한다. → [룰북: 시작 소지품](../game-rule/item.md#시작-소지품)
- **영석(화폐):** 영석을 소지품으로 가지고 값을 치른다. → [룰북: 영석](../game-rule/item.md#영석), [룰북: 결제](../game-rule/item.md#결제)
- **상점 사고팔기:** 관리 툴에서 NPC에 상점 역할(파는 물건·값)을 준다. 게임에서 그 NPC에게 사고판다. → [NPC: 역할](npc.md#역할), [룰북: 상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기), [룰북: 역할별 이용](../game-rule/npc.md#역할별-이용)
- **저물대·귀속:** 저물대가 소지품 칸을 정한다. 물건을 귀속하고 푼다. → [룰북: 저물대 · 저물탁](../game-rule/item.md#저물대--저물탁), [룰북: 귀속](../game-rule/item.md#귀속)
- **주기:** 같은 방 플레이어에게 물건·영석을 바로 넘긴다. → [룰북: 직접 거래](../game-rule/item.md#직접-거래)
- 3차 완료 시나리오: 관리자로 admin-console 로그인 → 아이템 종류 정의 → 방 바닥에 배치 → 시작 소지품 지정 → NPC에 상점 역할(파는 물건·값) 지정 → play-client에서 새 캐릭터로 시작 소지품·영석 확인 → 바닥 물건 줍기·버리기 → 물건 보기 → 상점 NPC에게 사기·팔기(영석 증감) → 저물대·귀속 동작 → 같은 방 다른 플레이어에게 주기.
- 3차에 넣지 않는 것: 아이템을 써서 효과 내기(단약 복용 효과·부적·진법원반·법기 장착 등 — 스탯이 아직 없다), 교환 창·거래소·경매장, 제작, 몹 드롭, 공법·경지, 전투, LLM 챗.
- 3차에 걸리는 열린 질문은 [아래](#3차-이터레이션-열린-질문)에 모았다.

### 4차 이후 후보 (예정)

창호가 순서를 정했다(2026-11-14). 범위는 그때 정한다. 단, 5차 범위는 창호가 미리 골랐다.

1. **4차: 공법·신통 배우기 + 임의 경지 상승(레벨업)** (예정) → [룰북: 공법](../game-rule/technique.md), [룰북: 경지](../game-rule/realm.md)
2. **5차: 기본 전투** (예정) → [룰북: 전투](../game-rule/combat.md), [룰북: 몹](../game-rule/npc.md#몹)
   - 넣는 것(창호가 미리 고름): 캐릭터 전투 스탯(룰북 최소한), 관리 툴에서 몹을 만들고 방에 배치, 공격 명령과 서버 틱 자동 교전, 처치·재등장.
   - 그 뒤로 미룬 것: 공법 사용·단약·도주 판정. 선공·배회·드롭·사망·경험은 그때 정한다.
3. 그 뒤 후보 (순서는 그때 정함):
   - LLM 캐릭터 챗 · NPC 장기 메모리 (예정) → [NPC: 캐릭터 챗](npc.md#캐릭터-챗), [함께 쌓는 내러티브](npc.md#함께-쌓는-내러티브)
   - 퀘스트 · 공적 (예정) → [퀘스트 · 공적 교환](quest.md)

## 열린 질문

- 월드 상태의 DB 저장 주기·시점과 게임 틱은? — 1차 저장 시점(캐릭터 위치는 이동할 때마다)은 제안으로 정했다. 이후 상태·틱은 열려 있다. → [플랫폼](platform.md#열린-질문)
- WebSocket JSON 메시지 목록·스키마는? → (제안) 1차 메시지를 정했다. → [플랫폼: 1차 WebSocket 메시지](platform.md#1차-websocket-메시지)
- NPC 대사의 LLM 연동은 LLM 이터레이션(순서 미정)의 후보로 정했다(예정, [4차 이후 후보](#4차-이후-후보-예정)). 그 전까지 대사는 낱말 묻기 방식으로 입력한다([2차 범위](#2차-범위-npc-배치--기본-대화--성종문-정의)). → [NPC](npc.md)
- NPC 장기 메모리에 무엇을 어떻게 남기는가? (엔진 자동 기록 / LLM 요약 등) → [NPC](npc.md#함께-쌓는-내러티브)

### 2차 이터레이션 열린 질문

2차 구현 전에 정해야 하는 것이었다. 창호가 정하지 않아 구현 때 `(제안)` 으로 정했고, 질문마다 답과 적은 곳을 붙였다.

**NPC 데이터와 배치**
- NPC 하나가 가지는 항목은? (이름, 방에서 보이는 한 줄 묘사, 자세히 볼 때 묘사, 호칭 등) 이름은 세계에서 유일한가? → [룰북: 유니크 NPC](../game-rule/npc.md#유니크-npc)
  - → (제안) 2차 NPC는 이름(띄어쓰기 없이 1~12자, NPC끼리 유일, 영문 대소문자 무시)·인사말·낱말 대답·기본 대답·LLM 대화 켬/끔·배치 방만 가진다. 한 줄 묘사·자세히 볼 때 묘사·호칭은 `보기 <대상>` 이 생길 때 더한다. 캐릭터 이름은 NPC 이름과 겹칠 수 없다. → [NPC: 2차 데이터 모델](npc.md#2차-데이터-모델)
- NPC가 있는 방을 지우면 NPC는 어떻게 되는가? (배치만 풀림 / 시작 방으로 / 삭제)
  - → (제안) 배치만 풀린다. NPC는 남고 관리 목록에 `배치 안 됨` 으로 보인다. → [NPC: 2차 데이터 모델](npc.md#2차-데이터-모델)

**대화 명령어와 화면**
- NPC 이름을 줄여 부르거나(앞글자), 같은 방에 비슷한 이름이 둘일 때 어떻게 고르는가?
  - → (제안) 이름 전체가 같은 NPC를 먼저, 없으면 이름이 입력으로 시작하는 NPC 가운데 방 보기 순서(만든 순서) 첫째를 고른다. 영문은 대소문자를 가리지 않는다. 번호(`2.왕씨`)는 2차에 없다. → [명령어 처리: 2차 명령어](command.md#2차-명령어)
- 플레이어가 NPC와 나눈 대화를 같은 방의 다른 플레이어도 보는가?
  - → (제안) 보지 않는다. NPC의 대답은 묻는 플레이어에게만 간다. → [명령어 처리: 2차 명령어](command.md#2차-명령어)
- 방 화면에서 NPC를 플레이어 목록과 어떻게 구분해 보여주는가? NPC를 자세히 보는 명령(`보기 <NPC>`)이 있는가?
  - → (제안) 플레이어 줄 다음에 NPC 줄을 다른 스타일(`npc`)로 그린다. `보기 <NPC>` 는 1차 그대로 `아직 자세히 볼 수 없습니다.` 다. → [플랫폼: 플레이 화면](platform.md#플레이-화면-play-client), [플랫폼: 2차 WebSocket 메시지 변경](platform.md#2차-websocket-메시지-변경)

**LLM 켬/끔 자리**
- 2차에서 LLM 켬 NPC에 말을 걸면 어떻게 되는가? (그냥 정해진 대사로 답함으로 둘지)
  - → (제안) LLM 끔 NPC와 같은 정해진 대사로 답한다. 2차는 LLM을 부르지 않는다. → [NPC: 캐릭터 챗](npc.md#캐릭터-챗)
- LLM용 캐릭터 설정(성격·말투·배경) 입력 칸도 2차에 자리만 두는가, LLM 이터레이션으로 미루는가? → [NPC: 열린 질문](npc.md#열린-질문)
  - → (제안) LLM 이터레이션(순서 미정)으로 미룬다. 2차에는 칸이 없다.

**성·종문 정의와 소유**
- 성·종문이 소유한 지역이 있으면 그 성·종문을 지울 수 없게 하는가?
  - → (제안) 지울 수 없다(409 `소유한 지역이 있는 성·종문은 지울 수 없습니다`). → [월드 구조: 2차 데이터 모델](world-structure.md#2차-데이터-모델)
- NPC에 소속(성·종문)도 2차에 지정하는가?
  - → (제안) 지정하지 않는다. 가입·종문 규칙이 생길 때 더한다. → [NPC: 2차 데이터 모델](npc.md#2차-데이터-모델)

### 3차 이터레이션 열린 질문

3차 구현 때 `(제안)` 으로 정할 세부다. 답은 구현 계획이 정한다. 룰북에 이미 답이 있으면 `→ 룰북:` 으로 적었다. 룰북 규칙·수치는 그대로 따른다.

**아이템 종류**
- 3차의 아이템 종류가 가지는 항목은? (이름·묘사 + 공통 속성 가운데 무엇을 3차에 두는가) 이름은 유일한가? → 룰북: 이름·종류·필요 경지·품질·겹침·기준가·거래 가능·귀속 → [아이템 공통 속성](../game-rule/item.md#아이템-공통-속성)
- 종류(법기·단약·부적 …) 목록을 3차에 모두 고르게 하는가, 일부만 두는가? 쓰는 효과가 없는 3차에서 종류는 무엇을 가르는가? (겹침·매입 비율·귀속 가능 여부) → 룰북: [겹침 규칙](../game-rule/item.md#아이템-공통-속성), [매입 비율](../game-rule/item.md#상점에서-사고팔기), [직접 귀속](../game-rule/item.md#귀속)
- 품질을 3차에 두는가? 둔다면 이름 앞에 붙는 품질과 판매가·매입 배율을 계산하는가? → 룰북: [품질](../game-rule/item.md#품질)
- 필요 경지는 경지가 없는 3차에 입력만 받는가, 빼는가? → 룰북: 모자라도 가지고 다니고 거래할 수 있다 → [아이템 공통 속성](../game-rule/item.md#아이템-공통-속성)
- 아이템 종류를 지울 때 바닥·소지품·상점·시작 소지품에 그 물건이 있으면 어떻게 하는가?
- 같은 종류의 물건이 개체마다 다른 값(귀속 여부, 법기 내구도 등)을 가지는가? 3차에 개체 단위로 저장해야 하는 것은 귀속뿐인가?
- 관리 툴에서 바꾼 아이템 종류·바닥 배치·시작 소지품·상점 역할이 실행 중인 게임에 바로 반영되는가? → [관리 툴: 관리 툴 변경의 반영](admin-tool.md#관리-툴-변경의-반영)

**영석**
- 3차에 영석 4등급(하품·중품·상품·극품)을 모두 두는가, 하품만 두는가? → 룰북: 4등급, 결제 때 한 등급 위 1개 = 아래 100개, 낮은 등급부터 내고 거스름은 하품 → [영석](../game-rule/item.md#영석), [결제](../game-rule/item.md#결제)
- 영석은 아이템 종류 데이터인가, 엔진이 아는 고정 물건인가?
- 상위 등급 깨기 확인(`확인`)과 거스름 넘침을 3차에 하는가? → 룰북: [결제](../game-rule/item.md#결제)

**상점**
- 상점 역할의 데이터는? (파는 물건 목록, 사 주는 종류, 값을 기준가에서 계산할지 상점마다 입력할지) → 룰북: 판매가 = 기준가 × 품질 판매가 배율, 매입가 = 하계 기준가 × 매입 비율 × 품질 매입 배율 → [상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기), [상점 종류](../game-rule/game-structure.md#상점)
- 상점 재고는 끝없이 있는가, 수가 정해져 있는가? → 룰북: 재고는 무한이고 가격은 바뀌지 않는다. 플레이어가 판 물건은 다시 팔지 않고 사라진다, 매입 수량 한도 없음 → [상점](../game-rule/game-structure.md#상점), [상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기)
- 상점 종류(단약방·법기점 …)를 3차에 데이터로 두는가, 사 주는 종류를 NPC마다 직접 고르는가? → 룰북: [상점](../game-rule/game-structure.md#상점)
- `값 <물건>` 을 3차에 넣는가? → 룰북: [역할별 이용](../game-rule/npc.md#역할별-이용)
- 상점 불변식(매입가 < 판매가 × 0.5)을 관리 툴이 검사하는가? → 룰북: [상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기)

**소지품 · 저물대 · 귀속**
- 소지품 한도는? → 룰북: 무게 없음, 칸 수로만. 기본 2칸 + 저물대·저물탁 칸 합. 저물대 3개·저물탁 1개까지, 저물대 하급 20 · 중급 40 · 상급 80칸 → [저물대 · 저물탁](../game-rule/item.md#저물대--저물탁)
- 저물대 크기는 아이템 종류의 속성인가? 저물탁(필요 경지 축기 초기)을 경지가 없는 3차에 어떻게 다루는가?
- 귀속 시점은? 3차에 생기는 귀속 경우는 무엇인가? (처음부터 귀속된 물건을 관리 툴에서 정하는가, `귀속` 명령만인가) → 룰북: 퀘스트 물건·본명법보·퀘스트 보상·직접 귀속 → [귀속](../game-rule/item.md#귀속)
- 직접 귀속은 정혈 최대치의 10% 를 쓰는데 3차에는 정혈 스탯이 없다. 3차의 `귀속` 은 무엇을 소모하는가? → 룰북: [귀속](../game-rule/item.md#귀속)
- 시작 소지품의 영수대는 영수가 없는 3차에 어떻게 하는가? → 룰북: [시작 소지품](../game-rule/item.md#시작-소지품)

**바닥 물건**
- 관리 툴로 배치한 바닥 물건은 주우면 다시 나타나는가(얼마 뒤), 한 번뿐인가? 캐릭터마다인가, 모두 한 번인가? → 룰북: 플레이어가 버린 물건만 정했다(5분 남고 사라짐) → [줍기와 버리기](../game-rule/item.md#줍기와-버리기)
- 버린 물건이 5분 뒤 사라지려면 시간을 재는 무언가(서버 틱·예약 작업)가 필요하다. 3차에 무엇으로 하는가? → [플랫폼: 3차 월드 상태](platform.md#3차-월드-상태와-저장)
- 서버를 다시 시작하면 바닥 물건은 남는가?
- 바닥 물건을 방 보기에 어떻게 보이는가? 같은 물건은 묶는가? → 룰북: 대상 목록의 맨 끝, `하품 영석 3개` → [방 보기](../game-rule/world.md#방-보기)

**명령 · 화면**
- `보기 <물건>` 은 바닥 물건만 보는가, 내 소지품도 보는가? 찾는 순서는? → 룰북: 물건은 이름과 설명을 보여준다 → [방 보기](../game-rule/world.md#방-보기), [대상 지정](../game-rule/commands.md#대상-지정)
- 물건 이름 찾기(앞부분·낱말 앞부분 일치, 번호 `2.가죽`, 수량 `전부`)를 3차에 어디까지 하는가? → 룰북: [입력 문법](../game-rule/commands.md#입력-문법), [대상 지정](../game-rule/commands.md#대상-지정)
- `주기` 를 받는 쪽이 접속하지 않았거나 같은 방에 없으면? → 룰북: `여기에 한립은 없습니다.` → [직접 거래](../game-rule/item.md#직접-거래)
- 물건이 오가면 같은 방 다른 사람에게 알리는가? (줍기·버리기·주기)
