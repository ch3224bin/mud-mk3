# 시스템 스펙

구현할 시스템의 스펙이다. [룰북](../game-rule/index.md)이 "플레이어가 겪는 규칙·수치"라면, 이 문서들은 "그걸 담는 틀"을 다룬다 — 어떤 시스템이 있고, 무엇이 데이터(관리 툴에서 입력)이고 무엇이 엔진 코드인지, 시스템 간 관계.

- 스펙은 얼추 잡고, 구현하면서 이터레이션마다 점점 상세화한다. 한 번에 모든 스펙을 잡지 않는다.
- 게임 규칙·수치는 여기 적지 않고 룰북의 해당 장으로 링크한다.
- 용어는 [용어집](../glossary.md)을 따른다.
- 정해지지 않은 것은 `(미정)` 으로 두거나 각 문서의 `## 열린 질문` 에 남긴다.

## 기본 방향

- 텍스트 머드 게임이다. 기존 텍스트 머드 게임의 문법을 따르되, 이 게임만의 특이한 시스템이 있다.
- 시스템(엔진)은 틀을 만들고, 그 내용은 되도록 하드 코딩하지 않고 관리 툴에서 입력받는다(어쩔 수 없는 하드 코딩은 있을 수 있음). → [관리 툴](admin-tool.md)

## 이터레이션 계획

### 1차 범위: 관리 툴 + 맵

- 관리 툴에서 맵(방·출구)을 만들고, 게임에서 그 맵을 돌아다니기까지 구현한다. → [관리 툴](admin-tool.md), [월드 구조](world-structure.md)
- 그 다음 이터레이션 범위는 (미정).

## 열린 질문

- 기술 선택(언어·DB·클라이언트-서버 통신 방식)은? (미정) → [플랫폼](platform.md)
- NPC 대사의 LLM 연동은 언제(어느 이터레이션) 붙이는가? 그 전까지 대사는 어떤 형태로 입력하는가? → [NPC](npc.md)
- 이벤트·시나리오를 관리 툴에서 어떤 형태로 만드는가? (단계 목록, 조건-행동 규칙, 스크립트 등) → [이벤트 · 시나리오](event.md)
