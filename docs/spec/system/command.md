### 대화형 명령어

- 플레이어끼리 말을 주고받는 명령(말하기, 귓속말, 외치기). [멀티 유저](platform.md#멀티-유저)에서 쓰인다.
- NPC와의 대화는 `대화 <NPC> [낱말]` 이다. `말` 이라는 명령은 없다. → [2차 명령어](#2차-명령어), [NPC](npc.md)

## 1차 명령어

1차에 있는 명령이다. 명령어는 정해진 이름·줄임말로만 알아듣고 앞부분 일치는 받지 않는다(룰북 입력 문법과 같다). 입력은 최대 500자고, 넘으면 `명령이 너무 깁니다.`(룰북에 아직 없음)를 보낸다. (제안) → [룰북: 명령어](../game-rule/commands.md), [룰북: 이동 · 보기](../game-rule/commands.md#이동--보기), [룰북: 말하기 · 계정](../game-rule/commands.md#말하기--계정)

| 입력 | 하는 일 | 출력 |
|---|---|---|
| `보기`, `ㅂ` | 지금 방 다시 보기 | `room`(`zoneEntered=false`) |
| `보기 <무엇이든>` | 1차엔 자세히 보기가 없다(3차에 물건·소지품 보기가 생겨 사람·NPC·바닥 물건·소지품 순서로 찾는다 → [3차 명령어](#3차-명령어)) | `system/info` `아직 자세히 볼 수 없습니다.`(룰북에 아직 없음) |
| `동` `서` `남` `북` `북동` `북서` `남동` `남서` `위` `아래`, `e` `w` `s` `n` `ne` `nw` `se` `sw` `u` `d`(대소문자 무시) | 그 방위 출구로 이동 | 성공: 새 방 `room`. 실패: `system/error` `그쪽으로는 길이 없습니다.` |
| `말하기 <내용>`, `'<내용>`(띄어 쓰지 않아도 됨) | 같은 방 모두에게 | 나: `say(self=true)` `한백: "길을 묻겠소."`, 남: `say(self=false)` `한백이 말한다: "길을 묻겠소."`. 내용 없음: `system/error` `무엇이라 말하시겠습니까?`. 200자 넘음: `system/error` `말은 200자 이내로 하십시오.`(룰북에 아직 없음) |
| `누구` | 접속한 사람과 있는 지역 | `system/info` 여러 줄: `접속한 사람 (2)` 다음 줄마다 `  한립    청석숲`(두 칸 들여쓰기, 이름 뒤 네 칸) |
| `도움말` | 명령 목록 (2차에 `대화`, 3차에 물건 명령, 4차에 `상태`·`공법`·`신통`·`읽기` 추가 → [4차 도움말](#4차-도움말)) | `system/info` `명령: 보기(ㅂ) · 동 서 남 북 북동 북서 남동 남서 위 아래 (e w s n ne nw se sw u d) · 말하기(') · 대화 <NPC> [낱말] · 누구 · 도움말 · 종료` |
| `종료` | 접속을 끊는다 | `system/info` `다음에 또 뵙겠습니다.` 뒤 닫기 1000 |
| 빈 줄 | 무시 | 없음 |
| 그 밖 | — | `system/error` `무슨 말인지 모르겠습니다. ('도움말' 로 명령을 볼 수 있습니다)` |

- 위 표 전체가 (제안)이다. 문구는 룰북 `commands.md` 를 따랐고, 룰북에 없는 문구는 위에 "룰북에 아직 없음" 으로 적었다.
- `말` 은 1차에 알 수 없는 명령으로 처리한다. NPC에게 말 걸기는 2차의 `대화` 다. → [2차 명령어](#2차-명령어)
- 출력 메시지 종류와 닫기 코드는 [플랫폼: 1차 WebSocket 메시지](platform.md#1차-websocket-메시지)를 따른다.

### 같은 방 알림 문구

룰북 출력 문체(묘사는 "~다")를 따른다. 조사 `이/가` 는 이름 끝 글자의 받침으로 고른다. 문구는 룰북에 아직 없다. (제안)

- 내가 북쪽으로 떠날 때 원래 방 사람들: `한백이 북쪽으로 떠난다.`(`위로`, `아래로`. 8방위는 `동쪽으로`·`북동쪽으로` 식) (제안)
- 도착한 방 사람들: `한백이 남쪽에서 다가온다.`(도착 방향은 이동 방향의 반대. `위에서`, `아래에서`) (제안)
- 접속해 세계에 들어옴: `한백이 나타난다.` 접속 끊김: `한백이 사라진다.` (제안)
- 다른 지역의 방에 들어가면 `room.zoneEntered=true` 이고 클라이언트가 방 위에 `◇ 청석숲` 한 줄을 그린다. 룰북 `◇ 지역 (권장: …)` 의 권장 경지는 1차에 없다. 접속 직후 첫 방도 `zoneEntered=true` 다. (제안)

### 캐릭터 생성 (1차 최소)

룰북 생성 절차에서 이름과 확인만 한다. 성별·외모·출신·영근은 다음 이터레이션이다(4차에 영근을 더했다 → [캐릭터 생성 · 영근 (4차)](#캐릭터-생성--영근-4차)). → [룰북: 캐릭터 생성](../game-rule/character.md#캐릭터-생성) (제안)

- 캐릭터가 없는 계정으로 접속하면 `session(creating)` 과 `prompt` `이름을 정하십시오. (한글 2~6자)`.
- 이름 규칙은 한글 2~6자(`^[가-힣]{2,6}$`)다. 어기면 `system/error` `이름은 띄어쓰기 없이 한글 2~6자로 정하십시오.` 뒤 같은 prompt. 이미 있으면 `system/error` `이미 있는 이름입니다. 다른 이름을 정하십시오.` 뒤 같은 prompt.
- 맞으면 `prompt` `이름 한백` 과 `이대로 만들려면 '확인', 고치려면 '뒤로'.`(두 줄). `확인` 은 만들고, `뒤로` 는 이름 prompt로 돌아가고, 그 밖은 같은 확인 prompt를 다시 보낸다.
- 만들면 `system/info` `캐릭터를 만들었습니다.`, `session(playing, 한백)`, 시작 방 `room` 을 보내고 시작 방 사람들에게 `appear` 알림을 보낸다.
- 계정당 캐릭터 1개(DB 유니크)다. 2차부터 NPC 이름 검사를 한다: 이름이 NPC 이름과 같아도 `이미 있는 이름입니다. 다른 이름을 정하십시오.` 다. 금지어 검사는 아직 없고 나중 이터레이션에서 한다. → [NPC: 2차 데이터 모델](npc.md#2차-데이터-모델) (제안)
- 위 prompt·system 문구는 룰북에 아직 없다.

## 2차 명령어

2차에 더하는 명령이다. 창호가 정했다(2026-11-14). → [이터레이션 계획: 2차 범위](index.md#2차-범위-npc-배치--기본-대화--성종문-정의)

| 입력 | 하는 일 |
|---|---|
| `대화 <NPC>` | 같은 방의 NPC에게 말을 건다. NPC가 인사말과 물어볼 수 있는 낱말(`[ ]`)을 보인다 |
| `대화 <NPC> <낱말>` | 그 낱말에 대해 묻는다. 모르는 낱말이면 그 NPC의 기본 대답이 나온다 |

- 낱말 묻기 규칙은 [룰북: 말 걸기](../game-rule/npc.md#말-걸기)를 따른다. 대사(인사말, 낱말마다 대답, 기본 대답)는 관리 툴에서 입력한다. → [NPC: 고유 대사](npc.md#고유-대사)
- 1차의 `말하기`(줄임 `'`)는 그대로 같은 방 플레이어에게 말하는 채팅이다.
- 조건으로 열리는 낱말과 NPC가 알아서 말하기는 2차에 없다. NPC는 플레이어가 `대화` 를 쓸 때만 답한다.
- 출력 문구, NPC 이름 줄여 부르기, 같은 방 다른 플레이어에게 보이는지는 2차 구현에서 아래와 같이 정했다. → [2차 이터레이션 열린 질문](index.md#2차-이터레이션-열린-질문) (제안)

### `대화` 해석과 출력

아래 전체가 (제안)이다.

- 해석: 첫 낱말이 `대화` 면 다음 낱말이 NPC, 그 뒤 나머지 전부가 낱말이다. 낱말의 앞뒤 `[` `]` 는 뗀다(`대화 왕씨 [단약]` = `대화 왕씨 단약`). 떼고 나서 빈 낱말(`대화 왕씨 []`)은 낱말이 없는 것으로 보아 인사말을 낸다. 줄임말은 없다. `말` 은 1차처럼 알 수 없는 명령이다. (제안)
- 대상 찾기: 같은 방에 배치된 NPC 가운데서만 찾는다(플레이어는 대상이 아니다). 이름 전체가 같은 NPC를 먼저, 없으면 이름이 입력으로 시작하는 NPC 가운데 방 보기 순서(만든 순서) 첫째를 고른다. 영문은 대소문자를 가리지 않는다. 번호(`2.왕씨`)는 2차에 없다. (제안)
- 낱말 찾기: 저장된 낱말과 글자 그대로 같을 때만 맞는다(영문 대소문자 무시). 앞부분 일치는 하지 않는다(룰북: 앞부분 일치는 대상·물건 이름에만). 맞는 낱말이 없으면 기본 대답이다. (제안)
- 공개 범위: NPC의 대답은 **묻는 플레이어에게만** 간다. 같은 방 다른 사람은 보지 않는다. 메시지는 `talk` 다. → [플랫폼: 2차 WebSocket 메시지 변경](platform.md#2차-websocket-메시지-변경) (제안)
- LLM 대화를 켠 NPC도 같은 정해진 대사로 답한다. → [NPC: 캐릭터 챗](npc.md#캐릭터-챗) (제안)
- `보기 <NPC>` 는 1차 그대로 `아직 자세히 볼 수 없습니다.` 다. 3차에도 사람·NPC를 자세히 보지는 않는다(`보기 <대상>` 은 [3차 명령어](#3차-명령어)의 찾는 순서로 대상을 고른다). (제안)

| 입력 | 출력 |
|---|---|
| `대화 왕씨` | `talk` `왕씨: "어서 오시오."`(룰북 예시 `왕씨가 주판을 튕기며 말한다. "…"` 의 서술형과 다르다. 2차는 `이름: "인사말"` 모양만 쓴다) 그리고 낱말이 있으면 다음 줄에 `물어볼 수 있는 낱말: [단약] [일거리]`(룰북에 아직 없음. 입력 순서, 낱말마다 `[ ]`, 사이 공백 하나). 낱말이 없는 NPC면 첫 줄만 |
| `대화 왕씨 일거리` | `talk` `왕씨: "<그 낱말의 대답>"` |
| `대화 왕씨 <모르는 낱말>` | `talk` `왕씨: "<기본 대답>"` |
| `대화` | `system/error` `누구에게 말을 거시겠습니까?`(룰북에 아직 없음) |
| 같은 방에 맞는 NPC가 없음 | `system/error` `여기에 그런 상대는 없습니다.`(룰북에 아직 없음) |

- `도움말` 문구는 2차에 `대화` 를 더해 `명령: 보기(ㅂ) · 동 서 남 북 북동 북서 남동 남서 위 아래 (e w s n ne nw se sw u d) · 말하기(') · 대화 <NPC> [낱말] · 누구 · 도움말 · 종료` 다. (제안)
- play-client 자동완성 명령 목록에 `대화` 가 `말하기` 다음에 있다. 이름 후보는 마지막 방 보기의 사람과 NPC 전부다. (제안)

## 3차 명령어

3차(아이템)에 더하는 명령이다. 창호가 정했다(2026-11-14). 명령 이름과 입력 형태는 룰북을 그대로 따른다. 출력 문구·이름 찾기·같은 방 알림 같은 세부는 3차 구현에서 정해 아래에 `(제안)` 으로 적었다. → [이터레이션 계획: 3차 범위](index.md#3차-범위-아이템--영석--상점--저물대귀속--주기)

| 입력 (룰북 그대로) | 하는 일 | 룰북 |
|---|---|---|
| `줍기 <물건> [수량]` | 같은 방 바닥의 물건을 줍는다 | [물건](../game-rule/commands.md#물건), [줍기와 버리기](../game-rule/item.md#줍기와-버리기) |
| `버리기 <물건> [수량]` (영석은 `버리기 하품 10`) | 바닥에 버린다 | [물건](../game-rule/commands.md#물건), [줍기와 버리기](../game-rule/item.md#줍기와-버리기) |
| `소지품` (`ㅈ`) | 칸·영석·물건 목록을 본다 | [정보](../game-rule/commands.md#정보), [저물대 · 저물탁](../game-rule/item.md#저물대--저물탁) |
| `보기 <물건>` | 물건의 이름과 설명을 본다 | [이동 · 보기](../game-rule/commands.md#이동--보기), [방 보기](../game-rule/world.md#방-보기) |
| `목록` | 상점 NPC가 파는 물건·값과 사 주는 종류를 본다 | [NPC · 상점 · 거래](../game-rule/commands.md#npc--상점--거래), [역할별 이용](../game-rule/npc.md#역할별-이용) |
| `사기 <물건> [수량]` | 상점에서 산다 | [상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기) |
| `팔기 <물건> [수량]` | 상점에 판다 | [상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기) |
| `주기 <대상> <물건> [수량]` (영석은 `주기 한립 하품 100`) | 같은 방 플레이어에게 바로 넘긴다 | [직접 거래](../game-rule/item.md#직접-거래) |

- 상점 명령은 같은 방에 상점 NPC가 둘 이상이면 `<명령> <NPC> …` 로 지정한다(룰북). → [역할별 이용](../game-rule/npc.md#역할별-이용)
- `보기 <물건>` 은 2차까지 `아직 자세히 볼 수 없습니다.` 였다. 3차 범위의 `보기 <대상>` 은 물건 보기다. 사람·NPC를 자세히 보는 것은 창호가 정한 3차 범위에 없다.
- `값 <물건>` 과 결제의 `확인`(상위 등급 영석 깨기)도 3차에 넣었다. → [상점 명령](#상점-명령), [결제와 `확인`](#결제와-확인) (제안)
- 3차에 넣지 않는 명령: `복용`·`부적`·`진법`·`꺼내기`·`거두기`(아이템 효과), `교환`, `거래소 …`·`경매 …`·`찾기`, `수습`·`줍기 유품`(몹·사망이 없음), `제작`.
- 전투·기절이 아직 없으므로 룰북의 '전투 중에는 쓸 수 없음' 같은 상태별 막힘은 3차에 생기지 않는다. → [룰북: 상태별로 쓸 수 없는 명령](../game-rule/commands.md#상태별로-쓸-수-없는-명령)
- `도움말` 문구와 play-client 자동완성 목록에 3차 명령을 더했다. → [3차 도움말](#3차-도움말)
- 구현했다(2026-11-14). 아래 3차 절 전체가 (제안)이다. 룰북에 있는 문구는 그대로 쓰고, 룰북에 없는 문구는 각 항목에 "룰북에 아직 없음" 으로 표시했다. 룰북이 정한 것과 다르게 3차가 줄인 것(정혈 비용, `(꺼냄)`·내구도, 목록의 효과 설명)은 해당 항목에 적었다. 룰북은 고치지 않았다.

### 물건 이름 찾기와 수량

룰북 입력 문법·대상 지정을 따른다. → [룰북: 입력 문법](../game-rule/commands.md#입력-문법), [룰북: 대상 지정](../game-rule/commands.md#대상-지정) (제안)

- 인자 해석: 마지막 낱말이 `전부` 면 모두, 수(`^\d+$`)면 수량(1~999,999,999, 0이나 10자리 이상은 수량 오류), 나머지가 이름이다. 이름이 비면 인자 없음이다. 수량 오류는 `수량은 1 이상의 수로 적으십시오.`(룰북 공통 오류)다. (제안)
- 이름이 `N.이름`(N 1~999)이면 N번째 맞는 것이다. 이름이 `하품`·`중품`·`상품`·`극품` 낱말 하나면 그 영석의 전체 이름으로 본다(`버리기 하품 10`, `주기 한립 하품 100`). (제안)
- 맞는 때: 이름 전체, 이름의 앞부분, 이름을 이루는 낱말 하나의 앞부분(영문 대소문자 무시). 맞는 것이 여럿이면 번호가 없을 때 이름 전체가 같은 것을 먼저, 없으면 보이는 순서(바닥은 방 보기 순서, 소지품은 소지품 표시 순서, 상점은 목록 순서) 첫째다. 번호는 전체 일치 우선 없이 보이는 순서로 센다. 전체 일치 우선은 2차 `대화` 대상 찾기와 같게 했다. 룰북 `commands.md` 에 없는 규칙(D46)이다. (제안)
- 소지품 묶음은 (캐릭터, 아이템 종류)마다 하나로 합쳐진다. 같은 종류의 묶음이 둘로 갈리지 않으므로 고르기는 이름·번호 규칙 그대로다. (제안)
- 방에 없을 때의 오류 `이곳에 '가죽'은 없습니다.` 에 넣는 이름은 입력을 정규화한 이름이다(번호 포함, 영석 등급 낱말은 `하품 영석` 처럼 전체 이름). (제안)

### 줍기·버리기·소지품·물건 보기

- `줍기 <물건> [수량]`(수량 빼면 1, `전부` 는 바닥의 그 물건 모두): 바닥 묶음에서 찾는다. 성공 `늑대 가죽 3개를 주웠습니다.`(룰북에 아직 없음) / 일부 `저물대에 자리가 없어 늑대 가죽 3개 중 1개만 주웠습니다.`(룰북) / 하나도 못 넣음 `저물대에 자리가 없습니다.`(저물대 3개 때문이면 `저물대는 세 개까지만 찰 수 있습니다.`, 룰북에 아직 없음) / 인자 없음 `무엇을 주우시겠습니까? (예: 줍기 늑대 가죽)`(룰북) / 없음 `이곳에 '가죽'은 없습니다.`(룰북 공통 오류) / 수 넘침 `늑대 가죽은 2개뿐입니다.`. 바닥에서는 버린 것(오래된 것부터) 다음 배치(id 순)에서 덜어 낸다. 줍는 수는 `min(요청 수, 바닥 수, 소지품에 들어가는 수)` 로 먼저 정하고 그만큼 바닥에서 덜어 소지품에 넣는다. (제안)
- `버리기 <물건> [수량]`(빼면 1, `전부` 는 가진 것 모두): 성공 `늑대 이빨 4개를 버렸습니다.` / `그런 물건은 가지고 있지 않습니다.` / `늑대 이빨은 2개뿐입니다.`(이상 룰북) / 인자 없음 `무엇을 버리시겠습니까? (예: 버리기 늑대 가죽)`(룰북에 아직 없음) / 저물대를 버려 칸이 모자라게 됨 `저물대에 든 물건을 먼저 비우십시오.`(룰북에 아직 없음). 검사 순서는 없음 → 수 넘침 → 저물대 칸이다. 퀘스트 물건도 3차에는 보통 물건처럼 버린다(퀘스트 구현 때 정함). (제안)
- 거래 불가(`거래 가능` 끔) 물건도 버릴 수 있다. 버리기를 막는 것은 룰북대로 귀속·퀘스트 물건뿐이고, 버린 것을 다른 사람이 주워 가는 것(버려서 넘기기)도 허용한다. (창호, 2026-11-14) → 삭제됨 (창호, 2026-11-14)
- `소지품`(`ㅈ`): 룰북 형식을 따른다. (제안)
  ```
  [소지품 3/22칸]  하품 영석 30
  하급 저물대   회춘단(연기 초) x3   회기단(연기 초) x3
  ```
  첫 줄 `[소지품 {쓴 칸}/{전체 칸}칸]`, 영석이 있으면 두 칸 띄우고 가진 등급만 `하품 영석 132 · 중품 영석 1`. 둘째 줄부터 영석 밖 물건을 표시 순서(영석 하품 → 극품 다음 얻은 순서 = 묶음이 처음 생긴 순서)로 한 줄에 셋씩, 사이 공백 셋. 2개 이상이면 ` x{수}`. 영석도 물건도 없으면 둘째 줄 `가진 물건이 없습니다.`(룰북에 아직 없음). **룰북 예의 `(꺼냄)`·내구도는 3차에 없다.** 법기 사용·꺼내기가 생길 때 붙인다. (제안)
- `보기 <대상>`: 먼저 방의 대상을 방 보기 순서(같은 방 플레이어 → NPC → 바닥 물건)로 한 목록으로 보고 위 이름 찾기 규칙으로 고른다. 방에 맞는 것이 없으면 내 소지품(표시 순서)에서 찾는다(룰북 대상 지정: 대상은 방에서, 물건은 소지품에서, 여럿이면 방 보기에 보이는 순서로 첫째). 고른 것이 물건이면 `늑대 가죽 — 거칠고 질긴 늑대의 가죽이다.`(묘사가 비면 이름만, tone `item`), 사람·NPC면 2차 그대로 `아직 자세히 볼 수 없습니다.`(info), 아무것도 아니면 `그런 것은 보이지 않습니다.`(룰북, error)다. 방에 없는 사람에게 `보기` 하면 이제 `그런 것은 보이지 않습니다.` 다(2차는 `아직 자세히 볼 수 없습니다.`). (제안)

### 상점 명령

룰북 문구를 그대로 쓰고 룰북에 없는 문구는 "룰북에 아직 없음" 으로 표시한다. `{NPC}:` 자리는 그 상점 NPC 이름이다(룰북 `상인:`·`왕씨:` 자리). 상점 명령은 묻는 사람에게만 답한다(같은 방 알림 없음). → [룰북: 상점에서 사고팔기](../game-rule/item.md#상점에서-사고팔기), [룰북: 역할별 이용](../game-rule/npc.md#역할별-이용) (제안)

- **상점 고르기:** 같은 방의 상점 NPC(배치 순 = id 순)다. 없으면 `이곳에서는 할 수 없습니다.`(룰북 공통 오류). 하나면 NPC 이름을 빼고, 인자 첫 낱말이 그 NPC 이름 전체와 같으면 떼어 낸다. 둘 이상이면 첫 낱말이 상점 NPC 이름(전체 또는 앞부분, 2차 `대화` 규칙)이어야 하고 아니면 `상인이 여럿입니다. 상인 이름을 붙이십시오: 왕씨 · 이씨`(룰북에 아직 없음). `목록` 은 물건 인자가 없으므로, 인자가 있는데 상점 NPC 이름(전체 또는 앞부분)에 맞지 않으면 상점이 하나여도 `여기에 그런 상대는 없습니다.`(2차 `대화` 문구)다. (제안)
- `목록 [NPC]`: 상점 이름은 `{NPC 이름} {상점 종류}`(룰북 목록 머리 `[왕씨 단약방]`)다. 파는 물건이 없으면 둘째 줄 `  파는 물건이 없습니다.`, 사 주는 것이 없으면 `사 주는 것: 없음`(둘 다 룰북에 아직 없음). **3차 목록에는 룰북 예의 `(기혈 회복)` 효과 설명과 칸 맞춤 공백이 없다**(효과가 없다). 이름 뒤 두 칸 띄우고 값을 적는다. 효과가 생기면 붙인다. (제안)
  ```
  [왕씨 단약방]  파는 것  값(하품)
    1. 회춘단(연기 초)  3
    2. 회기단(연기 초)  4
  사 주는 것: 단약·영약
  ```
- `사기 [NPC] <물건> [수량]`(수량 빼면 1, `전부` 는 수량 오류): 상점의 파는 물건에서 이름으로 찾는다. 성공 `회춘단(연기 초) 5개를 샀습니다. (하품 영석 -15)`. 실패 순서: 인자 없음 `무엇을 사시겠습니까? (예: 사기 회춘단 5)`(룰북에 아직 없음) → 수량 오류 → 없는 물건 `왕씨: "그런 물건은 팔지 않소."` → `영석이 모자랍니다. (필요 15, 가진 것 9)`(가진 것 = 하품 기준 합) → `저물대는 세 개까지만 찰 수 있습니다.` → `저물대에 자리가 없습니다.` → `거스름을 받을 자리가 없습니다. (하품 9,880개, 1칸 필요)`(칸 수는 거스름까지 넣으면 실제로 모자란 칸) → 상위 등급 확인(아래). (제안)
- `팔기 [NPC] <물건> [수량]`(빼면 1, `전부` 는 가진 것 모두): 내 소지품에서 찾는다. 성공 `늑대 가죽 10개를 팔았습니다. (하품 영석 +8)`. 상점이 주는 영석은 하품뿐이다(룰북: 얻는 영석의 등급). 실패 순서: 인자 없음 `무엇을 파시겠습니까? (예: 팔기 늑대 가죽 3)`(룰북에 아직 없음) → 수량 오류 → `그런 물건은 가지고 있지 않습니다.` → 영석 `왕씨: "그런 물건은 받지 않소."` → 퀘스트 물건 `왕씨: "그건 내가 살 물건이 아니오."`(종류별 매입 비율 표 값, 지금 문구 유지) → 종류가 사 주는 것에 없음 `왕씨: "그런 물건은 받지 않소."` 와, 그 종류를 사 주는 상점 종류가 있으면(표 순서 첫째) 뒤에 ` (재료는 재료상에 팔 수 있습니다)` → `늑대 가죽은 2개뿐입니다.` → 매입가 합계(내림) 1 미만 `왕씨: "값이 너무 적어 사 줄 수가 없소. 더 모아 오시오."` → 저물대를 팔아 칸이 모자라게 됨 `저물대에 든 물건을 먼저 비우십시오.` → 받을 하품이 들어갈 칸 없음 `저물대에 자리가 없습니다.`. (제안)
- `값 [NPC] <물건> [수량]`: `늑대 가죽 1개에 하품 영석 0.8 — 10개면 8`. 개당 값은 소수 끝 0을 지운 값(`0.75`, `10`), 뒤의 수는 적은 수량이고 없으면 가진 수다. 실패는 `팔기` 와 같은 순서·문구다(인자 없음은 `무엇의 값을 보시겠습니까? (예: 값 늑대 가죽)`, 수 넘침 검사와 1 미만 검사는 하지 않는다). 룰북 역할별 이용에 있고 새 규칙이 없어 3차에 넣었다. (제안)
- 매입가는 룰북 식(하계 기준가 × 매입 비율 × 1.0)이고 입력받지 않는다. 판매가는 상점이 정한 값 또는 기준가다. → [NPC: 3차 상점 역할 데이터](npc.md#3차-상점-역할-데이터) (제안)

### 결제와 `확인`

룰북 [결제](../game-rule/item.md#결제)를 그대로 따른다. 3차에 결제를 쓰는 곳은 `사기` 뿐이다. (제안)

- 하품 → 중품 → 상품 → 극품 순으로, 그 등급으로 남은 값을 다 낼 수 있으면 필요한 만큼만(올림) 내고 끝낸다. 다 내도 모자라면 그 등급을 모두 내고 다음 등급으로 넘어간다. 낸 값이 가격보다 많으면 남은 값을 하품으로 거슬러 받는다. 등급 가치는 하품 1·중품 100·상품 10,000·극품 1,000,000. 하품 기준 합이 가격보다 적으면 결제하지 않는다. (제안)
- **거스름 넘침을 검사한다.** 거스름 하품이 칸에 다 들어가지 않으면 결제하지 않는다(위 `거스름을 받을 자리가 없습니다.`). (제안)
- **상위 등급 깨기 확인을 한다.** 결제에서 상품·극품을 **실제로 깰 때**(그 돌에서 거스름이 나올 때)만 사기 전에 묻는다. 중품은 묻지 않는다. 값에 그대로 다 쓰면(예: 상품 1로 10,000, 거스름 0) 묻지 않는다. 거스름은 마지막으로 낸 등급에서만 나오므로 깨는 등급은 많아야 하나다. 문구: `값을 치르려면 상품 영석 1개를 깨야 합니다. 거스름 하품 9,880개를 받습니다. 계속하려면 '확인'.`(룰북). 깨는 돌이 있으면 거스름은 늘 0보다 크고 깨는 등급은 하나뿐이라, 계획에 있던 여러 등급을 `, ` 로 잇는 경우와 거스름 0 일 때 문장을 빼는 경우는 생기지 않는다. (제안)
- `확인`: 10초 안(정확히 10초까지 유효)이면 같은 상점·같은 물건·같은 수로 지금 값을 다시 계산해 확인 없이 산다(그 사이 바뀐 것은 다시 검사해 해당 실패 문구를 보인다. 상점이 방에 없거나 상점이 아니면 `이곳에서는 할 수 없습니다.`, 그 물건을 더 팔지 않으면 `{NPC}: "그런 물건은 팔지 않소."`). 확인 대기는 하나만이고, `확인`·`취소` 가 아닌 명령이 오면 조용히 취소된다(빈 입력은 명령이 아니므로 취소하지 않는다). 10초가 지났거나 대기가 없으면 `확인할 것이 없습니다.`(룰북에 아직 없음, error). `취소` 는 `그만두었습니다.`(룰북, info)이고 대기가 없으면 `그만둘 것이 없습니다.`(룰북에 아직 없음, error)다. → [룰북: 확인이 필요한 명령](../game-rule/commands.md#확인이-필요한-명령) (제안)
- 시계는 주입한 `Clock` 이라 테스트가 시간을 앞당길 수 있다. → [플랫폼: 3차 월드 상태와 저장](platform.md#3차-월드-상태와-저장) (제안)

### 귀속

`귀속`·`귀속 해제` 명령은 지금 없다. 치면 다른 모르는 명령과 같은 응답(지금의 모르는 명령 문구)이다. → [룰북: 귀속](../game-rule/item.md#귀속) (제안) (창호, 2026-11-14)

### 주기

`주기 <대상> <물건> [수량]`(영석은 `주기 한립 하품 100`). 수수료 없음, 성 밖에서도 된다. → [룰북: 직접 거래](../game-rule/item.md#직접-거래) (제안)

- 대상: 같은 방에 접속해 있는 다른 플레이어(들어온 순서)다. 이름 전체가 같으면 그 사람, 없으면 이름이 입력으로 시작하는 첫 사람이다(앞부분 일치는 나보다 다른 사람을 먼저 고르고, 앞부분이 내 이름일 때만 나). 없으면(접속 안 함·다른 방·NPC·생성 중) `여기에 한립은 없습니다.`(룰북, 입력 그대로 + `은/는`)다. 내 이름이면 `자기 자신에게는 줄 수 없습니다.`(룰북에 아직 없음). (제안)
- 받는 쪽 칸이 모자라면 넘어가지 않는다(룰북). 문구: 주는 쪽 `한립에게 회춘단 2개를 주었습니다.` / 받는 쪽 `여소이가 회춘단 2개를 건넸습니다.` / `한립의 저물대에 자리가 없습니다.`(이상 룰북). 새 문구(룰북에 아직 없음): 인자 없음 `누구에게 무엇을 주시겠습니까? (예: 주기 한립 회춘단 2)`, 받는 쪽 저물대 3개 `한립은 저물대를 더 찰 수 없습니다.`, 주는 쪽이 저물대를 줘 칸이 모자라게 됨 `저물대에 든 물건을 먼저 비우십시오.`. (제안)
- 검사 순서: 대상이나 물건 인자 없음 → 수량 오류 → 대상 없음 → 자기 자신 → 내 소지품에 물건 없음 → 수 넘침(`…은 2개뿐입니다.`) → 주는 쪽 저물대 칸 → 받는 쪽 저물대 3개 → 받는 쪽 칸. (제안)

### 3차 같은 방 알림

줍기·버리기·주기는 같은 방 다른 사람에게 알린다(새 `notice` tone `item`). 문구는 룰북에 아직 없다: `한립이 늑대 가죽 2개를 줍는다.` / `한립이 늑대 가죽 1개를 버린다.` / `여소이가 한립에게 회춘단 2개를 건넨다.`(주는 사람·받는 사람 빼고). 사기·팔기·값·목록·소지품·보기는 알리지 않는다(상점 거래는 룰북에서 상인과 나 사이의 일이다). 바닥이 바뀌어도 같은 방 사람의 방 보기를 다시 보내지 않고 이 알림만 보낸다. 조사는 [1차 같은 방 알림 문구](#같은-방-알림-문구)와 같이 이름 끝 글자의 받침으로 고른다. (제안)

### 3차 도움말

`도움말` 문구는 3차에 물건 명령을 더해 다음과 같다. 룰북에 아직 없다. (제안)

`명령: 보기(ㅂ) · 동 서 남 북 북동 북서 남동 남서 위 아래 (e w s n ne nw se sw u d) · 말하기(') · 대화 <NPC> [낱말] · 소지품(ㅈ) · 보기 <물건> · 줍기 <물건> [수량] · 버리기 <물건> [수량] · 주기 <대상> <물건> [수량] · 목록 · 사기 <물건> [수량] · 팔기 <물건> [수량] · 값 <물건> · 확인 · 취소 · 누구 · 도움말 · 종료`

- play-client 자동완성 `COMMANDS` 순서: `보기 말하기 대화 소지품 줍기 버리기 주기 목록 사기 팔기 값 확인 취소 누구 도움말 종료` + 방위. `귀속`·`귀속 해제` 는 지운 명령이라 넣지 않는다. 이름 후보는 마지막 `room` 의 occupants 이름 + 바닥 물건 이름이다(`notice` 의 `pick`·`drop`·`give` 는 후보를 바꾸지 않는다). → [플랫폼: 플레이 화면](platform.md#플레이-화면-play-client) (제안)
- 4차 도움말은 [4차 도움말](#4차-도움말)에 있다.

## 4차 명령어

4차(경지·스탯·공법 배우기)에 더하는 명령과 바뀌는 흐름이다. 범위는 고나가 창호 원문을 해석한 것이고 창호 확인 전이다. → [이터레이션 계획: 4차 범위](index.md#4차-범위-경지스탯--임의-경지-상승--공법신통-배우기). 명령 이름과 입력 형태는 룰북을 그대로 따른다. 아래 4차 절 전체가 (제안)이다. 룰북에 있는 문구는 그대로 쓰고, 룰북에 없는 문구는 "룰북에 아직 없음" 으로 표시했다.

| 입력 (룰북 그대로) | 하는 일 | 룰북 |
|---|---|---|
| `상태` (`ㅅ`) | 경지·영근·스탯·수위·깨달음을 본다 | [정보](../game-rule/commands.md#정보) |
| `공법` | 익힌 공법과 단계, 다음 단계 필요 깨달음을 본다 | [정보](../game-rule/commands.md#정보) |
| `신통` | 배운 신통을 공법마다 본다 | [정보](../game-rule/commands.md#정보) |
| `읽기 <물건>` | 소지품의 옥간·서책을 읽어 공법을 익힌다 | [성장](../game-rule/commands.md#성장), [공법](../game-rule/technique.md#공법) |

- 공통: 수는 천 단위 쉼표를 넣어 보인다(`11,000`). 시간은 룰북 출력 문체를 따른다(60초 미만은 초, 끝 0을 지워 `3초`·`1.5초`, 그 이상은 `1분`·`7분 12초`, 60분 이상은 `1시간`·`1시간 5분`). 경지 이름은 `범인`, `연기 1층` ~ `연기 13층`, `축기 초기`·`축기 중기`·`축기 후기`·`축기 대원만` 이다. 오행 순서는 금 → 목 → 수 → 화 → 토다. → [룰북: 출력 문체](../game-rule/commands.md#출력-문체) (제안)
- `상태`·`공법`·`신통` 은 정보 명령이고 같은 방 알림이 없다. 결과는 `상태` 만 `status` 메시지, 나머지는 `system/info` 다. `읽기` 의 성공은 `system` tone `growth`, 거절은 `system/error` 다. → [플랫폼: 4차 WebSocket 메시지 변경](platform.md#4차-websocket-메시지-변경) (제안)
- 4차에 넣지 않는 명령: `참오`, `서재`·`서재 익히기`, `읽기 확인`(서재가 없음 — 치면 `읽기` 가 `확인` 이라는 물건을 찾아 `그런 물건은 가지고 있지 않습니다.`), `산공`, `돌파`·`돌파 시작`·`돌파 중단`, 신통 이름 명령(신통 쓰기), `고르기`·`튜토리얼 건너뛰기`. (제안)
- 전투·기절·돌파가 아직 없어 룰북의 '전투 중에는 `읽기` 불가' 같은 막힘은 4차에 생기지 않는다. 범인 막힘은 상점만 한다 → [범인의 상점 막힘](#범인의-상점-막힘). (제안)

### 캐릭터 생성 · 영근 (4차)

[1차 최소 생성](#캐릭터-생성-1차-최소)에 룰북 영근 단계를 더한다. 4차 절차는 이름 → 영근 → 확인이다. 성별·외모·출신은 아직 없다. → [룰북: 생성 절차](../game-rule/character.md#생성-절차), [룰북: 영근 · 영근 자질](../game-rule/stats.md#영근--영근-자질) (제안)

- 이름이 맞으면 `prompt` `영근을 고르십시오. 오행(금 목 수 화 토) 가운데 1~5개를 띄어 쓰십시오.`(룰북). (제안)
- 영근 입력: 공백으로 나눈 낱말이 모두 `금` `목` `수` `화` `토` 가운데 하나이고, 1~5개이고, 겹치지 않아야 한다. 어기면 `system/error` `오행(금 목 수 화 토) 가운데 1~5개를 겹치지 않게 띄어 쓰십시오.`(룰북에 아직 없음) 뒤 같은 prompt. `뒤로` 는 이름 prompt로 돌아간다. (제안)
- 맞으면 `prompt` 여러 줄(룰북 예의 모양, 4차에 있는 칸만):
  ```
  목·화 진영근 — 목 50, 화 50
  ────────
  이름 한백 · 영근 목·화 진영근 (목 50, 화 50)
  이대로 만들려면 '확인', 고치려면 '뒤로'.
  ```
  영근 이름은 개수로 정한다(1개 천영근, 2~3개 진영근, 4~5개 위영근 — 룰북). 오행은 입력 순서와 상관없이 오행 순서로 `·` 로 잇는다. 자질은 100 ÷ 개수를 소수 그대로 저장하고 화면에는 소수점을 버린다(3개면 `금 33, 목 33, 수 33`). `확인` 은 만들고, `뒤로` 는 영근 prompt로 돌아가고, 그 밖은 같은 확인 prompt를 다시 보낸다. (제안)
- 만든 캐릭터의 경지는 범인이다(룰북). 만든 뒤 출력은 1차와 같다(`캐릭터를 만들었습니다.` → `session(playing)` → `room` → `appear`). (제안)
- **영근이 없는 기존 캐릭터:** 4차 전에 만든 캐릭터는 영근이 없다. 접속하면 세계에 들어가기 전에 `session(creating, 한백)`, `system/info` `영근을 아직 정하지 않았습니다. 영근을 고르면 세계에 들어갑니다.`(룰북에 아직 없음), 위 영근 prompt를 보낸다. 입력 규칙은 같고, 이때 `뒤로` 는 같은 영근 prompt를 다시 보낸다(이름 단계가 없다). 확인 prompt는 위와 같되 마지막 줄이 `이대로 정하려면 '확인', 고치려면 '뒤로'.`(룰북에 아직 없음)다. `확인` 하면 `system/info` `영근을 정했습니다.`(룰북에 아직 없음), `session(playing, 한백)`, 지금 방 `room`, 같은 방 `appear` 알림 — 보통 접속과 같다. 영근을 정하기 전에 접속을 끊으면 다음 접속에 다시 묻는다. 영근을 고르는 중에 같은 계정이 다시 접속하면(앞 연결 4409) 새 연결은 영근 단계를 처음(안내·영근 prompt)부터 다시 받는다. 새 캐릭터 생성 중에도 같다(이름 prompt부터). (제안)
- 정한 영근은 게임에서도 관리 툴에서도 바꿀 수 없다(룰북: 확인한 뒤에는 바꿀 수 없다). 영근 추가(개령과)는 4차에 없다. (제안)

### 상태

룰북 [정보 명령 출력 형식](../game-rule/commands.md#정보)을 따르고 4차에 값이 있는 줄만 쓴다. `status` 메시지의 `text` 다. (제안)

```
> 상태
한백 · 연기 1층 · 목·화 진영근 (목 50, 화 50)
기혈  60 / 60     법력  25 / 25
의식  20 / 20     정혈  20 / 20
육신  6   근력  3   영력  5 / 5
수위  0 / 190
깨달음  금 0 · 목 0 · 수 0 · 화 0 · 토 0 · 연체 0
```

- 줄 순서는 룰북 그대로다: 이름·경지·영근 → 소모 스탯 → 포인트 스탯 → 수위 → 깨달음. 룰북 첫 줄의 성별은 4차에 없어 뺀다. 영기·지속 효과 줄, 전투 줄, `(경지 안정 중 …)`·`(정혈로 -12)`·`[기절 4초]` 같은 상황 표시는 4차에 생기지 않는다. (제안)
- 영근은 [생성](#캐릭터-생성--영근-4차)과 같은 모양이고 자질은 처음 자질 + 익힌 공법 단계의 영근 자질 증가다(소수점 버림). (제안)
- 사이 공백은 룰북 예와 같은 자리에 같은 수(이름과 값 사이 두 칸, 소모 스탯 두 칸 사이 다섯 칸, 포인트 스탯 사이 세 칸)로 넣고 자릿수 맞춤은 하지 않는다. (제안)
- 현재 수치는 4차에 늘 최대치다(깎는 것이 없음). 값의 계산은 [플랫폼: 4차 월드 상태와 저장](platform.md#4차-월드-상태와-저장)을 따른다. (제안)
- **수위 줄**은 4차에 수위를 쌓는 길이 없어 늘 `0 / {지금 소경지 필요 수위}` 다(룰북 [소경지 필요 수위](../game-rule/realm.md#소경지-필요-수위) 표: 연기 1층 190 … 13층 11,000, 축기 초기 47,000 … 대원만 120,000). 범인은 필요 수위가 없어(입문으로 연기 1층이 됨) 수위 줄을 뺀다. 룰북의 `(이번 층 단약 수위 40 / 210)` 은 단약 효과가 없어 붙이지 않는다. (제안)
- **깨달음 줄**은 4차에 깨달음을 쌓는 길이 없어 늘 모두 0이다(룰북 형식대로 보인다). (제안)
- 범인 예: `한백 · 범인 · 화 천영근 (화 100)` / `기혈  10 / 10     법력  0 / 0` / `의식  10 / 10     정혈  10 / 10` / `육신  1   근력  1   영력  0 / 0` / (수위 줄 없음) / 깨달음 줄. (제안)

### 공법 · 신통

`system/info` 여러 줄이다. 룰북 [정보 명령 출력 형식](../game-rule/commands.md#정보)을 따르되, 칸 맞춤 공백은 3차 `목록` 처럼 하지 않고 사이를 두 칸으로 띄운다. (제안)

```
> 공법
장춘공  1/9성 · 목 · 오행  다음 2성: 목 깨달음 120 (지금 0)
강체결  1/9성 · 연체  다음 2성: 연체 깨달음 530 (지금 0)
> 신통
[장춘공 1성]
  화탄술  공격·화  법력 5  대기 3초
[강체결 1성]
  철권  공격·연체  법력 없음  대기 4초
```

- `공법`: 익힌 순서로 한 줄씩 `{이름}  {단계}/{단계 수}성 · {속성} · 오행  다음 {k+1}성: {속성} 깨달음 {필요} (지금 0)`. 속성은 오행 순서로 `·` 로 잇고(`화·토`), 연체술은 룰북 예처럼 `· 연체` 만 쓴다. 여러 속성이면 필요 깨달음 합을 속성 수로 나눠 `다음 2성: 화 깨달음 200 (지금 0) · 토 깨달음 200 (지금 0)`. 끝 단계면 `다음 …` 대신 ` · 끝에 이름`(룰북 `9/9성 · 끝에 이름`)을 성 뒤에 이어 쓴다. 지금 경지가 그 공법의 시작 경지보다 낮으면(관리 툴로 경지를 내린 때) 끝에 `  (연기 7층 필요)`(룰북)를 붙인다. 룰북의 `(서재에 익히지 않은 공법 1개 — '서재')` 줄은 서재가 없어 없다. 익힌 공법이 없으면 `익힌 공법이 없습니다.`(룰북에 아직 없음). (제안)
- `신통`: 익힌 공법마다 머리 `[{공법} {단계}성]`, 그 아래 두 칸 들여 배운 신통(배우는 단계 ≤ 지금 단계)을 정의 순서로 `{이름}  {종류}·{속성}  {소모}  대기 {시간}`. 속성이 없는 신통은 `·{속성}` 을 뺀다. 소모는 `법력 5`, 틱마다면 `의식 1 (틱마다)`, 소모가 없으면 `법력 없음`(룰북 법기 줄 문구). 시전 시간이 0보다 크면 소모와 대기 사이에 `시전 2초`(룰북). 재사용 대기 남은 시간과 `[법기 · 꺼낸 것]` 묶음은 신통 쓰기·법기가 없어 없다. 배운 신통이 없으면 `배운 신통이 없습니다.`(룰북에 아직 없음). (제안)
- 룰북 공법 목록의 철권 종류 `연체술 공격` 은 종류 `공격` + 속성 연체로 정의하고 `공격·연체` 로 보인다(룰북 경지·종류별 기준값 표의 '연체술 공격' = 공격 + 연체). (제안)
- 종류 이름은 룰북 [신통이 가지는 것](../game-rule/technique.md#신통이-가지는-것)의 낱말(`공격` `범위 공격` `방어` `회피` `치료` `둔술` `탐지` `은신` `렴기` `보조`)이다. (제안)

### 읽기

`읽기 <물건>` 은 내 소지품에서 3차 [물건 이름 찾기](#물건-이름-찾기와-수량)로 찾는다(번호 `2.옥간` 은 받고, 수량은 받지 않아 인자 전체가 이름이다). 한 번에 1개를 읽는다. → [룰북: 공법](../game-rule/technique.md#공법), [룰북: 성장](../game-rule/commands.md#성장) (제안)

- 검사 순서와 거절 문구(모두 `system/error`, 물건은 그대로 남는다). 처음 걸린 것만 알린다. 순서는 룰북 `참오` 의 순서(익혔는가 → 시작 경지 → 자질)를 따랐다. (제안)
  1. 인자 없음: `무엇을 읽으시겠습니까? (예: 읽기 장춘공 옥간)`(룰북에 아직 없음 — 공통 오류의 '동사와 예를 바꾼다')
  2. 소지품에 없음: `그런 물건은 가지고 있지 않습니다.`(룰북)
  3. 종류가 옥간·서책이 아님: `읽을 수 있는 물건이 아닙니다.`(룰북에 아직 없음)
  4. 담긴 공법이 없음: `아무것도 적혀 있지 않습니다.`(룰북에 아직 없음)
  5. 이미 익힌 공법: `이미 깨친 내용입니다. (장춘공 1/9성)`(룰북 잔엽 문구 `이미 깨친 내용입니다. (청원검결 3/9장)` 의 모양)
  6. 지금 경지 < 시작 경지: `지금은 이 공법을 익힐 수 없습니다. (연기 7층 필요)`(룰북 문구의 앞부분. 뒤의 `그래도 읽어 서재에 남기려면 '읽기 확인'.` 은 서재가 없어 뺀다)
  7. 공법 속성의 영근이 없음(오행 순으로 첫째): `지금은 이 공법을 익힐 수 없습니다. (화영근 필요)`(룰북에 아직 없음)
  8. 1성 영근 자질 조건 미달(오행 순으로 첫째, 내부 소수 그대로 비교, 화면은 소수점 버림): `지금은 이 공법을 익힐 수 없습니다. (화영근 자질 40 필요, 지금 33)`(룰북에 아직 없음)
- 연체술 공법은 7·8을 건너뛴다(룰북: 영근·자질 조건 없음). (제안)
- **성공**: 그 물건 1개를 소지품에서 빼고, 그 공법을 1성으로 익힌다(익힌 순서 = 이 순간). 1성 신통을 배우고, 1성 스탯 증가가 있으면 더해진다. 같은 트랜잭션에서 한다. 출력은 `system` tone `growth` 여러 줄이다. (제안)
  ```
  옥간을 이마에 대자 구결이 머릿속으로 흘러든다. 장춘공 1성에 이르렀습니다!
  새 신통을 깨쳤습니다: 화탄술
  ```
  - 첫 줄은 룰북 문구다. 서책도 같은 문구를 쓴다(옥간·서책이 한 종류이고 서책 문구가 룰북에 없음). (제안)
  - 1성 스탯 증가가 있으면 둘째 줄에 `법력 +2 · 목영근 자질 +1` 처럼 0이 아닌 것만 룰북 `참오` 출력 순서(법력 · 의식 · 영력 · 정혈 · 육신 · 근력 · 영근 자질)로 넣는다. 보통 1성은 비어 있어 이 줄이 없다(룰북 공법 표). (제안)
  - 줄 순서: 첫 줄 → 스탯 줄(있으면) → 신통 줄 또는 입문 줄. (제안)
  - 신통 줄은 룰북 `참오` 문구 `새 신통을 깨쳤습니다: 어풍결` 이다. 여럿이면 `, ` 로 잇는다. (제안)
  - **범인이 입문 공법(시작 경지 범인)을 읽으면** 경지가 연기 1층이 되고, 신통 줄 대신 룰북 튜토리얼 문구 `단전에 따뜻한 기운이 맺힌다. 연기 1층이 되었습니다. 새 신통: 화탄술` 을 쓴다(신통 여럿이면 `, `). 연기 1층 스탯은 바로 다 찬다(룰북 [입문](../game-rule/character.md#입문)). 범인이 아니면 입문 공법을 읽어도 경지는 그대로다. (제안)
- 같은 방 알림은 없다. (제안)
- 익힐 수 있는 공법 수에는 제한이 없다(룰북). (제안)
- `보기 <옥간>` 은 3차 물건 보기 줄 다음에 담긴 공법이 있으면 둘째 줄 `담긴 공법: 장춘공 (목 · 오행 · 9성 · 범인부터)`(룰북에 아직 없음, 연체술은 `(연체술 · 9성 · 범인부터)`)을 붙인다. 읽기 전에 조건을 알 수 있게 하려는 것이다. (제안)

### 범인의 상점 막힘

룰북 [상태별로 쓸 수 없는 명령](../game-rule/commands.md#상태별로-쓸-수-없는-명령)의 범인 줄 가운데 4차에 있는 명령은 상점 명령뿐이다. 경지가 범인이면 `목록`·`사기`·`팔기` 는 다른 검사보다 먼저 `system/error` `아직 범인의 몸이라 할 수 없습니다.`(룰북)다. `값`·`취소` 와 결제 밖 `확인` 은 룰북 목록에 없어 막지 않는다. 청우촌 밖 이동 막힘(마을 어귀 NPC 대사)은 튜토리얼과 함께 붙인다. 3차 완료 시나리오의 상점 단계는 이제 입문(연기 1층)한 캐릭터나 4차 전 캐릭터로 한다. 3차 스모크·E2E 의 상점 단계는 상점을 쓰기 전에 그 캐릭터를 관리 툴 `PUT /api/admin/characters/{id}/realm` 으로 `QI_1` 로 지정하거나 입문 옥간을 읽게 고친다(리드 판정 L1). 1·2·3차 테스트의 캐릭터 생성 단계에는 영근 입력(예 `목 화`)을 끼운다. 결제 `확인` 이 사기를 다시 계산할 때도 범인이면 `아직 범인의 몸이라 할 수 없습니다.` 다(확인 대기 10초 안에 관리자가 범인으로 내린 경우). (제안)

### 경지가 바뀔 때

관리 툴에서 경지를 지정하면(→ [관리 툴: 4차 화면](admin-tool.md#4차-화면)) 커밋 뒤 접속 중인 그 캐릭터에게 `system` tone `growth` 한 줄을 보낸다. 경지가 같으면 보내지 않는다. 같은 방 알림은 없다. (제안)

- `경지가 연기 7층으로 바뀌었습니다. (육신 +6, 근력 +3, 영력 +6, 의식 +12, 정혈 +12)`(룰북에 아직 없음). 괄호 안은 경지 몫 스탯의 차이를 룰북 [소경지 상승](../game-rule/realm.md#소경지-상승) 출력 순서(육신 · 근력 · 영력 · 의식 · 정혈)로, 0이 아닌 것만, 내리면 `-` 로 적는다. 조사 `으로/로` 는 경지 이름 끝 글자의 받침으로 고른다(받침이 없거나 ㄹ이면 `로`: `축기 초기로`). (제안)
- 룰북 소경지 상승 문구(`몸 안의 영력이 크게 한 바퀴 돌며 …`, `영력이 새 경지에 자리 잡는 중입니다.`)와 같은 방 `○○의 기운이 한층 짙어진다.` 는 정식 소경지 상승의 것이라 쓰지 않는다. (제안)
- 경지를 내려 익힌 공법의 시작 경지보다 낮아져도 공법·신통은 그대로다(`공법` 에 `(… 필요)` 가 붙음). 저물탁 칸이 닫혀 소지품이 칸을 넘을 수 있다 → [저물탁](#저물탁). (제안)

### 저물탁

3차에서 미룬 저물탁을 더한다. → [룰북: 저물대 · 저물탁](../game-rule/item.md#저물대--저물탁), [관리 툴: 저물탁](admin-tool.md#저물탁) (제안)

- 저물탁은 1개까지 가진다(저물대 3개와 따로 센다). 이미 1개면 줍기·사기·받기에서 더 얻지 못한다: `저물탁은 하나까지만 찰 수 있습니다.`(룰북에 아직 없음), 주기에서 받는 쪽 `한립은 저물탁을 더 찰 수 없습니다.`(룰북에 아직 없음). 검사 자리는 3차 저물대 3개 검사와 같다. (제안)
- 경지가 축기 초기 이상일 때만 저물탁 칸이 소지품 칸에 더해진다. 아래면 가지고 다니고 버리고 팔고 줄 수 있지만 칸은 0이다. 저물탁 자체는 칸을 차지하지 않는다(룰북). (제안)
- 저물탁을 버리거나 팔거나 줘서 칸 합이 쓰는 칸보다 작아지면 `저물탁에 든 물건을 먼저 비우십시오.`(룰북에 아직 없음)다. (제안)
- 관리 툴로 경지를 축기 아래로 내려 칸이 쓰는 칸보다 작아지면 물건은 그대로 두고 칸을 넘은 채로 둔다(`[소지품 130/22칸]`). 그동안 물건이 늘어나는 것(줍기·사기·받기)은 남은 칸이 없어 되지 않고, 줄이는 것은 된다. (제안)
- `소지품` 에서 칸이 닫힌 저물탁 뒤에 ` (축기 초기 필요)`(룰북에 아직 없음)를 붙인다. (제안)

### 4차 도움말

`도움말` 문구는 4차 명령을 더해 다음과 같다. 룰북에 아직 없다. (제안)

`명령: 보기(ㅂ) · 동 서 남 북 북동 북서 남동 남서 위 아래 (e w s n ne nw se sw u d) · 말하기(') · 대화 <NPC> [낱말] · 상태(ㅅ) · 공법 · 신통 · 읽기 <물건> · 소지품(ㅈ) · 보기 <물건> · 줍기 <물건> [수량] · 버리기 <물건> [수량] · 주기 <대상> <물건> [수량] · 목록 · 사기 <물건> [수량] · 팔기 <물건> [수량] · 값 <물건> · 확인 · 취소 · 누구 · 도움말 · 종료`

- play-client 자동완성 `COMMANDS` 순서: `보기 말하기 대화 상태 공법 신통 읽기 소지품 줍기 버리기 주기 목록 사기 팔기 값 확인 취소 누구 도움말 종료` + 방위. 이름 후보는 3차 후보에 마지막 `inventory` 의 물건 이름(`items[].name`)을 더한다(`읽기` 대상이 소지품이기 때문). (제안)
- 저장소 README의 명령 목록도 이 도움말과 같게 고친다. (제안)
