# NPC

NPC의 대사, 동료 합류, 캐릭터 챗, 함께 쌓는 내러티브. → [목차](index.md)

**이 게임의 핵심 재미 중 하나다.**

NPC 게임 규칙(유니크 NPC·몹, 말 걸기)은 [룰북: NPC](../game-rule/npc.md), 동료 NPC의 전투·회복 규칙은 [룰북: 파티 — 동료 NPC](../game-rule/party.md#동료-npc)를 따른다.

## 데이터 관리

- NPC와 내러티브는 DB(PostgreSQL)로 관리한다. 저장 방식은 (미정). → [플랫폼](platform.md)
- NPC마다 장기 메모리로 기억이 필요하다. → [함께 쌓는 내러티브](#함께-쌓는-내러티브)

## 생성과 배치

- NPC는 관리 툴에서 생성하고 배치한다. → [관리 툴](admin-tool.md)
- 2차의 NPC는 모두 유니크 NPC(세계에 하나)이고 방 하나에 고정한다. 같은 NPC 여러 마리, 구역을 돌아다니는 NPC는 2차에 넣지 않는다(창호, 2026-11-14). → [2차 범위](index.md#2차-범위-npc-배치--기본-대화--성종문-정의)

## 고유 대사

- NPC는 저마다 고유의 대사가 있다.
- 대사 내용은 관리 툴에서 입력한다. (데이터 주도 원칙 → [관리 툴](admin-tool.md#데이터-주도-콘텐츠))
- 대사는 룰북의 낱말 묻기 방식([말 걸기](../game-rule/npc.md#말-걸기))으로 입력한다. 관리 툴에서 인사말, 낱말마다 대답, 모르는 낱말에 하는 기본 대답을 입력한다(창호, 2026-11-14).
- 2차에는 조건(단서·경지·종문·퀘스트 단계)으로 열리는 낱말과 NPC가 알아서 말하기(60초마다 무작위 대사)를 넣지 않는다. NPC는 플레이어가 `대화` 로 말을 걸 때만 답한다. → [명령어 처리: 2차 명령어](command.md#2차-명령어)
- 추후 LLM과 연동할 수 있다. → [캐릭터 챗](#캐릭터-챗)

## 2차 데이터 모델

2차 구현에서 정한 것이다. → [이터레이션 계획: 2차 범위](index.md#2차-범위-npc-배치--기본-대화--성종문-정의)

- NPC `Npc` 는 모두 유니크 NPC다. 가지는 항목 (제안):
  - 이름: 띄어쓰기 없이 1~12자(`^\S{1,12}$`), 앞뒤 공백은 자른다. NPC끼리 유일하고 영문은 대소문자를 가리지 않는다(`대화` 의 대상 찾기와 같게). 띄어쓰기를 막는 까닭은 `대화 <NPC> <낱말>` 을 공백으로 나누기 때문이다. (제안)
  - 인사말: 1~500자. 기본 대답(모르는 낱말에 하는 대답): 1~500자. 관리 툴의 새 NPC 폼은 기본 대답에 룰북 예 `글쎄, 잘 모르겠구려.` 를 넣어 둔다. (제안)
  - 낱말 대답 목록: 최대 30개이고 입력 순서를 지킨다. 낱말은 띄어쓰기 없이 1~20자이고 앞뒤 `[` `]` 는 떼고 저장한다. 대답은 1~1000자. 같은 NPC 안에서 같은 낱말(영문 대소문자 무시)이 둘이면 저장하지 않는다. (제안)
  - LLM 대화 켬/끔: 기본 끔. 2차에는 저장만 한다. → [캐릭터 챗](#캐릭터-챗) (제안)
  - 배치 방: 방 하나 또는 없음. 없으면 배치 안 됨 = 세계에 없다. (제안)
- 2차에 넣지 않는 항목: 한 줄 묘사·자세히 볼 때 묘사·호칭(`보기 <대상>` 이 생길 때), LLM용 캐릭터 설정 칸(성격·말투·배경 — 3차 LLM 이터레이션으로 미룸), 소속 성·종문(가입·종문 규칙이 생길 때). (제안)
- 배치와 방 삭제: NPC는 방 하나에 고정한다. NPC의 배치 방은 방 id로만 갖고 방 FK를 두지 않는다(캐릭터의 현재 방과 같은 까닭). NPC가 있는 방을 지우면 **배치만 풀린다** — NPC는 남고 관리 목록에 `배치 안 됨` 으로 보인다. 배치 풀기는 방 삭제와 같은 트랜잭션에서 하므로 방 삭제가 막히면(예: 시작 방이라 409) 배치도 그대로다. (제안)
- 관리 툴의 배치 고르기에서 지역만 고르고 방을 고르지 않으면 배치 안 함으로 저장한다(따로 알리지 않음). (제안)
- 방 보기: 배치된 NPC는 그 방의 플레이어 줄 다음에 만든 순서로 보인다. NPC가 방에 생기거나 사라져도(관리 변경) 같은 방 사람에게 알림은 없고 다음 방 보기에 보인다. → [플랫폼: 2차 WebSocket 메시지 변경](platform.md#2차-websocket-메시지-변경) (제안)
- 캐릭터 이름과 NPC 이름: 캐릭터를 만들 때 이름이 NPC 이름과 같으면 1차 중복 문구 그대로 `이미 있는 이름입니다. 다른 이름을 정하십시오.` 다. 반대로 NPC를 만들 때 캐릭터 이름과의 중복은 검사하지 않는다(`대화` 는 NPC만 가리키므로 헷갈리지 않는다). 금지어 검사는 아직 없다. → [명령어 처리: 캐릭터 생성](command.md#캐릭터-생성-1차-최소) (제안)
- 관리 화면·REST API는 [관리 툴: 2차 화면](admin-tool.md#2차-화면), [관리 툴: 2차 REST API](admin-tool.md#2차-rest-api)에 있다.

## 동료 합류

- 특정 NPC는 동료로 합류시킬 수 있다.
- 동료가 된 NPC의 파티 내 규칙은 [룰북: 파티](../game-rule/party.md)를 따른다.

## 캐릭터 챗

- 요즘 유행하는 AI 캐릭터 챗과 같은 기능을 제공한다.
- LLM 연동으로 구현할 수 있다(추후).
- 캐릭터 챗(LLM 대화)을 하는 NPC는 관리 툴에서 지정한다. NPC마다 LLM 대화 켬/끔을 설정한다. → [관리 툴](admin-tool.md#관리-화면에서-하는-일)
- 2차에는 LLM 대화를 켠 NPC도 끈 NPC와 같은 정해진 대사(인사말·낱말 대답·기본 대답)로 답한다. 2차는 LLM을 부르지 않는다. 관리 툴의 `LLM 대화` 체크박스 옆에 `켜 두어도 지금은 정해진 대사로 답합니다.` 라고 알린다. (제안)

## 함께 쌓는 내러티브

- 플레이어와 모험하면서 겪은 일들을 NPC와 함께 공유하여 내러티브를 쌓는다.
- 쌓인 내러티브는 NPC마다 장기 메모리(기억)로 DB에 남긴다. 기억에 무엇을 어떻게 남기는지는 (미정).

## 열린 질문

- 2차 이터레이션(NPC 배치 + 기본 대화)에 걸리는 질문은 [이터레이션 계획: 2차 이터레이션 열린 질문](index.md#2차-이터레이션-열린-질문)에 모았다.

- LLM이 붙은 뒤 낱말 묻기 방식의 대사와 어떻게 함께 쓰는가? (LLM 연동 전 대사는 낱말 묻기 방식으로 정했다 → [고유 대사](#고유-대사))
- LLM에 넘길 NPC의 성격·말투·배경 같은 캐릭터 설정을 관리 툴에서 입력하는가? 어떤 항목인가? — 3차(LLM 이터레이션)로 미룸 (제안). 2차에는 입력 칸이 없다.
- "모험하면서 겪은 일" 로 기록할 것은 무엇인가? (함께 싸운 몹, 간 곳, 퀘스트, 대화 내용 등) 누가(엔진 자동 기록 / LLM 요약) 기록하는가?
- NPC의 장기 메모리 안에서 플레이어별 기억은 어떻게 나뉘는가? 여러 플레이어가 같은 NPC와 지낼 때는?
- 어떤 NPC가 동료로 합류할 수 있는지, 합류 조건(퀘스트·이벤트·호감 등)은 관리 툴에서 정하는가? → [이벤트 · 시나리오](event.md), [퀘스트 · 공적 교환](quest.md)
